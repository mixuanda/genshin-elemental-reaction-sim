预设 JSON

直接编辑角色、行动、Buff 与命中段

          

          

            
核心字段

            

              
characters
角色面板、等级、能量上限与初始能量。

              
actorPoses
可选的场景静态角色坐标与二维朝向；geometry.coordinateSpace 为 actor-local 时，核心按施放者姿态旋转并平移为世界坐标。当前不会自动移动或转向。

              
rotation
一个循环内的行动。系统按 cycleLength 自动重复至 duration。

              
enemy.targets
注册具名目标并可分别覆盖等级、标量抗性或完整逐元素抗性表、减防、初始附着、静态二维坐标和碰撞半径；省略时保留兼容目标 enemy-0。每个目标的 Aura 与附着 ICD 状态独立。

              
enemy.targetMotions
按目标声明有序、不重叠的 60 FPS 线性移动分段；分段间保持上一位置，核心按每次命中帧插值并返回解析后的移动时间线。

              
enemy.targetPhases
按目标和 60 FPS 声明有序、不重叠的半开阶段；开始帧生效、结束帧恢复。不同目标的阶段可以同时存在。

              
hits
每段伤害的偏移、倍率、附加基础伤害、元素、反应和快照方式；碎冰相关命中可声明 strikeType: blunt 与非负 poiseDamage。可用 targeting 选择已注册目标、显式 landed / miss，或覆盖阶段策略；也可用 geometry.circle、可旋转 geometry.rectangle、由起终点和扫掠半径定义的 geometry.capsule，或由圆心、半径、方向和夹角定义的填充 geometry.sector，按命中帧位置求交全部目标。几何默认使用世界坐标，也可声明 coordinateSpace: actor-local。

              
buffs
支持 atkFlat、atkPct、dmgBonus、critRate、critDmg、em、defIgnore、reactionBonus 和 energyRecharge。

              
debuffs
支持分元素减抗与防御降低。

              
energyGains
描述不受充能效率影响的固定回能，可声明按来源角色和键共享的内部冷却；每次触发或阻止都由核心记录。

              
particles
描述微粒/晶球的元素、离散数量范围、生成帧与飞行帧；核心在到达帧按前后台、同/异色和充能效率向全队分配。

              
timeline
启用 legal-frame-v1 后，以 60 FPS 整数帧描述行动定义和命令序列；支持切人、分后续行动取消帧、动画结束、冷却、充能次数、能量失败回滚，以及 strict / wait 合法性模式。

              
reactionEngine
aura-v1 根据每段 application 的元素量、icdTag、icdGroup 和敌方 Aura 自动判定融化/蒸发；aura-v2 加入雷 Aura、超载/超导/感电/冻结/碎冰/扩散/结晶；aura-v3 加入逐来源槽、草 Aura 与激化；aura-v4 加入可审计的燃烧 Marker/Fuel/Tick；aura-v5 再加入基础反应矩阵与草原核；aura-v6 加入共享来袭 Gauge 的雷来袭有序链；aura-v7 是 1.36 的显式 opt-in，把 Quicken 后的水草绽放跟进排为同帧 FIFO、执行时重读实时 Aura 的 core zero-delay task，并记录 reactionTaskLog；aura-v8 是 1.40 的显式 opt-in，在水草跟进耗尽同一代感电的最后水附着时武装 cleanup，并在普通衰减结算后的下一个有效目标 Tick 审计停止、保留或被新一代取代。v7 及更早模式保留历史兼容语义，不会自动升级为 v8。Burning refresh 只更新状态，不重复计作新反应；兼容模式保留显式 legacy ampBase 覆盖，Aura 模式只允许调试覆盖。上述顺序均为 fixed-gcsim-provisional，不代表官服真值；正式预设禁止手工 reaction 标签。

              
targetTaskModel
兼容模式继续使用 legacy-event-heap-v1。冻结的 1.37 target-phase-v1 只保留首批 Burning callback→Aura 衰减历史契约，并输出 targetTaskPhaseLog。1.38 引入的 target-phase-v2 必须显式 opt-in，要求 legal-frame-v1、60 FPS 和 aura-v7 或 aura-v8；它按目标注册顺序执行 QueueEnemyTask callback，再运行该目标的 Reactable.Tick，并以独立 targetPhaseLog 返回任务、生命周期转移和 Aura 三段状态。aura-v8 还要求 target-phase-v2，用于把感电 cleanup 绑定到下一个有效目标 Tick。Hitlag 导致的陈旧唤醒会先重投影。感电伤害 Tick/Wane、Quicken→Bloom 和其他 core work 仍按全局帧运行；Burning callback 内同步跨目标 Aura/反应命中尚未实现。

              
reactionDeliveryModel
1.39 引入并要求显式选择反应伤害的交付顺序，1.40–1.41 继续保留。现有预设和 1.38 及更早迁移输入固定使用 deferred-event-heap-v1，以保留网站基线；shatter-recursive-zero-delay-v1 只用于 legal-frame-v1 + aura-v7 或 aura-v8 的碎冰递归交付向量，并以 fail-close 方式拒绝其他组合。它不代表所有零延迟反应都已递归化，也不代表完整 gcsim 精度。

              
electroChargedPropagationModel
1.41 要求显式选择感电周期伤害的目标范围。所有正式预设和历史迁移默认使用 single-target-v1。nearby-wet-radius-v1 仅在 legal-frame-v1 + 60 FPS + aura-v8 + target-phase-v2 下 opt-in：核心在伤害结算帧读取每个目标的实时水附着与位置，并把用户给定 radius 加上目标碰撞半径来筛选全部范围内湿目标。该分支、半径与目标顺序均为 community-provisional，不是官服或 gcsim 已验证数据；副目标伤害不施加 Aura、不递归、不接管既有感电流、不重置 cadence，也不触发副目标 Wane。

            

            
旧配置继续使用绝对秒兼容模式；legal-frame-v1 的行动和命中使用整数帧。现有全队、个人、技能、时间轴、逐段伤害与累计/构成曲线只读取核心结构化结果，页面不自行计算伤害；aura-v5–v8 的反应伤害与 1.41 opt-in 感电副目标伤害都会进入这些既有视图，专门的反应任务、草原核和感电候选审计面板后置。当前优先保证基础反应。1.41 保留 deferred 网站兼容基线和 aura-v8 感电 cleanup，并新增默认关闭的 nearby-wet-radius-v1；它只是带完整候选与 DamageEvent 回链的 community-provisional 回归契约，不能称为 gcsim parity。除已列明的 v6/v7 代表性来袭链、v8 感电 cleanup 和 1.41 provisional 湿目标传播向量之外，其他来袭元素全组合、一般化 Aura overlap、特殊 Aura 的全部可达排列、通用敌方任务所有权、感电副目标流接管/cadence/Wane、Lunar 反应、完整角色特有 ICD、真实粒子/掉球与飞行、全角色动作/取消帧和全角色/武器/圣遗物/敌人可执行机制数据库仍未完成。冻结的 1.37 target-phase-v1 只覆盖第一批 Burning callback；1.38 target-phase-v2 也仅保证每个目标内 callback→Reactable.Tick，不代表已实现同步跨目标 Burning 命中或完整 gcsim。所有相关顺序都只是 fixed-gcsim-provisional 或 community-provisional，不是官服真值。草原核 300f 生命周期和默认杜林预设的示例魔法数仍是 provisional，不是正式已验证数据。
