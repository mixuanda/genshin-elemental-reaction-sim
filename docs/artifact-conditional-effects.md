# 四件套条件快照增量

`artifact-conditional-effects.ts` 新增10个四件套范围，复用共享装备公式类型与 `FormulaExpression`。模块只输出表达式、变量定义、来源引用、条件假设与阻塞；数值代入和执行仍由共享计算核心完成。所有条目维持 `provisional`，不宣称自动触发、持续覆盖率或当前官服独立验证已经完成。

## 已实现条款

| 四件套 | 仅本模块新增的贡献 | 必需的命中前条件 |
|---|---|---|
| 炽烈的炎之魔女 | 额外火伤 `0.15×0.5×层数`，最多22.5% | 0–3有效战技触发层数 |
| 冰风迷途的勇士 | 冻结目标40%暴击；否则冰附着目标20%；否则0 | 明确冻结状态；未冻结时需明确目标附着 |
| 逐影猎人 | 暴击率 `0.12×层数` | 0–3有效生命变化层数 |
| 黄金剧团 | 战技常驻25%，额外后台／上场未满2秒窗口再25% | 额外窗口是否仍有效 |
| 水仙之梦 | 攻击0/7/16/25%，水伤0/4/9/15% | 当前有效的不同攻击类别数，3表示至少三种 |
| 沉沦之心 | 有效窗口中普攻／重击增伤30% | 战技后15秒增伤窗口是否仍有效 |
| 追忆之注连 | 有效窗口中普攻／重击／下落增伤50% | 已合法触发的10秒增伤窗口是否仍有效 |
| 辰砂往生录 | 潜光有效时攻击 `0.08+0.1×层数`，失效时0 | 16秒内且未退场的潜光状态、0–4有效失血层数 |
| 花海甘露之光 | 战技／爆发增伤 `0.1×(1+0.8×层数)`，最多50% | 0–5仍有效外部受伤层数 |
| 苍白之火 | 攻击 `0.09×层数`；恰好两层额外物伤25% | 0–2有效战技命中层数 |

二件套由已有套装模块独立且仅计一次。本模块不能把四件套条件贡献覆盖或重复叠加到二件套：黄金整套应为战技45%／70%，苍白满层整套为物理50%，魔女满层整套火伤37.5%。水仙水伤、魔女火伤、苍白物伤按伤害元素过滤；黄金、沉沦、追忆与花海按攻击类型过滤。冰风暴击不要求伤害本身为冰元素。

## 条件恢复与接口

导出接口为 `hasArtifactConditionalRule(id)`、`resolveArtifactConditionalEffects({ setId, pieces, enabled, context })`、`getArtifactConditionalControls(setIds)` 及 `SUPPORTED_ARTIFACT_CONDITIONAL_IDS`。

`ArtifactConditionalContext` 继承 `EquipmentFormulaContext`，仅新增 `setEffectActive?: boolean` 与 `targetFrozen?: boolean`，其余复用 `setStacks` 和 `enemyAuras`。`setEffectActive` 根据实际套装显示不同标签；未知和明确否是不同状态。缺少需要的状态加入 `missingConditions`，上层必须拒绝将缺少该项的数字作为完整结果。辰砂明确失效时不要求失血层数，因为该条贡献已确定为零。

冰风是对目标生效的条件暴击，不是角色常驻面板。当前单目标计算器可以将已明确目标状态的条件暴击写入本次面板，但改变目标、附着或冻结状态后必须重新恢复快照。固定参考实现优先检查Frozen并直接给40%，因此 `targetFrozen: true` 与 `enemyAuras: []` 是可执行冻结分支；不强行要求额外列出独立冰附着。多目标不同状态与月反应特殊钩子不属于本次验证范围。

水仙按普攻、重击、下落、战技、爆发五类独立8秒状态计数，点按／长按战技共用一个类别；同类多段不会增加类别数。花海每层是外部伤害触发，分别持续5秒，生命主动消耗不能直接视为受伤。这里的层数均指命中前已经有效的层数；本次才触发的层数不应追溯修改本次已结算伤害。

## 保留的范围限制

本模块只处理普通增伤和面板条款。后续的 [装备反应与减抗模块](artifact-reaction-effects.md) 已独立接入魔女常规反应奖励、翠绿普通扩散与对应元素减抗、深林草减抗、如雷常规剧变和超激化奖励；这些不会重复算作普通增伤。月／星反应专有装备路由与余响概率触发仍有明确缺口。

追忆只恢复用户确认已合法触发的伤害窗口；15能量门槛、来源实现约10帧后扣能、窗口内禁止再次触发及循环能量可行性没有由此模块验证。沉沦与辰砂参考代码在触发快照前后仍留有TODO，逐影代码也仍有受击触发TODO；本次据此只提供已知状态下的数值公式，不提升自动事件时序的完成状态。

## 来源与实测

10项套装描述与活动7.1目录逐项匹配，链接通过 `equipmentDescriptionSource` 跟随活动不可变快照；源文字改变时拒绝继续执行旧映射。数值、过滤和条件与 [gcsim固定提交](https://github.com/genshinsim/gcsim/tree/b4ae769d7c1c1bce68fce5faf0b460c5b5b7f541/internal/artifacts) 交叉检查。`artifactConditionalSourceEvidence` 保存10份源码的完整路径、URL与SHA256；原始字节在本次运行的 `/tmp/gidps-artifact-conditional-sources/`。

执行 `npx vitest run packages/game-data/src/artifact-conditional-effects.test.ts`：10项参数化用例通过，耗时873 ms（测试执行4 ms）。覆盖全部新条款的手算上限值、零层／无效窗口、层数范围与整数约束、缺条件阻塞、二件套不重复执行、冻结不依赖独立冰附着、水仙各档位、元素／攻击类型过滤以及魔女反应部分独立执行约定。本轮没有重复旧装备或全核心测试；黄金整套共享核心与JSON往返由主任务另测。
