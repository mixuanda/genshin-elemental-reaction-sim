# 讨龙实际切人与独立结果回放

## 本分工修改

当前 1.53 配置显式声明 `thrillingTalesModel` 的持有者和精炼；同一角色不能同时声明其他已建模武器，已声明普攻能量类别时须为法器。未启用讨龙模型的配置不增加字段。旧版本投影、迁移和结果边界不接受新模型与日志。自动模型开启时拒绝手写共享 `ttds` 增益，避免覆盖来源状态。

结果回放从已校验的实际动作与能量不足动作推导角色切换，而不是相信 `thrillingTalesLog` 自报触发。持有者冷却到期帧仍阻塞；通过后先消耗 1200 帧冷却，再检查接收者共享状态；已有状态不刷新、不覆盖、不叠加。R1–R5 系数共用 `reaction-formulas` 的固定来源表。

状态存在与数值有效期分别回放：攻击力贡献在 `[领取帧, 领取帧 + 600)` 生效；600 帧等号处的状态仍可阻止重新领取，直到实际完整面板读取删除已到期状态。读取事件仅来自已选择动作的 action 快照、召唤实际快照、真实落地的实时面板命中及独立武器追击触发。治疗、精通、充能等单属性查询不伪装成完整面板读取。数值窗口使用全局 60 帧时间，保留旧兼容输入的实际事件时间。

共享属性回放验证讨龙对所有相关普通命中、动作/召唤/周期/追击快照的实际贡献；讨龙标签也按命中真正快照时点验证。周期实体的 action 快照按 tick 时点还原。计算器桥返回实际已包含份额的日志，并显示“受益角色基础攻击力 × 讨龙系数”的 AST；恢复后的最终面板不再加一次。

本分工执行 1 个新聚焦用例，命令为 `npx vitest run packages/schemas/src/thrilling-tales-result-integrity.test.ts`。

运行时边界和固定外部来源对照由各自分工记录；这里不重复执行，不把尚未运行的用例记为通过。没有全套、构建或外部 CLI 运行。
