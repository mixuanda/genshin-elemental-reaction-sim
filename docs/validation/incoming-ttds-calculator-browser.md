## 正常页面操作与实际行为

从 `/calculator` 选择夏洛蒂 C2 点按 E，完整五击，有效天赋 1、突破 6。明确最终 ATK 1000、HP 10000、DEF 800、EM 0、CR 0.5、CD 1，角色和敌人均 90 级，抗性 10%，两名非枫丹其他队友的 A4 未含。C2 每击实际一层、共同面板未含、接收者基础攻击 500，角色自身每击独立增加 50 ATK；其他状态明确稳定，标记完整。

通过外部讨龙控件显式启用来源，填写提供者标识 `support-lisa`、说明“丽莎·讨龙持有者”、精炼 R5。该标识是教学条件中的提供者声明，未创建队伍或模拟一次切人；接收者仍为夏洛蒂。每击的实际生效状态和输入面板已含精炼分别填写。

测试实际确认：

- 讨龙状态未知时，选中命中不能计算。单选已明确“实际 R5 有效且面板已含 R5”的标记，讨龙差额为零，不要求未知基础攻击；其余未选命中未知不会连带阻塞。
- 初击改为实际 R5 有效、面板未含时，缺少讨龙基础攻击会阻塞；填写 500 后增加 `500 × 0.48 = 240 ATK`。角色 C2 的 50 ATK 仍单独执行，两项没有覆盖彼此。
- 切回完整五击，未填的讨龙状态继续阻塞；明确所有状态后，按五个真实命中求和。
- 某标记实际讨龙已失效，但所填面板已含旧 R1 时，执行 `500 × (0 − 0.24) = −120 ATK`。普通页面可展开这项 AST，显示共享核心的实际代入。
- 共同最终面板及其来源、夏洛蒂 C2 上下文保持原值；没有套用提供者的攻击力，也没有把某一击的调整写回整个面板。
- 正常导出、导入 JSON 后，提供者、R5、逐击状态和未舍入伤害保留，全部逐击结构化轨迹严格相等。队伍模拟结果保持为空。

## 独立算式与实际数值

五击依次明确为：有效 R5／未含，失效／已含 R1，有效 R5／已含 R1，有效 R5／已含 R5，失效／未含。讨龙增攻差为 `[240, -120, 120, 0, 0]`，C2 增攻为 `[50, 50, 50, 50, 50]`，最终逐击 ATK 为 `[1290, 930, 1170, 1050, 1050]`。

```text
每击讨龙增攻差 = 接收者基础攻击 ×（实际生效系数 − 已含精炼系数）
完整非暴击 = (0.672 × 1290 + 0.392 × (930 + 1170 + 1050 + 1050)) × 1.1 × 0.5 × 0.9
完整期望 = 完整非暴击 × (1 + 0.5 × 1)
```

| 实际页面状态 | 非暴击 | 期望 |
| --- | ---: | ---: |
| 单标记，讨龙净差零、基础攻击未知 | 203.742 | 305.613 |
| 初击，R5 未含，另有 C2 | 429.1056 | 643.6584 |
| 完整五击、不同实际及已含状态 | 1244.0736 | 1866.1104 |
| 单标记，失效后扣除已含旧 R1 | 180.4572 | 270.6858 |
| 完整五击 JSON 重载 | 1244.0736 | 1866.1104 |

表中显示便于阅读的十进制值；原始完整结果为非暴击 `1244.0736000000002`、期望 `1866.1104000000003`。独立算式断言核对到 9 位小数，逐击求和核对到 10 位小数；上下文与 JSON 轨迹比较使用完整对象相等断言。
