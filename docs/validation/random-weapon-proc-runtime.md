# 五把随机独立追击武器：真实回调与附着条件

## 本轮实现

普通团队武器模型新增吃虎鱼刀、试作古华、雪葬的星银、龙脊长枪、忍冬之果。使用既有 `weaponProcModel`、独立物理伤害事件、目标几何、属性快照及计算器捕获桥接，不把追击倍率加到宿主技能基础伤害上。倍率、精炼冷却和概率复用 `reaction-formulas/independent-weapon-proc.ts` 的固定来源定义。

钺矛、苍纹角杯、冷寂迸音保留既有同步回调、原来源标识及日志形状；新五把使用 `gcsim-random-weapon-proc-v1`。新随机字段只出现在新五把日志中，不给旧三把补虚构的抽样字段。

实际来源顺序分别为：

- 吃虎鱼刀：本人且在场 → 武器冷却 → 抽样 `roll <= 0.5` → 非零伤害。抽中但伤害为零仍消耗这次抽样，不开始冷却。
- 试作古华：本人且在场 → 武器冷却 → 明确普通/重击标签 → 抽样 `roll < 0.5`。没有零伤害门槛。
- 三把霜葬：本人且在场 → 武器冷却 → 明确普通/重击标签 → 抽样 `roll < 0.5 + 0.1 × R` → 设置冷却 → 读取原触发目标当时 Cryo/Frozen。精炼 5 仍抽样，没有零伤害门槛。

上述普通伤害回调包括独立武器追击；不会因为 `attackTag: proc` 预先过滤掉吃虎鱼刀允许的来源。各武器冷却均保留到期帧仍有效的边界。显式物理伤害加成与角色通用伤害加成进入实际追击计算；宿主命中的专属暴击覆盖、防御忽略和伤害加成不自动继承。

## 真实延期回调

固定源码 `pkg/enemy/attack.go` 将伤害回调追加到同帧任务队列；霜葬不能无条件使用父命中的 `auraAfter`。例如目标初始有冰，先排的物理普攻父命中仍记录冰，随后同帧火命中可先消耗冰，最后武器回调才执行。

新五把因此使用真实 `weaponProcCallback` heap 事件，与父普通命中相同相位、全新 FIFO 序号。在回调执行时才检查前台、冷却、标签、概率、目标位置与附着，并保存属性快照。默认命中为相位 3，显式晚相位动作后代使用既有相位 13；不把回调强行推至所有反应任务之后。

霜葬现场读取目标 AuraEngine 在当前帧的状态。`triggerAura.cryo` 表示独立 Cryo 光环，`triggerAura.frozen` 表示 Frozen；增强条件为两者之一存在。只有成功抽中才读取，未查询记录为 null。选出的系数固定给整次 AoE，不能按每个受击目标重新选择，也不能在一帧后落地时再读附着。圆形追击以原触发目标回调时位置为圆心、半径 3，即刻取样、延后 1 帧交付；吃虎鱼刀为原目标单体。

实际待执行追击上下文保存随机记录、附着判定、选定倍率、冷却及触发快照；日志保存原始父伤害、实际回调序号与独立子伤害关系。结果完整性校验独立重放条件、随机流和队列顺序，Cryo/Frozen 判定来自已验证目标状态时间线。它不信任自报回调序号来任意选择附着，也不把整个 Aura 对象都声称为相位尾部不变：同相位 Quicken/Bloom 后续任务只消费 Hydro/Quicken 的已审阅范围支持这两个谓词的独立恢复。

新五把默认使用帧时钟，显式 `legacy-v0.1` 被拒绝；霜葬必须声明 Aura 引擎，缺失附着上下文不能当作无冰。该接口仍限普通团队伤害回调，未接入反应伤害回调、月曜/星辉特殊宿主或角色卡肉延长，不认证所有跨类 gcsim 任务顺序与当前服务器行为。

## 随机性与周期状态

新五把共用独立命名流 `independent-weapon-proc-v1`，算法为现有 `fnv1a32-mulberry32-v1`。每条新日志记录概率、严格/非严格比较、实际 roll、drawIndex 与前后 drawCount；前置条件未通过时没有抽样，吃虎鱼刀零伤害检查的特殊位置除外。

相同本地 seed 可复现；gcsim 使用共享随机流，不能声称双方相同 seed 产生相同抽样。新五把的完整确定性 phase checkpoint 明确阻塞其随机流及延期回调，旧三把确定性追击的既有真实冷却/待执行快照捕获继续保留。

## 实际验证

仅新增 `packages/sim-core/src/__tests__/random-weapon-proc-runtime.test.ts` 的 3 个核心用例，没有执行旧全集、构建、MC 或额外矩阵。

首次为 2 通过、1 失败：Vitest 1.09 秒，测试 192 毫秒，退出码 1。失败发现一个真实入口缺口：带 timeline 的调用在进入运行时前强制了合法帧模式，导致新五把对用户显式 legacy 模式的拒绝被绕过。已仅在公共模拟入口针对新五把提前拒绝该组合，旧三把不变。只复验失败用例，1 通过、2 跳过，Vitest 1.08 秒、测试 187 毫秒，退出码 0。日志保留于 `random-weapon-proc-runtime.log` 和 `random-weapon-proc-runtime.retry.log`。

实际断言：

- 初始两目标均有冰；原目标第 10 帧先物理普攻、再零伤害火附着清冰。父物理命中仍记录 Cryo，但实际延期回调为 `{cryo:false,frozen:false}`，R5 仍抽一次，系数 1.4。第 11 帧两个 AoE 命中各 700，即使第二目标仍有冰也不重新选系数；总伤害 1900，子命中 capture → JSON → replay 差值 0。
- 原目标初始 Hydro，普通 Cryo 命中实际形成 Frozen，回调选 3.6；落地前下一帧的火命中清除 Cryo/Frozen，已排追击仍对两个目标各造成 1800。实际 R5 drawCount 从 0 到 1。
- 吃虎鱼刀固定首个 roll `0.036787065444514155` 抽中后被零伤害阻止，drawCount 增加但无冷却；下一个 `0.9033824452199042` 抽样失败。试作古华相同首个 roll 在零伤害普通攻击回调上成功，精炼 5 系数 4.8；900 帧仍冷却阻塞，901 帧才再次抽样。雪葬在独立 Frozen 条件下正确选择 3.6，R5 仍抽。

共享定义、单技能计算器、结果篡改校验与浏览器用例由各责任代理记录，没有在本文件重复运行。独立 schema 的同帧反例确认错误系数、伪造附着、伪造 roll 和伪造回调序号均被拒绝。

## 外部有限对照

独立代理只运行一次固定源码 Charlotte + R5 忍冬样本。第 14 帧 N1 只命中原目标并新附着 Cryo，之后武器回调选择 3.6，第 15 帧命中两个目标；第二目标没有被 N1 命中且无冰，仍共用 3.6。

唯一本地对照首次通过：宿主伤害 9.65933654375722，两个追击各 69.76265017880414，总伤害 149.18463690136548，逐值残差均 0；3 次捕获 JSON 回放、2 个独立追击计算文档也均零差。实际本地 R5 roll 为 0.46866409154608846，drawIndex 0；不伪造外部未输出的随机值。

证据位于 `docs/cross-validation/frost-proc/`，完整外部报告由该代理维护。该样本验证新附着后的原目标条件、全 AoE 共用系数及共享核心数值，不泛化为完整角色或全武器机制已认证。
