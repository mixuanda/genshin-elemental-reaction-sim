# M08：特殊反应贡献者种子暴击

本批生产实现已由根任务统一验收：唯一综合核心用例和构建通过，实际抽样捕获/JSON与解析期望分别保留。没有把独立游戏验证或未覆盖特殊域写成完成。

## 实际修改

- 新增 `packages/sim-core/src/special-random.ts`。每次模拟使用独立命名流 `special-contributor-critical-v1`，种子为运行种子加明确命名空间，算法为 `fnv1a32-mulberry32-v1`。这保证本地确定性，不宣称与 gcsim 的共享随机流同序列。
- 月感电、月结晶、直接月露涤荡和 mixed v1/v2 从实际状态引擎已经解析的贡献者取样，不从 UI 队伍补人，不为非伤害转换事件抽样。普通逐击暴击和此流各自推进。
- 月感电在实际扫描时抽样。月结晶在每段人物快照时抽样，保存到待投射记录；10 帧后交付伤害只读取原抽样。月露涤荡在实际各段命中时取样。
- `criticalExecution` 保存种子、算法、命名流、事件 ID、抽样帧和逐贡献者 `drawIndex / roll / critical`。保持原始 CR，按锁定源码的 `roll <= CR` 判定。包括 CR 为 0 或 1 的合格贡献者仍消耗一次本地抽样。
- 共享特殊公式新增 `sampled`，逐贡献者先暴击，再排序和使用 0.6/0.3/0.05/0.05 权重；直接能力权重为 1。原有非暴击、全暴击和最多 16 组合的解析期望保留。抽样组合概率用于说明，不再次乘入本次伤害。
- 共享 AST 记录比较、暴击倍率、排序权重与合计，每步沿用公式、变量、数字代入、结果和说明。反应 owner 与最高贡献者的 `displayedCritical` 分开保存，未改归属。
- Lunar 结果导出包含本地随机政策及实际事件上下文；已有 Worker 原样传递选项和结果，无 UI 抽样。捕获特殊命中至独立计算器时用 `sampled.damage` 对照实际伤害，JSON 保留上下文。计算器和 Lunar 页面并列显示实际抽样值与解析期望。
- 从已捕获命中创建可编辑条件副本时，克隆文档并去掉历史 `criticalExecution`。原捕获保留；编辑后的面板只做条件计算，不把旧抽样误作新执行。
