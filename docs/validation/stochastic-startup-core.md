# 有限随机起步诊断：核心实现与聚焦验证

本记录对应 `packages/sim-core/src/stochastic-startup.ts` 与本次新增的三个核心用例。它证明有界诊断的执行和统计口径，不证明任何角色队伍已经达到数学稳态，也不把有限种子结果提升为真实游戏机制验证。

## 执行政策

- `analyzeStochasticStartup(config, policy?, options?, controls?)` 已从 sim-core 公开导出。默认 8 组种子、W=5 个配置周期；样本数限制 2–32，W 为正整数。2W 加观察窗口受现有连续模拟 600 秒上限约束。
- 观察窗口长度采用原配置 `duration`，周期采用 `cycleLength`。每个种子分别从 zero/full 起步，各调用一次共享连续模拟入口，长运行长度为 `2W + duration`，因此共 2N 条最终连续轨迹。合法时间线的既有能量前缀探测仍由原引擎执行，并非本功能新增的独立统计样本。
- 法定轮转通过 `repeatLegalTimelineForDuration` 延展；不修改来源合同、动作合法性或循环末前台条件。跨周期能量、冷却、增益、在途粒子等都来自连续运行，未在观察起点重置状态。
- 在每条连续轨迹上取 `[W,W+duration)` 和 `[2W,2W+duration)` 两个整帧半开窗口。两个窗口可能重叠。四项差均先在同一个种子内相减，再对 N 个差汇总，未把两窗或单次命中当作独立样本。
- 伤害使用共享 `measureDamageWindow`；DPS 分母是完整窗口秒数。能量起末值取对应边界帧全部事件发生前的实际能量。正耗能请求数包含成功动作及被拒绝请求，失败率是该次窗口内失败数/请求数；没有请求为 `null`。合法性拒绝包括能量不足和其他拒绝，`insufficientEnergyFailures` 单列能量不足子集。能量不足同时出现在合法时间线和 skippedActions 时只计一次。
- 首个种子的 zero 结果保留完整轨迹与详细公式；其余保留原始窗口统计及完整 runManifest。其他运行关闭详细公式和主动完整捕获；既有引擎仍为实际随机暴击生成必要命中审计，但这些完整轨迹不进入最终统计导出。
- 返回原始配置、输入内容哈希、原始运行选项、解析后的政策、各运行种子及 manifest。`onProgress` 在开始及每条最终轨迹完成时报告 `0..2N`，取消在运行之间检查；网页可以终止独立 worker 中的当前运行。

## 统计来源与界限

使用 NIST 官方 [均值置信区间公式](https://www.itl.nist.gov/div898/handbook/eda/section3/eda352.htm)：`平均值 ± t × 样本标准差 / sqrt(n)`，样本方差分母为 `n−1`。当 n=1 时不生成区间；无有效率样本时分布为 `null`。配对数据先逐对相减，与 NIST 的 [配对数据说明](https://www.itl.nist.gov/div898/handbook/eda/section3/eda353.htm) 一致。

`t` 取 NIST [Student-t 临界值表](https://www.itl.nist.gov/div898/handbook/eda/section3/eda3672.htm) 的 0.975 列、自由度 1–31；固定表保留来源的三位小数，例如 12.706、2.776、2.040。没有引入求逆分布算法或把表值伪称为六位精度。上述页面于本次实现通过浏览工具读取。

经验 p05/p50/p95 使用排序样本下标 `(n−1)p` 的线性插值。这是本产品公开的描述政策，不是总体置信界。Student-t 区间另列为探索性均值区间；需要跨种子近似独立及均值或差近似正态等假设，有限样本、离散失败率、偏斜分布时有明显局限。比例的近似区间不裁剪到 `[0,1]`，以免隐去方法本身的近似性。多指标区间没有同时覆盖率校正。

不计算或设置 p 值通过门槛。区间包含 0、方差为 0、zero/full 均值相近，都不证明完整状态分布收敛。不同起步导致动作分叉后，相同种子的抽样序号也不保证对应同一命中。仅统计主模拟器能完整汇总的路径，独立特殊反应包络及未实现的暴击触发效果不在该证明范围。

## 本次实际检查

只运行新增文件一次：

```sh
npx vitest run packages/sim-core/src/__tests__/stochastic-startup.test.ts
```

首次 **2 通过、1 失败**，总耗时 **922 ms**，测试耗时 **120 ms**，exit **1**，记录启动时刻 `22:52:43`。失败是手算 `3−2.776/sqrt(2)` 与运算顺序不同的等价式相差约 `3×10^-16`，测试误用逐位相等；生产公式没有因此改动。断言改为 14 位近似后，只复验失败项：

```sh
npx vitest run packages/sim-core/src/__tests__/stochastic-startup.test.ts -t 'separates empirical spread'
```

复验 **1 通过、2 跳过**，总耗时 **800 ms**，测试耗时 **3 ms**，exit **0**，记录启动时刻 `00:00:57`。没有重新运行已通过的模拟用例、旧测试全集、构建或大型 Monte Carlo。

证据：[首次日志](stochastic-startup-core.log)、[首次 exit](stochastic-startup-core.exit)、[失败项复验](stochastic-startup-core-recheck.log)、[复验 exit](stochastic-startup-core-recheck.exit)。

三个用例覆盖：

1. 固定样本 `[1,2,3,4,5]`：均值 3，样本标准差 `sqrt(2.5)`，经验分位 1.2/3/4.8，95% 均值区间约 `[1.037071575426144,4.962928424573856]`；同时检查零样本、单样本、零方差、表的两端及不执行运行的取消。
2. **N=2、W=1，总计四条实际连续轨迹**。合成轮转每 2 秒产 1 个同色球、随后请求 6 点能量的 Q；观察窗 4 秒，长运行 8 秒，能量上限 6。zero 的 Q 成功帧为 122、362，失败帧为 2、242；两个观察窗起末能量分别为 3/3、0/0。full 的两个窗口分别为 0/0、3/3。每窗均为 2 次请求、1 次失败；后台无请求角色的失败率为 null。随机暴击开启，单 Q 实际伤害只能是手算的 427.5 或 641.25；逐 seed 配对差、df=1 的区间、真实进度、完整代表公式与原输入不变同时核对。
3. 另一个 **N=2、W=1，总计四条实际连续轨迹** 的 wait 模式合成场景：能量不足导致状态启动失败，继后的耗能动作因缺少状态拒绝。每观察窗 2 次请求、2 次失败，其中仅 1 次属于能量不足；验证没有遗漏合法性拒绝，也没有把同一能量拒绝重复计数。

这里的合成数值用于验证引擎和统计方法，不代表新的角色伤害基准。浏览器集成与最终构建由主任务另记。
