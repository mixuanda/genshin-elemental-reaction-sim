# 祭礼：当前配置与结果独立回放校验

本轮仅新增祭礼配置、结果结构及其来源重放校验；模拟器与合法时间轴接线由并行运行时任务完成。没有把冷却重置改写成宿主伤害加算，也没有修改独立计算器的伤害公式。

## 实际实现

- 当前 1.53 配置可显式声明祭礼剑、祭礼大剑、祭礼弓或祭礼残章及 R1–R5。必须使用合法时间轴；同角色不能同时声明西风、独立武器追击或讨龙。已有普通攻击产能武器类型声明时必须匹配。
- 持有者的所有 `kind: skill` 变体共享一个 E 充能槽，最大层数必须一致。恢复时间取每次实际技能的 `chargeRecoveryFrames ?? cooldownFrames`，且须为正整数。
- `cooldownStartFrame` 仅在当前版本的祭礼持有者技能上可用，省略时运行语义为零，序列化不强行补值。延迟结束时才扣层和追加队列，起手时不提前保留一层。
- 新增 `sacrificialLog` 与 `skillCooldownLog`。未显式启用模型时不产生字段；历史版本仍拒绝这两个当前扩展。
- 结果校验从真实接受动作、实际普通伤害回调与共享纯充能函数重新生成 start、recover、reset、stale-worker。导入日志中的队列或最后冷却不参与推导。
- 每次技能请求另用此前命令的来源重放求最早可用层数。当前和后续请求的命中不能倒流帮助当前请求；校验真实冷却等待、随后体力等待与超出观察期的处理。
- 祭礼模型中的同帧动作还受已排事件相位约束：较晚相位动作已完成时，下一较早相位动作不能倒排回当帧。自动模式记录一帧的动作重叠等待；严格模式拒绝。该限制只影响显式祭礼模型，结果按此前实际接受动作独立校验。
- 概率过滤顺序、严格 `<` 抽样、失败不设武器冷却、到期帧仍阻挡、未满足前提不抽样均由独立 `sacrificial-v1` 种子流重放。成功只恢复一层，删除队首并从成功帧重新计剩余队首的完整时长。

主要文件：`packages/schemas/src/sacrificial-schema.ts`、`sacrificial-replay.ts`、`sacrificial-command-integrity.ts`、`sacrificial-integrity.ts`；当前类型、配置/结果投影与公共完整性入口已接入。两个旧测试的当前扩展类型断言仅补入新日志字段，没有运行旧测试。

## 固定来源与范围

来源固定为 gcsim `b4ae769d7c1c1bce68fce5faf0b460c5b5b7f541` 的 `internal/weapons/common/sacrificial.go`、`internal/template/character/cooldown.go` 与任务/动作时序。倍率和纯充能队列复用 `packages/reaction-formulas/src/sacrificial.ts`、`skill-cooldown.ts`。

来源具体审计及唯一外部执行另见 [祭礼外部对照](../cross-validation/sacrificial-external.md)。本测试采用砂糖两充能技能的时间形状，但伤害是明确合成的 100% ATK 物理攻击，不冒称为砂糖真实倍率。来源模型明确假设没有角色卡肉；不支持缺少真实技能冷却槽的旧 rotation，也不覆盖月曜／星辉特殊伤害宿主。独立本地随机流不声称与 gcsim 共享 seed 产生相同抽样。

## 本轮唯一执行的检查

命令：

```text
npx vitest run packages/schemas/src/sacrificial-result-integrity.test.ts
```

首次通过，exit 0，1 个文件、1 个测试；Vitest 1.07 秒，其中测试 198 毫秒；外层实测 1.484267 秒。[完整输出](logs/sacrificial-result-integrity.txt)

实测：

- 三次起手保持第 1、57、113 帧；延迟 9 帧启动冷却。
- 第 43 帧仍有一层可用，不抽祭礼随机；第 99 帧触发；第 155 帧被祭礼冷却阻挡，总计仅一次抽样。
- 成功前 0 层，成功后恰 1 层；剩余队列为一项 900 帧。自然恢复发生于第 999、1899 帧。
- 三击独立手算 `1000 × 100% × 0.5 = 500`，实测合计 1500。第三击完整计算上下文经过 JSON 序列化/解析后由共享计算核心复现，差值 0。
- 删除全部充能日志、伪造抽样值、把重置改为补满两层、把自然恢复伪造为第 910 帧，四类篡改全部拒绝。

本任务没有运行构建、数据生成、旧套件或外部 CLI；没有失败后扩测。运行时、消费者和页面验证由各自任务记录，不能把它们算作本文件所执行的检查。

首次测试通过后，运行时审阅另发现零取消帧的相位 8 → 相位 0 同帧倒序边界。对应的时间轴结果投影作了限定于祭礼模型的同步修改；本任务没有重复上述已通过测试，该边界由运行时任务补入其受影响用例并定点执行。
