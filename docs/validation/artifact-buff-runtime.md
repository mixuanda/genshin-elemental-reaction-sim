# 六套圣遗物实际增益生命周期

本专题记录 `gcsim-b4ae769-artifact-buffs-v1` 的实际增益生命周期。主执行器、公共结果独立重放、正常队伍控件及结果账本已接线；2026-09-25 根任务集中验收中，六套的两条核心用例在修正夹具后均已取得通过结果，宗室与通用玩家盾的正常页面流程也已通过。各次失败和定向重跑记录保留在下文，不能将最后一次仅运行一条用例的结果写成六套全量重跑。

本实现使用固定社区源码假设，不代表实机验证，也不改变 released / preview 数据分类。本轮没有新增外部战斗样本；本次文档收尾仅读取已有执行日志，没有另外运行测试或构建。

## 已实现模块

- `packages/reaction-formulas/src/artifact-buff.ts`：六套来源常量、事件、应用操作、私有状态和明确适用域。
- `packages/sim-core/src/artifact-buff-runtime.ts`：真实事件驱动的状态转换；数值增益、层数、存在性、人数上限、窗口、冷却与延迟帧直接由 executable AST 算出，写入状态和应用结果。返回的 trace 就是执行时生成的公式、变量、数值代入和中间结果。
- `packages/schemas/src/artifact-buff-model.ts`：当前配置与结果叶节点、唯一四件套持有者、宗室显式分支、辰砂单持有者、所需实际资源及互斥约束。它不把结构解析当成独立事件重放证明。
- `apps/web/src/artifact-buff-controls.ts`：正常队伍声明入口，明确静态面板不得预含这里自动执行的四件套条件增益。
- `apps/web/src/artifact-buff-panel.ts`：正常结果与观察窗口共用账本，读取保存的真实公式追踪与父事件关系；不在界面补算触发、过期或伤害。
- `packages/game-data/sources/artifact-buff-runtime/manifest.json`：固定源码的逐字归档、来源路径、字节数和 SHA-256。归档来自现有固定源码树；本轮没有新增外部战斗样本。

## 已完成的主执行器接线

配置字段为 `artifactBuffModel = {mode: "fixed-source-no-character-hitlag-v1", actors: [{actorId, effectId, noblesseSelfDelayFrames?}]}`。宗室必须明确填写 0 或 1；其他套装禁止此字段。若已有可组合角色来源绑定，接线方还需核对该绑定的实际宗室分支，不能按显示名称猜测。

`simulator.ts` 已创建 `ArtifactBuffRuntime(model, characters)` 并保存真实私有状态；`handle(event)` 接入实际发生的事件，不遍历计划输入伪造爆发或反应。主执行器已将模块返回的决策与实际 frame / priority / FIFO / intra-event tuple 及来源 ID 一起保存为 `artifactBuffLog`，结束时保存 `artifactBuffState`。

`applications` 中 `replace` 按接收者与语义键整体替换后，一次加入该窗口的所有属性；饰金的 ATK 与 EM 两条不能互相删除。`update` 仅用于辰砂增层：更新既有 modifier 数值，保留原开始帧与结束帧；`startFrame` 在该操作中标记实际更新帧，不能据此重建新窗口。

宗室 `delayedApplications` 已进入主队列，以实际执行时刻调用 `delayed-buff`；保留原始任务与 FIFO，不提前应用，也不从日志重新构造任务。

真实完整属性取样调用 `markStatsSample(actorId, frame)`；只读面板、审计或 `Stat` 查询不能调用。发生到期删除时返回 `stats-sample / expired-on-read` 决策，保存真实读取 tuple。普通乐园在反应攻击创建、实际读取加成时调用 `reactionBonus(actorId, reaction, frame)`，消费返回的 `value` 与 trace，并记录 `decisions` 中实际发生的 `react-bonus-read` 清除；不能把普通增伤当作反应加成。

教官与饰金须在真实反应事件处、后续 live EM 读取之前应用。增幅反应原有攻击快照中的 EM 不回填；转化与激化等实际实时取样按主引擎来源顺序读取。谐律使用实际生命之契回调量；辰砂使用来源掉血请求量，不以最终 HP 差替换。

结束状态使用 `captureState()`，主执行器的检查点取样也已纳入本模块私有状态。周期完整性仍须同时核对主队列中的真实延迟任务、活动 buff 及其余执行状态；本专题的通过用例没有证明任意队伍已建立稳态，也不能因本模块没有 RNG 而跳过 Aura、目标时钟或随机状态阻塞。

## 独立结果重放接线

`packages/schemas/src/artifact-buff-state-replay.ts` 与 `artifact-buff-integrity.ts` 已接入公共结果校验。前者独立计算六套状态、应用和门禁，不导入 sim-core；后者从已接受动作、实际 Aura 审计、草核消费、生命与生命之契记录以及真实完整 Stats 取样，导出回调，再核对完整日志与结束私有状态。ReactBonus 读取由实际来源的生成、刷新或草核交付时钟导出；缓存周期命中不会伪造新的读取。

`result-integrity.ts` 的通用属性重放已纳入自动应用、覆盖、更新和移除。宗室延迟不提前进入动作快照；辰砂更新不重设窗口起点；饰金两个属性同时保留。普通攻击快照与反应之后的实时 EM 使用不同取样位置，普通一段剧变、扩散及草核伤害按其生成或交付时钟核对。此接线没有新增另一套伤害计算器。

两条核心用例均通过 `simulationResultSchema.parse` 重新解析完整 JSON，核对 `artifactBuffLog` 与 `artifactBuffState`，再将实际伤害命中导入独立计算器重放。覆盖的普通绽放、饰金普通伤害及谐律普通伤害重放差值均为 0；这不是另建一套伤害计算器。


## 保留的适用范围

六套仍限于明确声明的固定源码普通宿主、全局帧和无角色卡肉范围；普通乐园不接月绽放，普通 ATK／增伤不替代特殊反应公式。宗室特殊持有者分支须由实际来源绑定或显式声明确定，辰砂保留单持有者限制及源码掉血回调语义，教官的多持有者延长 TODO 与宗室／辰砂时序 TODO 继续保留。页面和核心合成用例不认证全部特殊宿主、所有多持有者组合、任意周期稳态或当前游戏内机制。
