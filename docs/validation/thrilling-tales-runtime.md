# 讨龙：真实切人领取、属性取样与完整检查点

本轮将讨龙英杰谭接入普通团队模拟的真实前台切换，使用既有 `activeBuffs → computeStats → snapshot → damage trace → calculator capture` 管线。没有把领取者加成放入持有者面板，也没有对已填写的最终面板再叠一次。五精炼系数与 600/1200 帧常量统一读取 `reaction-formulas/thrilling-tales.ts`。

## 已实现的实际规则

`ThrillingTalesRuntime` 维护两类独立真实状态：各持有者的冷却，以及各接收者共享 `ttds` 属性增益的存在性。只有从持有者切给其他角色时尝试触发。

- 合法轮转在已经完成的实际 swap 动作调用，日志标为 `legal-completed`；不会遍历输入请求提前生成增益。旧式轮转中实际改变前台的动作，包括到场后被能量拒绝的动作，按现有执行行为标为 `legacy-implicit`，不冒称已验证角色切换动画。
- 持有者冷却到期帧仍阻塞。冷却可用时先消耗 1200 帧冷却，再查接收者共享增益；接收者已有则不刷新、不替换、不叠加，也不退还冷却。
- 增益属性贡献为半开区间 `[applyFrame, applyFrame + 600)`，作用为白值 × R1–R5 的 24/30/36/42/48%。领取后换下不会删除增益。
- 来源 `StatModIsActive` 在到期相等时仍返回存在；实际 `Stats()` 完整取样会删除到期相等及更早的 StatMod。接收者存在性独立保存，普通全局 cleanup 不删除它。现有 `computeStats` 的查询与数字增益清理也不会擅自清除这份存在性。
- 只有真实消费完整面板的执行节点调用 `markStatsSample`：已选择的 action-snapshot 攻击、召唤生成时的绑定快照、实际命中的 live-hit 属性和未另保存的附加项拥有者，以及独立武器追击触发快照。空切人、未命中、周期治疗/选择属性查询、粒子 ER、反应 EM/bonus、属性转换和审计查询不额外冒充完整 Stats 读取。周期攻击在其真正交付的 live-hit 节点读取。

`thrillingTalesLog` 记录真实来源、前后台角色、动作身份、实际帧与事件顺序、精炼、结果和两类期限前后值。`owner-cooldown` 的接收者字段为 null，明确表示源码在此分支没有查询接收者。

## 快照与检查点

动作/召唤命中保存的是取样时的 TTDS 状态标签；交付时的实时增益不能冒充旧快照。该状态实际存入待执行命中与存活召唤载荷，独立追击沿用其真实 trigger snapshot。命中恢复继续通过完整结果校验和共享公式核心。

检查点输出 `icdAndTriggerHistory.thrillingTales`，只在真实 runtime capture 可用时解除这一能力的阻塞。持有者与接收者的相等到期帧都保留剩余 **0**；真正已过期、对后续执行无影响的绝对期限可以规范掉。实际增益、待执行快照及其相对起止时间也继续保存。没有按日志重建第二套状态或为冷却增加额外等待。

## 核心实测

仅新增 `packages/sim-core/src/__tests__/thrilling-tales-runtime.test.ts` 的 **3 个用例**：

1. 合法三角色配置：A R1 在 **101** 帧给 C，B R5 在 **261** 帧遇到已有增益，不刷新至 701 的期限，但消耗自己的冷却至 1461；B 在 **1621** 帧成功给 R5，期限至 2221。C 的基础攻击 1000、固定攻击 200，普通伤害依次为 **600 / 720 / 720 / 600 / 840 / 600**。另一个攻击在 700 帧快照、702 帧交付，仍为 **720**，实际 TTDS 标签与旧快照一致；捕获、JSON 导出导入及共享核心重算差值为 **0**。
2. 接收者到期帧 **600**：先切人再 Stats 时，原增益仍存在并阻塞刷新，随后快照无加成；同帧先执行真实 live-hit Stats，再执行动作相位 8 的切人时，旧存在性已清除，R5 可以领取。下一帧伤害分别为 **600 / 840**。持有者冷却恰好 **1200** 帧仍阻塞，1202 帧再次切出可以触发。
3. 同一 40 秒闭合合法循环连续预热 8 周期，完整检查点建立实际周期 **1**，测量伤害 **4080**、DPS **102**；持有者 B 在边界的冷却剩余 **421** 帧。增益数字已经失效时，剩余 0 的接收者存在性仍单独保存，不能用空 numeric buff 列表冒充状态完全相同。

执行记录保持完整：首轮 **1 passed / 2 failed，exit 1**，总耗时 1.03 s、测试 145 ms；失败是新合法轮转夹具将命令/能力种类误写成 `attack`，配置 schema 正确拒绝，尚未进入模拟。仅把夹具改成现有 `normal` 后，重跑这两个失败项，结果 **2 passed / 1 skipped，exit 0**，总耗时 **1.08 s**、测试 **220 ms**。日志分别为 `thrilling-tales-runtime.log` 与 `thrilling-tales-runtime.retry.log`。没有因这些核心用例修改生产逻辑。

主任务统一构建发现检查点载荷推断缺少索引类型，已补 `Record<string, unknown>` 显式声明；这是类型修复，不改变执行。核心代理没有运行旧全集、构建、Monte Carlo 或浏览器批次。

## 独立来源对照与保留范围

另一个代理仅运行一次固定 gcsim 外部样本，以及一次本地对照。**6 次伤害、6 次捕获 JSON 回放均为严格零差，总伤害 65.33266136319587；11 次实际角色转换、6 次讨龙尝试及冷却期限一致。** 外部样本直接证实接收者 602/1803 到期相等时阻塞刷新并消耗持有者冷却、603 帧完整 Stats 删除旧增益。原先计划的持有者到期等号请求被来源正常换人冷却延迟至下一帧，不能把它写成已外测等号；R5 成功领取亦仅由本地核心用例覆盖。详见 `docs/cross-validation/ttds-external.md` 与 `docs/cross-validation/ttds/swap-reference.local-metrics.json`。

当前是固定来源、无角色卡肉的普通宿主模型。角色卡肉延长期限、月曜/星辉特殊宿主和未接入的角色私有 Stats 读取不宣称完成；随机、插件、目标时钟及未导出反应域仍按既有检查点能力独立阻塞。没有宣称固定 gcsim 一致性等同当前游戏服务器实测。
