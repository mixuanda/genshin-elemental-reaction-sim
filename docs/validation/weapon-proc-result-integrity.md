# 独立武器追击：结果完整性与单击复现

本轮范围为钺矛、苍纹角杯、冷寂迸音的固定来源普通伤害回调。来源系数共用 `reaction-formulas/independent-weapon-proc.ts`；机制证据仍为固定源码假设，不提升为当前游戏实测完成。声明模型假设无角色卡肉，不覆盖反应伤害回调或完整武器机制。

## 实际修改

- 当前 1.53 wire 新增显式 `hit.attackTag`、每角色 `weaponProcModel`、`weaponProcLog` 与直接伤害的 `weaponProcLogId`。旧版本类型、迁移及结果边界拒绝这些新字段。武器选项即明确装备声明，不能从角色名字猜类别；同角色不能再装备西风，已有普攻能量武器类别必须一致。两把生命值圆形追击要求所有敌人提供真实位置。
- 结果回放从配置和已执行普通伤害回调推导触发尝试、前台、严格冷却到期边界、独立动作与目标圆心；输出日志不能自行创造追击。来源、倍率、触发面板、触发时 buff、归属、完整命中组、范围外未命中以及父子双向引用均参与原结果校验。
- 追击保持独立动作、自己的物理增伤及暴击/防御/抗性结算；不继承宿主单击覆盖、加算项或轮转身份。触发时快照与落地时敌方状态分开保存。
- 计算器桥恢复触发快照帧，并展示触发帧加 1 帧、来源倍率乘触发时属性的共享 AST。已有普通伤害公式继续负责数值计算；`SimulationHitReplay.weaponProc` 暴露经过校验的来源事件。
- 修复首次实测发现的旧 trusted reaction-delivery gate：只有当前版本具有精确追击日志回链的独立 direct 允许非空父事件；旧普通伤害规则保持。运行核心同时向该裁剪视图传递当前追击日志。

## 执行证据

命令：`npx vitest run packages/schemas/src/weapon-proc-result-integrity.test.ts`

1. 首轮退出 1：1 个新用例失败于旧 `direct damage events must have a null parentDamageEventId` gate；Vitest 875 ms，其中用例 41 ms。未更改用例预期以绕过生产问题。
2. 修复该 gate 与运行结果投影视图后，仅失败的同一文件复验退出 0：1/1 通过；Vitest 1000 ms，其中用例 154 ms，命令墙钟 1.434 s。

独立手算：R3 苍纹角杯 `0.6 × 20000 × (1 + 0.25) × 0.5 = 7500`，与实际独立伤害一致。来源链接、触发 HP 面板、触发圆心、遗漏子事件回链、删除整张追击日志这五种 JSON 篡改均被拒绝。缺少敌人坐标与显式武器类别冲突也被配置边界拒绝。

完整原始命令、失败及复验输出：[日志](logs/weapon-proc-result-integrity.txt)。本分工只运行上述 1 个新用例及其必要失败复验，没有全套、构建、外部模拟或数据生成。运行时四个聚焦场景由对应分工记录，不重复计算为这里的测试数量。

## 边界

这里证明当前声明条件下的事件归属、持久化完整性与计算器数值复现；不宣称三把武器的当前游戏实测、全部伤害来源触发、角色卡肉冷却延长或带追击待执行队列的完整 checkpoint 续跑已完成。未声明模型的既有结果不新增追击日志。
