## 实际接入

`artifactEventModel` 仅声明需要执行的事件效果，不重复添加装备面板。支持 `exile-4pc`、`scholar-4pc`、`gambler-4pc`、`scroll-2pc`。所有模型使用明确的 `fixed-source-no-character-hitlag-v1`，限定当前合法帧轮转和普通伤害引擎。

| 效果 | 真实入口 | 执行规则 |
| --- | --- | --- |
| 流放者四件套 | 已接受的大招起手 | 持有者在场；全队任一接收者仍有共享状态则拒绝；其余队员各自排入 120、240、360 帧后固定 2 点回能任务。 |
| 学士四件套 | 粒子／晶球实际全队分配完成后的单次回调 | 持有者当时在场；180 帧自身冷却；按队伍顺序给显式声明为弓或法器的成员各 3 点固定能量。包括满能、零数量的真实拾取，不包括普通固定回能。 |
| 赌徒四件套 | 已交付伤害使声明目标 HP 从正值变为零 | 冷却检查后核对真实杀手与当时前台；900 帧冷却；复用同一条共享战技串行队列重置一层，后续合法动作读取实际反馈。技能已经可用时仍消耗这次圣遗物冷却。 |
| 烬城勇者绘卷两件套 | 共享夜魂迸发实际触发 | 给持有者 6 点固定能量；不要求持有者在场，没有额外套装冷却。未把四件套反应增益称为自动完成。 |

固定能量写入现有能量状态、上限、溢出、曲线和统计桶，`rawEnergy === finalEnergy`、`energyRecharge === 1`。新的 `artifactEventLogId` 关联真实能源记录，赌徒重置关联真实 `skillCooldownLog`，不伪装为祭礼触发。

共享 `nightsoulBurstModel` 显式声明纳塔参与角色 ID。真实普通元素伤害交付后排入同相位 FIFO 回调；1、2、3／4 人对应 1080、720、540 帧共享冷却。地区身份是配置声明，不从角色名猜测，也不据此把角色数据标为 verified。

角色状态采用固定源码的到期帧仍有效规则；夜魂全局状态采用 `Duration > 0`，到期帧即可再次触发。两者分别存储和规范化。
