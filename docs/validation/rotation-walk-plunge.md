# 轮转横向功能：walk 与已声明 plunge

本轮完成 master §18 对行走和下落攻击输入的缺口；未增加新的角色倍率、动作帧或自动跳跃物理假设。

## 已实现

- DSL 接受 `walk 12f`、明确提供占用映射后的 `W`、`plunge <行动ID>`，以及当前角色唯一已声明下落能力或明确别名的 `P`。`plunge`／`P` 必须引用 `kind: "plunge"`；名称或命中标签都不能制造下落能力。
- 导出、再解析保留当前角色、显式 `for`、请求帧、等待、移动、拾取、下落和 repeat 展开的输入。`N5` 仍展开为明确普攻链的前五次输入，某次输入含多段命中不会改变该语义。
- 已有移动费用及其数值、扣除时点、零值调用声明、来源文本一并保留。DSL 的可选 `stamina` 元数据后缀只承担无损序列化，正常费用仍通过既有表单编辑，不引入默认消耗。
- `walk` 复用现有移动的显式占用、取消、前台及共享体力逻辑；执行延迟方案和稳态尾段也纳入其取消或延迟费用。行走不自动生成空间位移，实际位置轨迹保持独立声明。
- `plunge` 必须显式声明 `timelineState.requires: ["airborne"]` 和 `consumes: ["airborne"]`。只有此前实际接受的已声明能力才能通过既有 `timelineState.grants` 提供仍未过期的腾空状态；下落消耗它。普通 jump 仅有占用信息，不授予未知高度或未知持续时间。
- 合法时间线编译器执行状态门槛，独立结果重放也验证接受的下落动作具有有效的来源腾空状态。真实能量或体力失败不会成为已接受的升空能力。
- 当前配置／结果支持 walk、plunge 和相应取消项，历史冻结格式保持原动作范围；临时旧格式校验投影不改变保存的真实动作类型。
- 正常轮转编辑器增加行走按钮及只列出已有下落能力的下拉选择。没有下落定义时禁用该入口并说明原因；固定来源预设继续遵守各自允许的动作范围。

## 仍有明确边界

这里提供执行已声明能力的轮转能力，不认证所有角色的下落动作时序。没有实际升空来源定义、下落能力定义或腾空有效状态时仍拒绝执行；独立单次下落伤害计算器继续可用。行走占用不等于位置变化、碰撞或高度模拟。
