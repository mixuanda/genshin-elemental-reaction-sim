# 普通合法动作的真实共享战技冷却

本次把既有实际串行充能运行时从祭礼专属限制中解开，没有复制第二套冷却算法。任一战技显式设置 `cooldownStartFrame`（包括 `0`），即可让该角色全部战技变体共用实际 E 槽；现有祭礼配置继续选择同一运行时。既未填写该字段、也未声明祭礼的旧配置保留原独立静态槽规则，不静默改变历史输入或执行配置含义。

共享选择器为 `getRuntimeSkillCooldownActors`。当前配置验证要求同槽变体的最大充能数一致、实际恢复时长为正数；每个变体可以具有不同恢复时长和冷却开始延迟。显式 `0` 表示起手立即执行 SetCD；留空变体在该角色已启用共享槽时也按零延迟处理。

实际接受的动作才排延迟 SetCD。任务执行时扣除一层并把该次恢复时长加入有序队列；恢复 worker 每次只归还队首一层，剩余队列从该次恢复时点继续串行计时。能量不足、结构拒绝的请求不会生成技能或冷却任务。已有祭礼成功回调仍只归还一层并替换恢复 worker，没有把重置简化为修改末尾到期时间。

合法编译逐请求读取已执行前缀的真实队列转换，决定最早可用帧，再处理体力和动作状态。共享槽也使用已有同帧相位顺序约束，避免较晚相位的上一输入与较早相位的后续输入反向执行。`skillCooldownLog` 现在也属于无祭礼的通用共享槽；`sacrificialLog` 仍仅在显式武器模型存在时输出。导入结果从实际接受动作及来源回调独立恢复队列，不以自报冷却日志作为排程依据。

执行配置、轮转重复及随机启动的固定请求模板均通过真实参考模拟取得这类动作基线。旧 `1.0.0` 结构执行配置明确拒绝需要真实共享冷却的输入；没有把旧配置版本悄悄升级。普通动作编辑开放该字段，说明留空／零值区别，固定来源动作仍只读。

周期检查点直接保存实际共享槽、剩余充能、有序施放队列、worker 开始时点和相对代次；当前 worker 与已失效 worker 的待执行任务保持可区分。选中的 E 不再通过独立槽公式重建。无祭礼角色的真实未来冷却任务保留在 heap 中，即使晚于观察结束；执行仍止于原观察窗，不为等待整个冷却而延长模拟。既有祭礼保留原末尾裁剪及审计序号行为，且仍受未导出随机流的独立稳态阻塞。延迟冷却开始时点进入必要尾段计算，完整恢复时长不被当作额外强制等待。

同时补全信使待执行回调检查点中的可选 `hitWeakPoint` 字段，避免把弱点与非弱点的不同未来结果归一成同一状态。

已准备唯一综合回归 `packages/sim-core/src/__tests__/generic-skill-cooldown.test.ts`，涵盖无武器的延迟启动、同槽不同恢复时长、失败动作不占槽、自然恢复同帧消费及真实检查点。根任务已将该唯一综合用例纳入共用模块批次，实际通过；相关构建通过。未重复旧祭礼/角色全集，见[批次日志](module-completion-focused.log)与[QA](../qa-report.md)。
