# 祭礼实际技能重置与合法轮转反馈

## 实际实现

本轮将祭礼剑、祭礼大剑、祭礼弓、祭礼残章接入普通团队的真实伤害回调。声明入口为 `sacrificialModel.mode = fixed-source-no-character-hitlag-v1`，必须配有合法轮转和明确的持有者、武器、精炼等级；角色所有 `kind: skill` 的技能变体共用一个 E 充能队列，最大充能数必须一致。不能用动作名字推断攻击标签，也不能用旧式 rotation 冒充真实技能槽。

来源固定在 gcsim `b4ae769d7c1c1bce68fce5faf0b460c5b5b7f541` 的 `internal/weapons/common/sacrificial.go` 和 `internal/template/character/cooldown.go`。共同参数、队列纯函数位于 `packages/reaction-formulas/src/sacrificial.ts`、`skill-cooldown.ts`；运行时位于 `packages/sim-core/src/sacrificial.ts`，宿主接线和实际事件调度位于 `simulator.ts`，合法请求反馈位于 `legal-timeline.ts`。

实际回调依次检查：本人在场、明确的 skill 标签、武器冷却未生效、技能 `Cooldown(E) != 0`、实际伤害非零，之后才抽样。仍有任意一层技能充能时 `Cooldown(E) = 0`，不抽样。精炼概率保留来源表达式 `0.3 + 0.1 × R` 的浮点值，比较为严格 `roll < probability`；失败不消耗武器冷却。R1–R5 的武器冷却为 1800/1560/1320/1140/960 帧，到期帧仍阻塞。

技能冷却使用串行队列。每次真实 SetCD 才扣一层并追加本次恢复时长，`cooldownStartFrame` 可以显式延迟 SetCD。祭礼成功只恢复一层、弹出队首，并让剩余队列从触发帧按完整时长重新恢复。原 worker 保留实际任务身份，执行时以 generation 判定失效，不会重复恢复充能。不同技能变体可以提供不同恢复时长。

合法轮转对每个相关技能请求先运行此前真实命令前缀，读取实际队列转移，求当前请求相位能消费充能的最早帧，再编译这个请求。strict 模式在这一步之后才判断冷却是否合法；不会先被旧的静态独立充能槽拒绝。能源拒绝也保留既有的顺序反馈。前缀求冷却锚点不提前消耗或等待体力，体力在正式冷却反馈后独立处理。

`skillCooldownLog` 保存实际 start/recover/reset/stale-worker 前后队列、worker 身份及来源 cast/ability/command；`sacrificialLog` 保存每次真实条件结果、惰性冷却查询、实际抽样及双向 reset 关联。后续技能能产生自己的实际命中、粒子和能量，伤害仍经共享核心和现有 capture/JSON/replay 桥接。

## 同帧与随机边界

延迟 SetCD 与自然恢复任务使用 priority -1，位于普通 action 0 之前；零延迟 SetCD 则在实际动作内执行。普通伤害回调仍沿用宿主实际命中相位：相位 3 重置对默认 action 0 最早下一帧可用，显式 action 8 可以同帧消费。祭礼模型下，如果已排动作在同帧的相位高于下一请求，wait 模式增加一帧 ACTION_OVERLAP，strict 明确拒绝，避免 heap 将命令倒序。无祭礼模型的既有调度行为不变。

这不是所有 gcsim 任务插入顺序的普遍认证。固定源码同帧任务按插入顺序处理，多目标攻击先结算各目标伤害，再投递 OnEnemyDamage；当前接线使用普通宿主已提供的逐命中回调位置。已验证样本中的 CD-start、伤害回调和恢复时序一致；复杂同帧交叉任务的完整源码等价性仍需逐来源接入，不应由本报告推定。

随机流为独立命名的 `sacrificial-v1`，算法为现有 `fnv1a32-mulberry32-v1`。本地相同种子可重现；gcsim 使用共享随机流，相同 seed 不代表相同抽样序列。完整确定性周期检查点继续明确阻塞祭礼 RNG、串行充能及延迟任务状态，不将“此轮抽中”当作确定性稳态。月曜/星辉特殊宿主、角色卡肉延长、未声明的技能冷却修正和当前服务器实测认证不在本轮完成范围。

## 执行验证

仅新增 `packages/sim-core/src/__tests__/sacrificial-runtime.test.ts` 的 3 个核心用例；未跑旧全集、性能测试、MC 或构建。

首次执行 2 通过、1 失败，Vitest 1.09 秒、测试 205 毫秒，退出码 1。失败来自体力子夹具仍保留两个未声明体力消耗的未使用能力，配置校验在模拟前拒绝。修正夹具只保留实际使用能力；同时按独立静态审阅补入上述同帧相位先序约束及其检查。只复验该失败用例，1 通过、2 跳过，Vitest 957 毫秒、测试 70 毫秒，退出码 0。已通过用例未重复运行。

日志保存在 `sacrificial-runtime.log` 和 `sacrificial-runtime.retry.log`。实际断言包括：

- 合成三变体共用两层充能，恢复时长依次 600/900/1200。请求 1/57/99 帧实际执行于 1/57/100 帧；延迟 SetCD 在 10/66/109 帧。43 帧仍有一层，不抽样；99 帧真实触发后只恢复一层，剩余 900 从 99 重启。旧 610 帧 worker 不恢复，999/2199 帧各恢复一层。
- 三击分别在 43/99/142 帧造成 500 伤害，合计 1500；实际命中产球在 143/199/242 帧接收，最终能量 36。第三击 capture → JSON → replay 差值 0。
- strict 默认相位在 99 帧请求第三 E 被拒，明确最早 100；显式相位 8 在 99 帧成功。相位 8、取消帧 0 后同帧请求默认相位，会实际排为 1/2 帧。单次十体力技能在 114 帧执行，只记 INSUFFICIENT_STAMINA，不误记技能冷却等待。
- 前置场上/标签/剩余充能/零伤害门槛不抽样；R1 固定流首个 0.6284964594524354 失败且无 ICD，第二个 0.32096404768526554 成功。到期 1811 帧不抽样，1812 帧才再次抽样。旧式无 timeline 配置拒绝，确定性 checkpoint 明确阻塞。

共享队列、结果完整性、消费者和浏览器验证各由对应责任代理记录，未在此重复执行。结果独立核验按真实动作、回调和来源队列重新推导，不能仅修改自报日志通过。

## 外部对照

独立代理只运行一次 gcsim 砂糖 C1 外部样本，记录 E 起手 1/57/113、SetCD 10/66/122、99 帧祭礼重置、旧 910 worker 失效、999/1899 恢复；三组各 4 风粒子在 143/199/255 帧接收，各获 12 能量。本地外部对照首次在配置解析处因目标 ID 与 Aura 版本夹具错误停止；仅修正夹具后对照通过，没有生产修复。

9 次伤害各为 36.491855604123714，全部与外部逐值残差 0；9 次 capture JSON 回放差值 0，完整结果 schema 通过。实际队列、粒子和能量与来源样本一致。本地祭礼首个抽样值为 0.6284964594524354；外部日志不包含具体 roll，不伪造与外部随机数相等。
