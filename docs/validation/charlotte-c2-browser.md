## 实际页面操作

通过正常 `/calculator` 角色、动作选择器载入夏洛蒂长按 E，设为 C2、有效 E 天赋 1、突破 6。共同教学最终面板为 ATK 1000、HP 10000、DEF 800、EM 0、CR 0.5、CD 1；角色与敌人均 90 级、抗性 10%。明确两名非枫丹其他队友、A4 未含、标记完整持续、其余状态稳定。基础攻击明确填写 500，共同面板已含 C2 层数明确填写 0。

起初 C2 份额、基础攻击及逐击状态未知，完整技能阻塞。单选第一标记并填写实际一层后，其他未选命中保持未知也可计算；单选未填状态的最后标记则阻塞，明确填零后恢复计算。切回完整技能仍因其他未填命中阻塞，补齐九击后才能生成完整结果。

九击明确状态为初击 0、前七个标记 1、最后标记 0，与[固定外部长按观测](../cross-validation/charlotte-c2/hold-reference.reference.json)的状态顺序相同。本流程使用独立教学面板核对算式，没有把该外部样本的 Lv1 数值当成当前 UI 面板输出，也没有重新执行外部程序。

随后把共同最终 ATK 改为 1050、已含 C2 改为一层。实际修正成为 `[-50, 0, 0, 0, 0, 0, 0, 0, -50]`，首尾两击各扣除已不适用的 50 点攻击，完整伤害与之前完全相同。正常导出、导入 JSON 后，基础攻击、已含层数、九击选择和逐击状态均保留；伤害总计及每击完整结构化轨迹严格相等。

页面同时实际展开了 `sourceAttackAdjustment` 详情，核对共享核心的代入文本和 `charlotteBaseAttack` 变量，未注入内部状态或另写页面算式。
