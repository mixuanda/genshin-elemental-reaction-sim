# 三把独立武器追击的确定性周期检查点

钺矛、苍纹角杯和冷寂迸音的已实现普通伤害回调模型，现在可以在既有确定性、静止目标支持域内提供完整检查点。新增状态来自实际运行时与真实主队列；没有根据输出日志重建追击，也没有改变 Aura 版本、队列优先级或来源冷却边界。

## 实际变更

- `IndependentWeaponProcRuntime.captureState()` 复制真实持有者声明和 `cooldownExpiresFrames`。检查点输出位于 `icdAndTriggerHistory.weaponProcs`。冷却到期帧仍阻塞，因此 `expiry === tick` 保存 `remainingCooldownTicks: 0`；只有 `expiry < tick` 才和从未触发的状态共同规范为 `null`。过期绝对帧只影响后续审计文字，不影响再次触发。
- 实际待执行命中载荷增加 `weaponProcContext`，保存触发时角色武器声明、触发帧和增益快照。命中执行也从这个队列上下文读取增益快照，日志不再承担待执行追击的增益状态。
- `pendingEvents.inFlight` 读取实际队列中 action、hit、角色属性快照、物理加成、目标和几何、priority，以及真实 FIFO 顺序。增益保存相对起止时间，包含在落地边界已到期但仍属于触发快照的增益。
- 动态生成的 action/hit ID 规范为 `weapon-proc:<actorId>:<weaponId>` 及其 hit；实际命中组按队列相对身份保存。绝对日志序号和周期审计号不阻止真正周期成立，数值快照、范围、目标顺序、精炼与加成继续保留。
- 只有提供真实 `weaponProcState` 才解除这一能力的阻塞。没有配置武器追击的检查点保持原有形状。
- 共用 `actionPendingHorizonTicks` / `abilityPendingHorizonTicks` 接受武器模型，为对应持有者的适用普通命中和周期实体末次命中增加实际交付延迟 **1 帧**。钺矛仍要求显式 normal；不会给纯粒子或生命任务盲加延迟，也不会为了冷却人为追加 600/900 帧等待。启动尾段与检查点截断门槛使用同一函数。
- 新的合法轮转用例暴露了旧结果校验的漏接：独立追击曾被要求引用已接受技能指令。现由完整来源重放识别独立追击，检查真实宿主和子事件身份，并明确禁止借用宿主 timeline metadata；未删除原有合法指令校验。

## 实测结果

新增测试仅为 `packages/sim-core/src/__tests__/weapon-proc-phase-checkpoint.test.ts` 的 **3 个用例**。没有运行旧全集、构建、类型检查、Monte Carlo 或浏览器批次。

1. 三武器合法闭合循环：960 帧/16 秒，持有者 A/B/C 分别在 **955/957/959** 帧触发，追击在 **956/958/960** 帧；初始和末前台均为 C，换人显式声明。使用原生 **aura-v9 + target-phase-v2**，水火宿主实际执行增幅判定，武器追击保持物理伤害。8 周期连续预热，模拟总长 **9600 帧**，5 个相位检查点完整且相同，实际周期 **1**。测量窗口 **[7680,8640)** 总伤害 **9800**，DPS **612.5**。

   边界上的三把冷却剩余分别为 **595/897/899**。真实待执行队列含冷寂迸音两个目标的追击，`remainingTicks=0`、`priority=3`，保持目标 FIFO。触发时 HP 增益已在边界到期，但待命中快照仍为 `hpPct=1`，增益 `startAgeTicks=1/endRemainingTicks=0`；第 960 帧实际伤害为 **4000/2000**。

2. 真实运行时冷却到期等号保存 **0**，下一帧已过期状态与从未触发状态等价。另在两个实际模拟中让当前增益都已到期、冷却一致，但保存的触发 HP 快照分别为 1 和 2，待执行状态不能判相等。改变实际目标排队顺序同样保留为不同状态。

3. 普通宿主延迟 480 帧，武器尾部必须为 **481 帧**；截掉该帧的检查点被拒绝。周期实体在第 **24** 帧执行真实 tick，延迟到 **649** 帧命中，再于 **650** 帧执行独立追击；启动模拟总长 **1610 = 960 + 650** 帧，覆盖实际尾部，没有增加冷却等待。随机暴击、目标时钟、缺少实际捕获及不完整尾段继续阻塞。

## 执行与失败记录

- 首轮：**2 passed / 1 failed，exit 1**；953 ms，总测试 83 ms。失败原因是新增 v9 夹具遗漏合法轮转声明与 Pyro geometry，未进入模拟。日志 `weapon-proc-phase-checkpoint.log`。
- 仅重跑失败第 1 项：**1 failed / 2 skipped，exit 1**；944 ms，总测试 92 ms。夹具修正后暴露上述独立追击的合法指令旧校验问题。日志 `weapon-proc-phase-checkpoint.retry.log`。
- 修复后，只重跑失败第 1 项以及补入真实周期尾部模拟的第 3 项：**2 passed / 1 skipped，exit 0**；1.01 s，总测试 148 ms。第 2 项已在首轮通过，没有重复执行。日志 `weapon-proc-phase-checkpoint.retry2.log`。

上轮 `independent-weapon-proc.test.ts` 的短观察窗断言同步改为真实“不足两次完整输入周期”理由；没有重跑该旧文件。

## 仍未覆盖

这是固定来源 **无角色卡肉**、普通伤害回调的确定性支持域。反应伤害回调、月曜/星辉特殊宿主、目标移动或目标时钟、私有随机流、插件以及未导出的特殊反应生命周期仍独立阻塞。完整检查点不把这些未实现机制标为完成，也不把固定 gcsim 一致性等同于当前游戏实测。
