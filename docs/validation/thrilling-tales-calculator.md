# 外部讨龙逐击攻击力记账：独立计算器专项记录

2026-09-24。本轮为普通伤害命中增加可选的外部讨龙条件，独立单击和完整技能均可使用，不要求建立团队或轮转。此入口计算用户明确声明的实际生效份额，不负责触发切人领取，也不把条件计算标为讨龙全机制已验证。

## 实际实现

共享定义位于 `packages/reaction-formulas/src/thrilling-tales.ts`：武器目录 ID `weapon:14302`，R1–R5 攻击百分比分别为 24%、30%、36%、42%、48%，名义持续 600 帧、持有者冷却 1200 帧。团队运行时和独立计算器导入同一份数值定义。

`CalculatorDocument.incomingThrillingTales` 保存外部来源 `ownerId`、`ownerLabel`、`refinement`、当前面板 `baseAttack`，以及以命中 ID 索引的 `hitStates`。来源身份是用户声明，不要求真实队伍 ID，也不从接收者自持武器推断已经收到增益。每击状态包含：

- `active`：此击实际取样时讨龙是否有效；未填不等于否。
- `includedRefinement`：此击输入面板已含的讨龙精炼档，0 明确表示未含，1–5 表示已含旧 R 档；未填不等于 0。
- `baseAttack`：仅供该击历史 `finalSnapshot` 的自身白值。当前普通命中使用来源配装推导白值，或共同的显式白值，不读此历史字段。

每击通过共享 AST 计算：

```text
实际比例 = active × coefficient(来源精炼)
已含比例 = includedRefinement 为 0 时的 0，或 coefficient(已含精炼)
ΔATK = 基础ATK × (实际比例 − 已含比例)
本击ATK = 输入面板ATK + ΔATK + 角色自身ATK调整
```

差额可为负，支持移除已过期但仍包含在输入面板中的旧份额。若实际比例与已含比例相等，直接执行明确的零差公式并解释两份相等，不索要不参与结果的未知白值。这里仅有一个实际讨龙份额，旧 R 档用于面板记账，不构成两把讨龙叠加。

核心派生 `ordinary.incomingThrillingTalesFormula`，独立于角色原有 `attackAdjustment`，因此可同时保留夏洛蒂 C2 等角色调整。每击包含 `<hit>.incomingThrillingTalesAdjustment` 和 `<hit>.afterIncomingThrillingTales` trace，使用既有公式树、变量释义、实际代入、结果和来源显示。`calculateDocument` 与转最终面板入口均重新 prepare；JSON 手改派生公式不会覆盖真实条件，删除顶层条件会清除旧派生公式。单击只要求所选命中的条件，完整技能要求各选中段分别明确。

## 当前面板、历史面板与导入

来源装备使用角色基础攻击与武器基础攻击之和，并将该白值保留在共同 context，便于转为最终面板后继续编辑。转换不把某个命中的讨龙或角色增量写入所有命中共享的最终 ATK。复验覆盖共同白值从 500 改为 600 后立即改变结果。

新来源配装将当前命中的已含份额设为明确未含；新展示柜最终面板清除当前已含份额和共同白值，要求用户重新说明。两种操作均保留外部来源和实际生效假设，并保留未被替换的历史 `finalSnapshot` 自身逐击白值、已含份额及实际状态。历史命中不能借用当前装备或共同白值；替换历史快照时，用户仍须核对其自身条件。

## 固定来源与实际字节

新 [来源清单](../../packages/game-data/sources/thrilling-tales/manifest.json) 复用既有归档的 **7 份实际源文件**，没有重新复制整批来源。6 份为已有原文文件，1 份基础属性源码取自已有 `charlotte-c2/source.json.gz`，清单记录原文 SHA-256 及压缩归档 SHA-256。来源提交为：

- gcsim `b4ae769d7c1c1bce68fce5faf0b460c5b5b7f541`：讨龙武器、切人、属性修改、卡肉、modifier 和基础 ATK 百分比算法。
- genshin-db `49a6544a6c6ae36089cb42fa591fc46f01de8bcf`：中文武器目录原文。

R1–R5 共 5 个倍率位置，gcsim 源式 `.18 + R × .06`、固定目录与共享定义一致。源码的持有者冷却先于接收者已有 `ttds` 判断；接收者已有该份额时不刷新、不覆盖、不叠加。源码使用角色卡肉相关的持续时间。独立入口仅展示这些来源边界，不能据此声称已经模拟它们；清单保持 `source-backed-provisional`，没有把 released 数据身份等同于机制 verified。

## 独立手算与剩余边界

夏洛蒂 C2、E T1 长按 9 击，当前 ATK 1000、基础 ATK 500、暴率 .5、暴伤 1、角色／敌人 90 级、抗性 .1、A4 两名非枫丹队友提供 .1 增伤。初击及末标记均明确无 C2／讨龙，中间 7 标记各有 C2 一层与外部 R5，当前面板两者均未含：中间每击 ATK = 1000 + 500×.1 + 500×.48 = 1290。

```text
完整非暴击 = (1.392×1000 + 7×.406×1290 + .406×1000) ×1.1×.5×.9
           = 2704.7691
完整期望   = 2704.7691 ×(1+.5×1) = 4057.15365
```

只修改讨龙共同白值为 600 后，中间 ATK = 1000+50+288 = 1338，完整非暴击为 **2772.29502**。末击实际无讨龙、输入面板仍含旧 R1 时，ATK = 1000−500×.24 = 880，单击非暴击 **176.8536**。独立历史样本的 ATK 1300、历史白值 300、实际 R5／已含 R1，经 2 倍倍率、.5 防御和 .9 抗性后为 **1234.8**；当前共同白值不参与。测试以独立手算断言近似相等，没有将浮点末位差宣称为逐位一致。

此报告证明的是上述来源与独立逐击数值路径。自动切人领取、600／1200 帧时序、卡肉延长、多来源接收资格、刷新和到期需要真实运行时另行验证。捕获模拟命中的重放还应保留“取样时已经包含”的份额，不能再加一次；本独立核心允许实际 R 与已含 R 相同的零差表达，但本轮两个测试没有代替团队回放专项验证。
