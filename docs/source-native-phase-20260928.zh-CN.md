## 实际实现

- `phase("rotation");` 是 opt-in 来源脚本标记，在真实 `queuePhase` 取下一个动作前让解释器交出状态。它不产生游戏动作，也不推进帧；同一队列边界重复标记会报明确信息。
- 重复输入依据原生 AST 调用位置、程序摘要和词法环境签名。首次标记不算已确认重复；后续相同位置／环境才有确认。用户函数捕获、未覆盖的调用延续、帧／随机／异步查询会保留输入缺口，不能只凭相同文字标签证明。
- 导出 input、simulation、player、characters、effects、targets、tasks、events、rng、external 十类状态。包含冷却与充能队列、角色本地任务、动画、护盾／附魔、目标顺序与碰撞形状、附着／ICD、构造物、外部受伤／能量计时及有序订阅。
- 队列读取副本后按执行时间和 FIFO 排序，不运行闭包。已有任务的 FIFO 排名可归一化；原始递增插入计数本身不改变排序关系。闭包捕获值尚未提供时单列缺口，不能仅比较 deadline。
- 读取固定 Go `math/rand.rngSource` 的 tap、feed、607 项向量与 Rand 字节缓存；64 位值用字符串保存。读取不调用随机方法，也不推进随机流。固定种子仍必须比较完整 RNG 状态，不能把暴击期望或零暴击率当成无随机状态。
- TypeScript 判定核对已确认输入、全部提供者、实际相对状态、周期时长和累计伤害之差，允许 period-k，并要求多个连续周期一致。支持有缺口或尚未确认的起步前缀；缺口、状态差异和实际区间差异可见，未建立时没有稳态 DPS。正例单元夹具仅验证判定算式，不充当原生正例。
- 来源队伍页面新增启用选项、可编辑相位示例、预热帧数、周期与采样上限，并展示原生记录、差异及完整 JSON。结果导入／导出保留政策和全部观察；从头复跑请求和比较入口也保留相位字段。
- 独立伤害计算器、逐击共享公式及已有队伍可视化流程继续保留；未修改数据分类和已验证状态。

## 尚未完成与下一步

实际最后边界中，classic／stellar 分别有 35／38 种事件订阅的捕获状态尚未导出，另有角色私有状态、武器私有状态和一项 Amount 回调缺口。这里是事件种类与回执条目计数，不是 35／38 个游戏机制；其中纯日志／统计回调尚需按源码明确区分。还没有可宣称覆盖完整的原生相位样本。

可比较状态仍保留了若干保守的历史计时值，例如空冷却队列的旧 worker 时点、角色累计本地时钟和已失效对象的过期差。这些会造成无意义差异，需要按实际读取语义去掉或规范化，不能仅为让测试变绿忽略它们。下一步是来源内回调／任务捕获描述与具体私有状态导出，连同这些时钟语义整理，之后才可能建立真实的周期正例。随机运行仍需预热与分布证据，不能用此确定性判定替代。

其余完整动作组成、广角色独立执行语义、游戏验证、完整版本身份与远程更新运行等缺口仍见主矩阵。当前实现使稳态所缺状态可直接观察，没有将目标缩减为有限窗口分析，也没有宣称 master 全量完成。
