## 白术 A1 与共享快照

[gcsim 白术 A1](https://github.com/genshinsim/gcsim/blob/b4ae769d7c1c1bce68fce5faf0b460c5b5b7f541/internal/characters/baizhu/asc.go) 和 [Optimizer 白术生产表](https://github.com/frzyc/genshin-optimizer/blob/180a0a1015cb725c7570cd828eb086749960df98/libs/gi/sheets/src/Characters/Baizhu/index.tsx) 都要求突破至少 1，当前场上角色生命不少于 50% 时增加 25% 草元素伤害。E 的三次链式攻击使用同一个起手 Snapshot，所以实际输入是 **E 起手在场角色的生命比例**，不是每击生命，也不是默认满血。

`gameContext.baizhuSkill` 保存 `activeHpRatioAtCast?` 和 `a1IncludedInPanel`。默认不提供生命比例：已解锁 A1 时三击明确阻塞；突破 0 没有此依赖。0.5 正好达到门槛。已含开关仅处理实际增伤中的 A1 份额，草伤公式为：

`0.25 × (I[起手生命比例 ≥ 0.5] − I[已含])`

公式由共享 AST 核心执行；三个命中由同一上下文准备，不使用 UI 算术。核心 `calculateDocument` 与最终面板转换入口也重新准备此上下文，因此直接改 JSON 中某段复制出来的 A1 公式不会制造三套互相矛盾的起手条件。公式说明、变量、实际代入和中间结果沿用已有结构化轨迹。

装备重新生成将“已含”设为 false；导入最终面板将它设为 true，依旧要求用户补充实际起手生命，绝不拿当前展示角色生命替代过去条件。JSON 与最终面板转换保留同一上下文。
