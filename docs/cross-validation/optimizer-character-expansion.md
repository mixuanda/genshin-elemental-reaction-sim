## 固定来源与拒绝采用的代码

使用 [Genshin Optimizer 固定提交 180a0a1015cb725c7570cd828eb086749960df98](https://github.com/frzyc/genshin-optimizer/tree/180a0a1015cb725c7570cd828eb086749960df98)，提交日期 2026-08-27T03:19:12Z。以 `libs/gi/sheets/src/Characters/*/index.tsx` 生产角色表建立缩放属性、标签、组成次数及条件语义，以 `libs/gi/stats/Data/Characters/*/skillParam.json` 逐项比对活动 7.1 目录的完整 15 级参数。

该提交中若干 `libs/gi/formula/src/data/char/*.ts` 文件仍有 TODO 与人工 `atk.add(1)`、`defRed_.add(1)` 占位表达式，**没有采用**。不是只发现目录就宣称机制可用，也没有从中文百分比标签猜 ATK 或伤害类型。源码仅按固定 URL 下载、检查 SHA-256/Git tree 身份和阅读，没有执行下载的 TypeScript。MIT 许可文本保存在卡齐娜来源清单中。

证据分别在 `optimizer-kachina-source-manifest.json`、`optimizerNormalSourceEvidence`、`optimizerAdditionalSourceEvidence`、`optimizerSkillSourceEvidence` 中保存。固定 tree 完整性与剩余身份目录检查在 `pinned-optimizer-source-availability.json`。每个命中的 `sourceRepository`、commit、文件路径进入计算器来源；不会给 Optimizer 路径错误拼接 gcsim URL。

## 真正执行的资源与被动公式

- 奈芙尔 E：先计算 `B = ATK×a + EM×b`。突破≥1且月兆人数≥2时，在基础伤害区加入 `B×0.08×帷幕层数`。外部固定附加伤害不被这一倍率放大。输入的最终 EM 已包含实际生效的属性来源，核心不会重复增加 A1 的 EM。
- 奈芙尔 Q：两个命中分别读取 `本次实际消耗帷幕数×该有效Q等级的param5`，加到伤害加成区。不能用消费后的剩余零层，也不会为第二击再消费一次。C0/C1为0–3整数，C2+阻塞；月兆与突破门均有明确执行。param5的完整来源向量成为单独依赖，漂移只阻塞Q。
- 阿罗夏 A4：突破≥4时，E/Q伤害加成 `0.0035×min(100×ER,200)`，ER为比值。真实ER=1产生35%，ER≥2达到70%。核心直接读取最终面板ER，适用时缺失则阻塞；未解锁时不要求ER。默认100%只是明确注明的教学面板，不能替代导入角色的真实数值。

三条表达式均使用与其他计算相同的 typed AST、数值代入与结构化 trace，文档 JSON 往返保留资源输入及来源。规则见 `apps/web/src/character-source-formulas.ts`；没有另写一个只用于展示的算式。

## 保留的具体缺口

1. 剩余未分类身份：奇偶男女缺少活动目录天赋集合；沃雅妮莎、薇斯纳在这三份固定实现中没有生产角色实现。此事实只描述已检索版本，不证明其他来源永久不存在。
2. 莉奈娅露米 E：本批结束时缺少自动抗性上下文；后续已接入 A1 岩抗15%/30%条件公式与所选普通双击。持续完整时序、月结晶锤击/粉碎仍是缺口，见后续报告。
3. 洛恩特定 E/Q：本批结束时缺少可追踪争胜资源分支；后续已执行 `1+0.004×willConsumed` 的已审输入域。真实资源自动事件、技能有效等级与 A4 状态恢复仍须完整，未用默认零资源冒充可达战斗情境。
4. 叶洛亚 Q：Song开启的自身加值为 `EM×[Q.param3+A4人数项]`，A4水/岩人数1、2、≥3时分别0.07、0.14、0.24。静态生产表不能证明新施加Song与Q初击先后；本批不提供伪定值。
5. 奈芙尔幻戏/月绽放影子、兹白第二段月结晶、桑多涅辉映/星扩散分支仍需特殊伤害组件和状态归属映射。普通组成的可计算性不表示这些部分已完成。
6. 本批所有来源都未验证真实角色全轮转、帧时序、附着、ICD、能量、队友触发或所有命座。已有相关能力与未支持范围各自保留，不合并成“角色全ready”。
