# 显式协同日程：十二个 C0 条件施放

本批以同一事件协议取代十八条部分动作：行秋 Q、夜兰 Q、托马 Q、空/荧雷 Q、雷神 E、宵宫 Q、阿贝多 E、迪希雅新 E/重新放置 E、菲谢尔新 E/完整 Q。23 条初击/追击系数模板由共享核心展开为实际独立命中；次数随使用者明确记录的事件变化，模板中一条追击不代表全寿命总伤害。

`coordinated-cast-schedule.ts` 只接收显式观察，不生成队伍轮转。普攻状态区间与伤害事件分别保留行为者、在场者、目标、标签、非零伤害、领域范围、来源等资格信息；只要求各来源实际读取的字段。未知资格阻塞，已知不合格事件跳过，空数组必须明确填写。无卡肉、替换、中断、完整观察及所有生成伤害实际命中均须明确确认；完整动作还要求来源取样间的基础面板、装备条件及反应属性稳定。

## 固定来源

- gcsim：`b4ae769d7c1c1bce68fce5faf0b460c5b5b7f541`，原文和许可保存在 `packages/game-data/sources/coordinated-casts/source.json.gz`。
- 同目录 `manifest.json` 记录归档 SHA256、每份原文 SHA256 和 Git blob SHA1；134 份归档均匹配未截断的固定 Git tree，42 份另匹配此前已审阅归档指纹。
- 20 组系数逐一比对全部 15 个有效天赋等级，与当前活动目录完全相等，最大绝对差为 0。共同读取 `definitions.json`，核心不依赖浏览器生成一份不同的倍率。
- 系数与源码一致属于固定来源条件支持；没有将其升级为当前游戏逐帧实测或完整团队验证。

## 生命周期与资格

| 来源组 | 核心实际处理 |
| --- | --- |
| 行秋、夜兰、托马 | 普攻状态进入的冷却检查与已启动的 60 帧 ticker 分开执行；被冷却拒绝的新状态不替换旧 ticker。行秋雨帘剑按 2/3 剑交替，夜兰每轮三枚，托马每轮一击。夜兰自身 E 命中另走独立触发路径。 |
| 空/荧雷、雷神 | 按伤害事件的攻击标签、行为者/在场者、非零条件执行各自回调；雷主寿命终点不包含第 720 帧，雷神 Eye 到期帧对来源事件顺序不明的情况阻塞。 |
| 宵宫、阿贝多 | 标记/领域范围与伤害事件冷却分别检查；不假定每到一个周期必然触发。状态冷却包含到期帧，构造物寿命终点不包含到期帧。宵宫完整分支明确排除旧 A1 叠层。 |
| 迪希雅 | 新领域与重新放置为不同动作。重新放置初击必须提供原领域完整进攻快照、已剩余寿命及冷却；新领域在第 41 帧重新取样。不得把历史初击偷换成当前面板。 |
| 菲谢尔 | 只支持明确无额外 A4、无魔导的新 E 与不中途切换的完整 Q。按实体排程生成奥兹伤害并包含离场后已经发射的尾弹；飞行帧数必须显式输入。Q 后奥兹另用 E 天赋等级。 |

核心遵循固定源码各自的寿命助手，不统一套用开区间或闭区间。普通 `StatusIsActive` 在到期帧仍成立；雷主的 `core.Status.Duration` 与阿贝多构造物规则不同。完整观察期限还覆盖已排队的伤害尾段。例如显式填写奥兹飞行 10 帧时，完整 Q 的最后奥兹伤害为第 723 帧，不能仅观察到实体到期第 713 帧。

## 逐击公式、快照与面板记账

行秋 A4、雷神 A4、阿贝多 A1、夜兰 A4 均用共享 AST 计算“实际被动份额 − 本击输入已经包含的份额”，未知已含份额阻塞。夜兰初击生命基数取施放第 0 帧，其他进攻属性取第 76 帧；可填写明确的第 0 帧生命，或声明这两时点面板稳定。托马追击生命附加项按 A4 处理，但固定源码错误使用突破 1 门；突破 1–3 在独立来源核准前仍阻塞，只开放明确突破 0 或 4–6。

每个生成命中有可读的触发、实际命中、快照和目标记录，同时进入计算 trace。重复准备保留相同事件的逐击输入；显式快照修改优先于此前已保存副本。改变已转换日程不能复用旧时点的增伤、附加基础值、反应或抗性，会持续阻塞直至重新应用构筑或导入真实面板。完整 JSON 保存事件、输入、快照、逐击被动份额及转换身份记录。

最终面板转换只结算通用装备/手工增伤，角色来源 `damageBonusFormula` 仍逐击执行。因此不能把尚未结算的被动提前标为已含，否则会重复扣除。本批合并检查实际发现并修复了这处转换边界；转换前后伤害一致。

一次合并来源检查（修复所发现问题后定向重跑）涵盖十二个协议的逐击展开、来源追踪、重复准备、JSON 往返、最终面板数值一致、独立单击、冷却边界、实体尾段和未知资格。`packages/sim-core/src/coordinated-cast.test.ts` 最终两项检查通过，耗时 2.64s，命令耗时 3.086s；见[最终日志](../validation/coordinated-casts-identity-retry.log)。未运行逐角色测试套件或性能测试。

早期类型检查曾只报告并行武器任务文件中一处 `LegalTimelineCommand.atFrame` 类型问题，原始失败仍保存在[检查记录](../validation/coordinated-casts-batch-notes.md)。修复后的统一类型检查与生产构建均 exit 0，命令耗时 2.833s，425 个模块，Vite 418ms；见[最终构建日志](../validation/continuation-modules-build.final.log)。

正常网页的一条[自动流程](../validation/coordinated-casts-browser.final.log)通过，测试耗时 1.0s，命令耗时 1.703s：实际编辑行秋普攻状态 100–221 帧，生成 120／180／240 帧的 2／3／2 剑共 7 击，并核对最终面板转换、完整 JSON 恢复和独立末击。原先提出的更广手工计划没有全部执行，不能将草稿跨动作保留等计划步骤计为页面验收通过。

分类覆盖生成器 `.20` 实测：120 个角色身份、1111 条分类命中模板、588 个条件完整动作、87 个部分动作、18 条阻塞映射。相较本批之前为命中模板 +5、条件完整动作 +12、部分动作 −18。1111 不是日程展开后的实际命中总数；上述数字是来源条件分类，完整动作运行时仍受必填日程和资格约束，不等于全部角色、自动团队、附着/ICD、命座或游戏机制已完成。
