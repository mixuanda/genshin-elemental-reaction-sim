# 轮转 DSL 与执行边界

DSL 由 `packages/sim-core/src/rotation-dsl.ts` 解析，输出既有 `LegalTimelineCommand`。它不导入天赋系数，不猜测技能种类或帧数；预览和模拟共用既有 `legal-frame-v1` 执行器。模拟时间为整数 60 帧参考刻度，不据此声明所有客户端帧率机制等价。

```text
# 必须已经定义当前角色的唯一 skill / burst 行动
E
wait 12f
Q
action explicit-ability-id
swap character-id
repeat 2 { action explicit-normal-id dash 12f }
at 120f action explicit-ability-id for character-id
at 200f pickup cryo
```

`E`、`Q`、`C` 只解析为当前前台角色唯一的 `skill`、`burst`、`charge` 定义。有多个同类行动时必须使用 `action <id>` 或显式角色别名。`E.hold` 只有在别名映射到已有正确 hold 行动时才合法。

`N5` 是明确普攻链的前五次输入，要求调用者提供 `normalChains[角色ID]` 的有序行动 ID；它不是第五次伤害事件。解析器不根据数组位置、名称或单一 normal 定义编造链。少于六段的链会拒绝 `N6`。`normal[5].hit[1]` 是命中选择语义，不能作为执行指令。

`D` / `J` / `W` 需要显式 `movementFrames`；也可直接写 `dash 12f` / `jump 12f` / `walk 12f`。帧数表示已配置的占用，实际体力费用使用来源声明及共享体力账本；不会由占用推断位移、高度或无敌帧。`plunge <id>`／`P` 只执行已声明的下落能力，并要求、消耗此前实际授予且仍有效的 `airborne` 状态；普通 jump 不凭空授予该状态。

`at 120f` 为紧接的非等待指令指定请求帧；实际执行仍受冷却、占用与严格/等待策略约束。放在 `N5` 前时只指定组合首个输入的请求帧，后续四次输入按动作占用衔接，不把五次攻击挤到同一帧。不能给 `wait` 或整个 `repeat` 标记一个含义不明的 `at`。

`action`、`plunge`、`dash`、`jump`、`walk` 可带 `for <角色ID>` 明确指令所属角色；它不会隐式切人。编辑器生成的规范 DSL 保留这个字段，因而在重排指令后也不会悄悄把移动改成另一个人的动作。请求了后台角色行动时，时间线编译器按实际前台状态报告不合法。`pickup any` 或 `pickup pyro/hydro/cryo/electro` 生成真正的结晶拾取请求，成功与否取决于模拟中的碎片，而不是仅凭 DSL 文本生成护盾。

可视编辑器支持加入行动、切人、等待、闪避/跳跃/行走、已声明下落和结晶拾取，逐指令编辑请求帧、上移/下移与删除。运行前的「预览合法时间线」使用同一个核心编译器，并应用所选输入延迟配置；显示请求帧、开始帧、取消时点、动画结束和强制等待。它是动作结构预览，能量可行性、反应与拾取成功仍须实际模拟。

来源动作入口可显式载入固定安柏 N1–N5 条件情景。只有精确匹配的能力和面板才提供 `N5` 简写；载入时清除先前输入延迟和基准标签。来源链不允许把两次 `N1` 当成前两次普攻，也不开放未经该契约定义的切人、移动或拾取。公共 `simulate` 同样校验来源契约，因此不能用 JSON／Worker 绕过 UI。固定源的动画末帧与下一帧进入自然闲置分别说明。来源范围与五击外部对照见 [动作库](source-action-library.md)。

`repeat 2 { ... }` 可嵌套，最多 8 层，每层最多 1000 次，展开最多 10000 个指令。等待使用非负整数帧（`12f`），不接受模糊小数帧。支持 `#` 行注释和分号分隔。

`strict` 模式直接报告重叠、冷却等合法性错误。自动等待采用既有内部值 `wait`，只对执行器已有等待规则生效；编译输出列明实际开始帧与等待帧。运行时能量不足仍按既有引擎记录失败施放，不能把预览时间表当成能量可行性证明。

新解析测试覆盖重复、合法链、N6 拒绝、明确位移帧、歧义技能、非法命中选择器、语法/展开上限及严格/等待冷却结果。完整角色的来源动作时序仍未全部收录。后续已经接入共享体力与真实输入延迟方案；本批新增 walk／plunge 生产路径尚待整批验证，不能由早期7项记录推定通过。详见[本批执行边界](validation/rotation-walk-plunge.md)。
