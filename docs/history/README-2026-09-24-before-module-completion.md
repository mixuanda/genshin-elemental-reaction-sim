# 提瓦特伤害实验室

独立单技能计算器与团队 DPS 模拟器。界面以中文为主，共享纯 TypeScript 公式、结构化计算轨迹和固定来源的规则。单击或一次施放无需创建队伍；当前数据覆盖仍不完整，详见更新状态与限制。

## 运行

需要 Node.js 24（数据工具使用其原生 TypeScript 支持）与 npm。

```sh
npm ci
npm run dev
```

- `/calculator`：独立计算器、逐步代入、公开展示柜、计算配置及轨迹导出。
- `/examples`：可修改的教学例题；合成数字与完整游戏实例分开。
- `/team`、`/rotation`：当前情景的面板、可执行行动及 DSL 编辑。
- `/results`：Worker 模拟、逐击轨迹、能量和实际行动；命中可在计算器中完整还原。
- `/compare`：保存当前页面的结果并检查假设差异。
- `/data`、`/updates`：来源目录、版本渠道和实际覆盖。
- `/` 保留原模拟界面兼容入口。

轮转页的来源示例包括久岐忍 E／Q：可修改请求帧、合法切换、初始生命与能量，观察实际治疗如何决定 Q 的七击／十二击分支。结果时间轴提供起手条件、治疗与扣能的实际记录；逐段伤害可直接打开独立计算器，保留同一次起手判断及全部公式。来源示例有明确的固定配装范围，仍为 provisional，详见 [久岐忍 E／Q 契约](docs/cross-validation/action-library/kuki-burst-source-contract.md)。

独立计算器现新增柯莱E无／两次／四次新叶、夏洛蒂E点按／长按的完整条件动作，保留逐段选择、独立历史快照和明确被动条件。夏洛蒂已扩到C0–5，逐击C2层数与面板已含份额独立输入，长按末次标记不默认仍带增益，C6仍阻塞。多莉E、白术E、妮露Q、甘雨E的完整C0动作继续保留。白术需要明确E起手生命条件，三击共用同一快照；新增六把武器的普通条款沿用来源配装控件与逐步公式，来源冲突和未实现部分仍可查阅。

独立计算器另提供钺矛、苍纹角杯和冷寂迸音的一次追击，面板与精炼可编辑。团队页可声明对应武器效果，实际普通命中触发后保存快照，在下一帧独立结算；事件账本与计算器恢复保留父子来源。已在确定性闭合域捕获完整追击周期状态；角色卡肉与反应伤害回调仍有缺口，见 [本轮实测](docs/qa-report.md)。

独立追击此前接入吃虎鱼刀、试作古华、雪葬的星银、龙脊长枪和忍冬之果。三把霜葬武器由明确的原触发目标冰／冻结条件选倍率，未知保留阻塞；正常面板、精炼和条件可编辑，JSON由共享核心重新推导。团队新五把使用真实延迟回调与独立随机流，整次范围追击共用回调时选定的倍率；完整随机周期状态仍未建立。见[本轮实测](docs/qa-report.md)。

笛剑、以理服人、流月针和竭泽的一次独立追击也已接入，共12把／60精炼位置、75个条件分支。单击计算不要求音符、战技窗口、拾球记录或队伍；生命周期条件由团队真实事件执行；四状态与待追击快照已进入限定普通Aura域的完整周期检查点，32秒闭环实测1880伤／58.75DPS。笛剑固定 Optimizer 的 R1–R4 倍率与另外两份来源不一致，界面明确保留冲突；未因此提升数据验证等级。见[当前QA](docs/qa-report.md)。

讨龙增益也可在独立计算器逐击恢复：实际生效与面板已含精炼分别输入，按接收者基础攻击补差，不需要队伍。团队页的讨龙由实际切人领取，已有增益不刷新，真实冷却与历史快照进入正常账本和完整确定性检查点；角色卡肉与尚未接入的特殊宿主仍有边界，见[来源及实际对照](docs/cross-validation/ttds-external.md)。

祭礼四类武器的 R1–5 已接入合法轮转：真实命中抽样成功后只恢复一层 E 充能，剩余队列重新计时，后续战技、产球与能量随实际结果执行。正常队伍和轮转页可编辑持有者、精炼与冷却启动延迟，并查看真实账本；固定请求的随机批次不会按每个种子重新排程。无角色卡肉和完整随机检查点的边界见 [祭礼来源对照](docs/cross-validation/sacrificial-external.md)。

执行延迟方案 1.1.0 使用实际能量与暴击选项生成参考请求表：失败的爆发输入不会制造动画取消延迟。预览和运行均在可取消的 Worker 中执行，整批使用同一参考种子的请求表；旧 1.0.0 记录保留原规则。确定性周期检查点已包含实体代次、在途快照和起手锁定条件，原生aura-v9／target-phase-v2在关闭目标时钟的有限普通附着域已建立周期1；其余反应生命周期与随机状态仍明确阻塞完整稳态认证，见 [本轮实测](docs/qa-report.md)。

```sh
npm run data:check
npm run typecheck
npm run test:unit
npm run test:performance
npm run build
npm run test:e2e
```

根据改动选择必要检查，不需要每次小改动反复执行整套测试。没有单独的 lint 脚本。生产构建不等于游戏机制已正确验证。

`npm run check:release` 将数据检查、完整单元测试、一次生产构建及计算器／整合浏览器契约串成失败即停止的发布校验。`.github/workflows/calculator-gate.yml` 在 PR 或手动触发时运行同一命令；浏览器使用已构建产物，不再次构建。其目的包括防止独立计算器被团队流程取代、解释／例题失联和命中恢复回归。本地尚未发布这些修改，远端工作流及分支必需状态规则未配置或验证，不能宣称已在远端阻止合并。工作流写法依据 [setup-node 官方说明](https://github.com/actions/setup-node) 与 [Playwright CI 文档](https://playwright.dev/docs/ci-intro)。

## 数据更新

`data:discover` 探测可访问来源；`data:sync` 保存已审阅的源输入；`data:normalize` 生成目录与补充表；`data:classify` 记录字段就绪维度；`data:validate` 校验依赖与清单；`data:diff` 比较不可变快照。`data:activate` 可将已发布的暂定快照切换为实际目录；`data:promote` 需要满足已验证门槛。激活、晋升及 `data:rollback` 会同步切换运行时的目录、索引、补充表和身份。`data:preview` 只选择隔离预览工作区。具体参数见 [更新流程](docs/update-status.md)。

读取百分数不代表确认缩放属性。尚未核验的角色、装备被动、命座或特殊反应状态不会自动成为已验证数据。目录元数据、可计算的条件公式和完整自动模拟支持是不同层次。

## 结构

- `packages/sim-core`：共享表达式执行、计算器、例题、事件模拟、完整命中捕获、DSL 与能量分析。
- `packages/reaction-formulas`：固定来源的普通反应以及独立的条件化月曜／星辉数值公式。
- `packages/schemas`：现有模拟配置、结果及迁移约定。
- `packages/mechanics`：明确分类的部分角色动作；全角色机制未完成。
- `packages/game-data`：身份、天赋、装备元数据，精确曲线，快照与更新清单。
- `apps/web`：中文界面、Worker 和公开 Enka 代理。

历史 wire/golden 保留为旧行为复现证据；新的正确性测试独立验证算术与来源修正。旧模拟器说明全文保存在 [基线历史文档](docs/history/README-84ff5cd.md)，其「当前」仅指该历史提交。
