## 计算速度不是回放速度

同一真实班尼特／凯亚／香菱／砂糖、合法圣遗物、满能开局、120 秒连续轴，在云端 Chromium 的 4 个固定 seed 测量：

|---|---|
| 单次 120 秒计算，加载 WASM 后 | 11.9575 / 10.2791 / 10.6539 / 10.6648 秒；平均约 **10.89 秒** |
| 四次串行总墙钟时间 | 44.2931 秒，含批次启动及摘要开销 |
| 四次双线程总墙钟时间 | **26.2917 秒**；优化前同组 37.6533 秒 |
| 原生计算／解释对照 | 优化前后四个 trial 的伤害、暴击、动作、能量、随机性事件 SHA 全部一致 |
| 1x / 2x / 4x / 8x / 16x | 只推进已计算结果的显示游标；120 秒结果的完整回放分别约 120 / 60 / 30 / 15 / 7.5 秒（不含暂停） |
| 直接查看结果 | 计算完成即可查看，不等待回放；**不是省略计算，也不是零等待** |

速度只对应这台云机器、该固定队伍与四个种子，不外推所有角色、多目标、Windows、首次远程下载 WASM 的耗时。并行时单个 trial 可能更慢，但总吞吐提高。

本次没有省略或延迟解释图，亦未关闭机制/验证。实际优化是：固定 locale/精度的数字格式器复用（最多 16 个）、解释节点 ID 的 Set 查找、只对模块自己已经递归冻结的解释节点避免重复冻结。任意外部浅冻结对象不能获得此信任。1002 条完整计算及解释哈希仍为 `3030a1b128d8d5672af608b7f6125ce27decc9e47e6f0c841ddc84b6952bffdf`。公式基准约 5.77 秒；上一阶段同轨迹约 9.36 秒，本阶段带 CPU profiler 的优化前测量为 11.07 秒，不能把 profiler 开销当作纯优化收益。
