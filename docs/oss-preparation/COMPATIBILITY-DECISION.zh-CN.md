# 需要维护者决定的一项兼容政策

**建议批准：新执行语义使用新的版本身份；旧文件仍可查看和导出，但不能证明语义等价时拒绝用新引擎直接重算。只有逐域证明无损的转换才自动迁移，其余保留原件并生成明确标为新计算的副本。**

这项选择决定的是“旧结果是否允许悄悄改变”，不是让维护者决定角色机制。建议接受兼容边界，而不承诺所有旧文件都能无损重算。若选择继续沿用1.53身份，则必须先补充逐字段可区分策略；当前证据不足以安全采用该方案。

## 真实存量证据

本地packages/test-vectors/fixtures有43份JSON含可识别schemaVersion节点，共23种版本身份，覆盖1.30–1.42及1.44–1.53；本次扫描未发现1.43节点。这里计的是仓库保存的测试/历史数据，不声称已盘点任何用户电脑中的文件。完整文件、JSON路径、schemaVersion和engineVersion列于交付stored-format-inventory.json。

最相关的存量是electro-charged-propagation-1.41.golden.json、冻结1.52和callback-bus的1.53 Golden。当前types.ts仍将CURRENT指向1.53.0/1.53.0-callback-bus。当前新结果也沿用该身份，但legal-frame-v1执行时强制写入canonical-v1平坦属性语义；已有1.53→1.52投影保留该选项后被严格旧wire拒绝。旧Golden不能通过统一改身份、删除语义标记或重新录制来解决。

## 为什么不能只删新字段

simulator.ts对canonical-v1把atkFlat/hpFlat/defFlat映射为实际flatAtk/flatHp/flatDef；旧分支写入原名称。formulas.ts的ATK读取baseAtk×(1+atkPct)+flatAtk。因此这是执行语义变化，而不只是附加说明。丢掉标记后既不能解释当前数值，也不能保证旧结果重算一致。相同的“1.53”字符串不是足够的等价证明。

## 对用户文件的明确行为（建议，尚未实施）

| 文件状态 | 建议行为 |
|---|---|
| 历史身份与原校验一致，结果可读取 | 原样查看/导出，保留来源身份和原结果；不自动改成CURRENT |
| 新身份且契约完整 | 允许相应新引擎计算，保存新身份与语义标记 |
| 可证明无损迁移（明确白名单领域） | 生成新副本，保留原件、迁移来源及校验结果，验证数值/来源链等价 |
| 缺字段、身份混用、涉及不同flat-stat或未证明事件顺序 | 拒绝“按原结果重算”；允许用户明确建立新计算副本，但不得冒称旧结果的无损重放 |

默认不删除文件、不覆盖历史结果，也不承诺搭载所有旧版引擎。需要的维护者选择只有：是否接受“保留旧结果可读、对不能证明无损的旧输入拒绝静默重算”的策略。批准后才能统一实现版本身份与迁移入口；本轮仍保持历史格式/Golden/EC原校验。
