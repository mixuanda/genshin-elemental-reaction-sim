# 随机起步范围审计（2026-09-28）

原始要求把确定性稳态与随机起步分开处理。第20节要求确定性运行按相关相位状态收敛，随机运行采用适当的预热／分布政策并披露残余起步敏感度；它明确不承诺随机状态精确重复，没有要求证明每个随机过程的完整分布达到数学稳态。第21节要求提供带种子随机模式，区分样本分位数与均值置信区间，并记录迭代数、种子、RNG版本、执行配置及暴击触发效果处理（`/Users/evan/Downloads/GENSHIN_DPS_MASTER_PROMPT_EN.md:439-465`）。

现有实现已覆盖这项有限诊断政策。`packages/sim-core/src/stochastic-startup.ts:207-228` 校验样本数、整数帧窗口及最长运行时间，并生成版本化种子；`:233-271` 对每个种子跑zero/full连续轨迹，比较W与2W窗口并作配对差；`:273-303` 保存配置、运行清单、随机政策和限制，明确有限窗口不证明完整分布收敛。原生来源起步分析在 `apps/web/src/source-host-startup-analysis.ts:62-74,112-197` 校验uint64种子、固定源码/WASM/脚本/动作模式，并按种子对比零能、满能及可选自定义初能窗口；允许不同动作分叉后抽样位置不同。公开的相位分析 `packages/sim-core/src/source-host-phase-analysis.ts:4-27,117-139` 则只把确定性、同一重复输入位置、完整状态覆盖用于确定性相位判定。

因此，产品缺口记录不应把“实现所有随机稳态证明”列作必需代码门槛。当前仍需扩展确定性原生来源域的真实状态覆盖：尚未审查的角色私有时钟、装备事件、活动反应/实体任务及护盾/耐力闭包可能使周期判断无法成立；经典示例中可见的 `skill_charge` 递增也应继续保持“未建立”。已观察到的星辉来源示例仅是固定来源状态下的 provisional 证据，不能外推为全角色覆盖或游戏验证。

RNG 种子别名与原生回执现已按有限范围实现并验证：来源批次／起步诊断拒绝映射到同一实际随机流的别名种子；回执记录请求seed、signedSeed、effectiveSeed、算法、Go版本及采样策略。浏览器来源运行中，classic 的 `1` 与 `2147483648` 产生相同实际伤害与能量流并被识别为别名；stellar 的最大uint64种子则把实际回执元数据带入独立计算器。证据见[来源RNG种子策略与回执审计](validation/source-host-rng-policy-20260928.md)及[浏览器验证结果](validation/source-rng-policy-browser-20260928.result.json)。这些结果限于报告中的固定来源WASM、输入和检验；不同effectiveSeed不等于统计独立性证明，也不认证任意随机分布稳态。
