分支 `cloud/login-adapter-20261022`，基于 `a3534aa`。**真实登录及真实账号读取仍未实现。** 本批补齐无凭据宿主契约、状态管理与模拟测试，没有接入页面或修改主整合分支。

## 已有实现与本批增量

原 `createAuthorizedFixtureAdapter` 已能读取合成 JSON 并断开，明确返回 `authorized-fixture`；本批保留它及已有测试，复用 `AuthorizedEquipmentRequest`、`importPlayerJson` 和现有缺项/来源约束。

新增 `packages/player-import/src/authorized-host.ts` 的 `createOwnedEquipmentController`。默认无宿主时返回 `host-unavailable`；当前只接受 `FixtureEquipmentHost.mode = fixture-only`。即使调用者传入声称为 live 的宿主，也不会执行。所有成功结果和预览仍明确为合成数据，`realLogin` 始终为 false。

实现的流程为：主动确认只读范围 → 读取宿主绑定的 UID/区服列表 → 明确选择一项 → 读取当前配装 → 验证范围与归属 → 合成预览。单个绑定角色也不自动选中。`prepareRead` 只检查模拟宿主状态，不执行登录。

- 米游社绑定必须标明 `cn`，HoYoLAB 绑定必须标明 `overseas`；UID、区服、提供方、游戏均由绑定列表明确给出，不从 UID 前缀猜测。
- 每次读取都检查提供方、所选 UID/区服、固定只读目的与主动确认；开始和完成时均检查有效期。过期、无权限或需验证时停止，不自动获取新访问或后台重试。
- 返回的完整已拥有角色 ID 列表必须与规范化配装中的角色集合逐项一致，重复、缺项、额外角色、仅部分列表都不能标为全角色导入。角色覆盖完整与词条完整、计算可执行分别判断。
- 数据归属不一致、凭据形状输入、异常或过大 JSON 不替换旧预览；失败后的旧预览明确不是当前成功结果。错误不回显宿主异常或原始响应。
- 取消和断开会阻断迟到响应。断开先清空本页角色/数据，再等待宿主释放；宿主释放失败返回 `disconnect-unconfirmed`，不假称提供方已撤销授权。

本模块只保留本页内存状态；不会读取浏览器会话、建立网络连接或写入存储。`index.ts` 只新增导出，当前页面未使用这个契约。

## 真实账号下一步需要什么

真实账号读取**尚未发起，状态为未执行**；没有权限拒绝，也没有悬而未决的真实登录请求。代码与模拟测试完成不代表账号接入已完成。下一步需同时解决以下事项：

1. 明确选择米游社国服或 HoYoLAB 海外，并由用户选择其已绑定的原神 UID/区服；只读范围为全部已拥有角色的当前装备，不包含背包未装备物品、历史配装或持续监控。
2. 先完成并审查提供方允许的真实宿主接入：用户在官方界面主动登录及完成验证；GIDPS/云端不获取或保存 Cookie、令牌、密码或会话句柄。还需验证在此约束下宿主是否能合法取得所需数据，不能假定普通跨域网页可借用官方登录状态。当前分支没有这样的生产宿主。
3. 对宿主的读取次数、仅当次使用、退出与断开的实际行为给出可审查方案，再由用户明确授权一次最小真实只读验证。无需向对话发送 Cookie；不以凭据导出作为替代方案。
4. 获授权后，验证所选角色归属、完整角色枚举及各角色装备详情，核对字段单位和天赋记账；真实缺项保持未知。成功后再将该生产适配器接到 UI，并分别验收角色覆盖和导入至计算闭环。

如果提供方当前没有符合上述限制的读取机制，真实读取继续保持不可用；用户同意打开登录页本身不补足技术实现或第三方读取权限。
