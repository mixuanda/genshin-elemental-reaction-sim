# 独立单技能计算器：实现与边界

本文件记录本次实现的接口和计算边界。原始项目基线见 [current-project-audit.md](current-project-audit.md)；命令、退出码和测试实测以 [qa-report.md](qa-report.md) 为准。本文件中的接口描述不代替测试记录，也不证明角色数据已经完成游戏机制核验。

## 独立入口与计算范围

主导航保留 `/calculator` 单技能计算器和 `/examples` 可编辑例题。直接进入这两个页面不要求组建队伍、编辑轮转或先运行模拟。计算器界面在 `apps/web/src/calculator-ui.ts`，路由接入在 `apps/web/src/app.ts`；计算实现位于 `packages/sim-core`，不依赖 DOM 或网络。

计算文档的 `scope` 明确区分 `single-hit` 与 `one-cast`：前者必须且只能选择一个命中，后者逐个计算勾选命中及其实际施放贡献再求和；条件触发命中另按其明确发生条件处理，不能无条件加算。结果列出纳入和排除的命中 ID，并分别报告非暴击、允许暴击部分暴击时、解析期望伤害。没有时间分母，因此这两个范围不显示 DPS。自定义行动序列和队伍轮转属于模拟工作流，不由单次命中的伤害数值推断。

核心每次仍完整计算所选命中、合计及结构化轨迹。页面对多击的折叠卡片先显示本击结果与状态，在用户展开时才把该次已保存的完整轨迹挂载到 DOM，不重新执行伤害公式；单击结果默认展开并显示全部步骤。已展开的卡片在输入更新后继续显示对应新轨迹，完整审计 JSON 与导出报告始终包含全部命中记录，不依赖用户是否展开。这是呈现方式的优化，不减少公式、变量定义、数值代入、中间结果或解释的可访问范围。

一次施放的当前实现是文档列出的自身伤害实例集合。它不自动把技能持续时间内的队友伤害、召唤物、场地反应或额外命座事件计入。只有具备对应定义的实例才能进入集合；缺少持续实体定义时，不能把已列部分称为该角色在所有条件下的完整技能伤害。

真实角色文档的 `gameContext` 保存角色和可用时的形态 ID、具体 `abilityId` / `skillId`、有效天赋等级、命座与归属政策。`scopeCoverage` 将单次命中、所选组成和完整一次施放分别记为 `single-hit`、`selected-components`、`complete-cast`。界面显示精确计算身份；仅有已定义部分时，范围明确标为“所选已定义分段合计（部分技能）”。输入 JSON 保留该身份，不凭文档标题或一个角色面板猜测动作。

## 输入、单位与角色数据

界面提供正式目录角色、已有分类技能/形态、有效天赋等级、命中选择、角色和敌人等级、目标抗性、防御调整、防御无视、面板、各段加算伤害与加成，以及条件化增幅反应。有效天赋等级读取该等级的精确来源值，缺值时阻塞。来源动作默认条件与导入角色的实际命座分别保存；命座、突破和被动支持按所选命中依赖判断，不因非 C0 一律拒绝，也不自动补齐未实现机制。只有经来源审阅的分类映射成为伤害命中，目录中的冷却、持续时间和未经分类的参数不会自动成为倍率选项。

正常角色条件区提供 C0–C6 命座选择器，由 `applyCharacterConstellationScope()` 重建已映射命中的来源分支，并保留明确输入的状态。切换命座不会自动改写最终面板或有效天赋等级，也不把未知机制标成已支持；直接改 JSON 后留下超出命座范围的公式会被核心阻塞。

输入框中的百分比采用小数：`0.80 = 80%`、`0.70 = 70%`、`1.20 = 120%`，天赋倍率 `2.00 = 200%`。固定攻击力与独立基础伤害加算是不同字段。目标 `defenseAdjustment` 沿用本项目有符号约定，负数表示减防；`defenseIgnore` 为 `0–1`。计算核心负责有限数值、范围、命中 ID 和元素/反应兼容性验证。空值或非法数值会撤下旧结果并显示阻塞，不保留看似仍有效的旧合计。

面板模式如下：

| 模式 | 当前执行方式 | 解释边界 |
| --- | --- | --- |
| `equipment-derived` | 从固定来源解析角色/武器等级、突破、副属性、合法圣遗物主副词条及明确启用的已映射装备条款，再推导面板；合成例题也可显式提供基础值 | 来源配装为暂定条件计算；未映射被动、动态触发、命座与套装条款不视为完成 |
| `manual-final` | 以用户给定最终 ATK/HP/DEF/EM/暴击面板为入口 | 不猜测此前分解，不重复加入装备或永久增益 |
| `imported-final` | 以公开展示柜最终面板为入口，保留来源 | 展示柜装备和天赋信息不等同对应机制已核验；最终面板不重复加装备 |

公开 Enka 导入复用项目的公开展示柜解析和 ID 映射。未解析或缺少可执行命中定义的角色保留导入面板并说明阻塞原因，不借用其他角色或教学例题天赋。`applyImportedCalculatorPanel()` 保留实际命座、突破和最终面板，并逐个匹配 `resolvedSkills.abilityId` 与该技能的 `effectiveLevel`；普攻、战技、爆发不会共用第一个读取到的等级，有效等级已包含导入提供的额外等级，不再因命座二次加 3。缺少技能映射或相关等级缺值会阻塞；非 C0 则由每个命中的公式依赖决定是否可算，例如只支持 C0/C1 的公式仍阻塞 C2。

突破只读取 `propMap[1002].val`；缺失、无效或只有 `ival` 时保持未知，不能从等级或适配器默认条件补成突破 6。未知突破只阻塞需要该字段的命中。Enka 响应缺少 `talentIdList` 按其[协议说明](https://github.com/EnkaNetwork/API-docs/blob/master/docs/gi/api.md)表示 C0；这项协议约定不能推广为任意内部对象缺少命座都默认 C0。计算文档可导出/导入 JSON；完整报告包含本次 trace、依赖与数据身份。

`equipment-controls.ts` 在选择正式目录角色后按需加载装备基础编辑器，纯解析由 `packages/game-data/src/equipment-build.ts` 完成。可选择角色等级/突破、相同武器类型的武器、武器等级/突破及来源记录中合法的精炼档位；缺少来源数据、突破等级不匹配或非法精炼会阻塞，不能补造档位。没有副属性或精炼被动的武器按其真实目录结构处理。

来源配装支持圣遗物逐件编辑：部位、套装、稀有度、等级、主词条、初始副词条数和每次强化档位。`artifact-build.ts` 检查套装实际部位/稀有度、部位允许的主词条、等级上限、主副词条冲突、强化次数与合法档位，并从固定主副词条表精确查值；不从最终总数反推一段虚构强化历史。

武器效果与套装效果各有显式启用开关，仅执行 `equipment-build.ts` 分派到的已有来源映射条款。常驻属性、已映射攻击标签增伤及生命比例/目标附着等条件按当前输入解析；命中加成还需同时满足元素、攻击标签和武器类型。比如限定普攻的加成不会施加到战技。缺少条件、来源文本变化、未映射条款及尚未执行的持续时间/冷却/额外追击都会报错或列入缺口，不将部分条款宣称为整件装备已完成。

新增 `equipment.additiveBaseBonuses[]` 与 `criticalBonuses[]` 使用共享 AST、具名输入、单位、来源和适用过滤。前者加入普通命中的基数附加，再进入该命中适用的防御、抗性、暴击、增幅等环节；不会增加角色 ATK，也不会重复角色附加公式或激化值。后者只调整符合攻击标签等条件的本段 CR/CD，合计后由共享公式限制暴击概率；不可暴击或非普通伤害明确不适用。14 把武器的 70 个合法精炼行有已审映射：赤角/裁叶/辰砂/月华/猎径提供基数附加，腐殖/灰河/狼牙/厄水/黑蚀/硕果钩/白雨/溢彩/渔获提供限定标签暴击属性。狼牙 E/Q 层数和溢彩两窗口分别保存，不合成一个全局暴击开关。

这些条款的 `inputPolicy` 区分来源读取策略：`final-panel` 读取本段实际 HP/DEF/EM 等，包含该命中明确加入的来源精通；历史快照必须作为独立输入保存，不能用技能施放快照冒充命中时属性。已生效窗口、剩余次数、前后台和护盾等条件由使用者明确恢复，解析器不自动推演触发首击、逐次消费、窗口过期或额外物理追击。固定来源冲突和未实现条款保持可见，详见 [装备逐击实施](weapon-hit-effects-implementation.md)。

新逐击条款的未知条件以 `pendingHitEffects` 保留规则、原因、来源、类型和适用元素/标签/武器；`getCalculatorHitPendingEquipmentEffects()` 按本段判定。比如狼牙 E 层数已知而 Q 层数未知时，可计算选中的 E，Q 仍阻塞；不能用未知当 0。切换为最终面板可保留未选中命中的 `pendingEquipmentEffects`，之后选择该命中仍会阻塞，JSON 也保留同一语义。此门仅覆盖新增逐击协议；旧的常驻属性或普通增伤解析缺少条件时，仍可能在配装阶段整体拒绝，例如厄水既有护盾增伤条件未知。来源和核心的专项记录分别列在实施文档，不据此声称全部装备条件已改为逐击处理。

本轮六把条件武器沿用同一配装核心及控件，不要求组队。各自R1–R5按固定目录和Optimizer的已审向量解析，普通数值条款如下；完整五档、来源归档及执行证据见 [六武器专项](validation/weapon-conditioned-expansion.md)。

| 武器 | 条件普通条款 | 必须恢复的状态 |
| --- | --- | --- |
| 弥坚骨 | 本击最终ATK×精炼系数加入普攻基础伤害，不增加ATK面板 | 合法7秒窗口、命中前剩余0–18次、前后台 |
| 聊聊棒 | 攻击百分比及七元素伤害加成分别执行 | 火附着攻击窗口与水冰雷草附着增伤窗口各自有效状态 |
| 试作星镰 | 每层精炼系数×有效层数加入普攻/重击增伤 | 12秒内有效层数0–2；不是攻击百分比 |
| 群王局戏 | 同一窗口的攻击百分比与固定精通 | 实际有效的棋中法度窗口，含已获得的延长 |
| 寸心余响 | 明确反应窗口中的固定精通 | 12秒精通窗口是否有效 |
| 金律铸影 | 主乐章与复调各自的攻击或精通，同类可相加 | 两状态独立选择无/攻击/精通/星烁；星烁不折为普通增伤 |

弥坚骨未知命中条件只阻塞普攻，试作星镰未知层数只阻塞普攻/重击，聊聊棒未知元素窗口按元素过滤；未知攻击或精通属性仍需先补齐面板条件。明确关闭或次数耗尽可取零，未知不当作false。自动触发、时间推进、剩余次数消费及星烁伤害仍未执行。弥坚骨的固定gcsim系数冲突、试作星镰的ATKP与DMG%属性区冲突，以及聊聊棒与金律的时长冲突继续展示，不推定争议边界；试作星镰的 `AttackTagExtra` 即重击，不再误称标签冲突。来源仍为provisional。10把无被动武器原已按真实基础属性和合法R1配装，不是新增十条被动实现。

元素集合控件区分“未知／未提供”和“已确认当前状态”：前者省略相应条件，核心按缺失处理；后者即使不勾选任何元素也保存明确空集合 `[]`，表示当前没有有效元素。烬城基础 12%/15 秒与夜魂额外 28%/20 秒使用两套独立集合，允许基础窗口已结束、仅额外 28% 仍有效；不能合为一个永久 40% 开关。磐岩与天赐秘仪的允许元素及集合上限由核心校验，不能用重复元素叠加。黑曜二/四件和匣里日月两个窗口也各自提供明确条件，见 [装备增量实施](equipment-additional-implementation.md)。这些是条件快照，不自动重建触发历史或完成整件装备的动态机制。

使用来源配装前仍需勾选明确停用**尚未实现**的角色/武器被动、命座、套装条款及外部增益。这不再意味着停用全部圣遗物：合法主副词条和明确启用的已映射效果可以执行。应用操作替换原输入为 `equipment-derived`，不会叠加到导入最终面板。它需要所选角色已有可执行命中定义，装备数据不能代替缺失天赋。任务专用武器变体被排除，未映射属性不静默计零。

每项基础属性保留 `derivedStats`、来源引用和来源版本，核心以“来源基础值 × 精确等级曲线 + 突破加值”生成共享 trace，再进入最终属性与伤害计算。`secondaryContributions` 逐项保留基础暴击、突破属性、武器副属性、圣遗物词条和已启用条款来源。`bonusAccounting: core-sourced-v1` 让共享核心逐段判定这些来源中的元素/攻击标签增伤，界面的手动伤害加成只作额外补充，避免复制来源加成两次。

普通面板的百分比/固定属性输入已包含本次来源贡献；核心先汇总来源，再将“输入值 − 来源合计”记作手动调整，随后只合入一次。推导后的基础 ATK/HP/DEF、武器基础 ATK 及角色等级在普通面板区域只读，必须通过装备编辑器更改。来源和发布渠道来自活动目录，计算仍保持 `provisional`，发布不等于数值与机制已经独立验证。切换最终面板时使用核心已解析属性和逐段适用增伤；原始手动/导入面板的前置装备分解仍不可凭空恢复。

`convertCalculatorToFinalPanel()` 还逐段保存 `effectiveCritRate`、`effectiveCritDamage`、固化后的基数及 `finalizedEquipmentEffects[]`。来源记录包含贡献类型/金额、表达式、当时真实输入和引用；最终面板 trace 重现这些历史代入并标记不再应用，JSON 要求金额与表达式/输入一致。`finalizedEquipmentBaseInput` 另存原手动份额。返回原装备、应用替换装备或为新技能重新结算时，`restoreCalculatorHitEquipmentInputs()` 只撤旧装备贡献，保留原手填基数、其后手工修改和角色附加公式；新命中从相应装备重新判定标签，不沿用旧命中的装备份额。核心实际合同验证见 [逐击装备核心记录](validation/equipment-hit-effects-core-20260923.md)，不代表本轮构建或浏览器验收已经完成。

普通与剧变命中均可填写“本段最终抗性覆盖” `effectiveResistance`。留空时，共享核心从目标抗性减去当前命中适用且条件有效的来源装备减抗；普通命中还可执行其 `resistanceReductionFormula` 角色来源减抗。填值时视为已结算的最终抗性，装备和角色来源减抗都不再重复应用。来源配装下的反应加成输入也是手动补充量，核心另行判定来源条款是否适用于该反应。`resolveCalculatorHitReactionBonus()`、`resolveCalculatorHitResistance()` 和 `convertCalculatorToFinalPanel()` 负责逐段结算和转换，页面不复制这套算术。切换为最终面板会保存已结算的反应加成与抗性覆盖；在同一编辑会话切回原来源配装时恢复各动作的原补充量和覆盖，避免重复计入。明确切回来源配装同时解除展示柜面板/天赋绑定，后续技能不会再注入展示柜最终增伤。明确点击应用新配装则重置旧的逐段手动增伤、反应补充量与抗性覆盖，重新从新配装解析。

## 独立恢复其他角色提供的讨龙

独立计算器可显式启用 `incomingThrillingTales`，填写外部提供者身份、说明及精炼，再逐普通命中恢复实际取样时是否生效、该击输入ATK已含的旧精炼份额。无需创建队伍或轮转；接收者自己装备讨龙不会据此获得自身增攻。实际来源R1–R5分别为24%、30%、36%、42%、48%；已含份额的0表示明确未含，缺值仍为未知。每次文档只表示一个实际来源，旧精炼用于撤销面板已含份额，不表示两把讨龙叠加。

共享核心逐击执行 `接收者基础ATK ×（实际有效×来源比例 − 已含旧比例）`，作为外部攻击调整与角色自身ATK公式并存，不覆盖刻晴、诺艾尔或其他角色原有调整。基础ATK为接收者角色与武器白值之和，不含固定或百分比攻击，不能把最终ATK直接乘1.24等比例。实际与已含比例相同则差0，轨迹明确说明且不要求未知白值；比例不同时必须提供真实基础ATK。未知状态只阻塞相关已选命中，未选中的其他段不阻塞独立单击。

当前来源配装可读取接收者基础ATK；具有 `finalSnapshot` 的历史命中必须使用自己独立的基础ATK，不能借当前装备或共同面板白值。公式、实际代入、来源身份和已含记账随JSON保存；共享核心在计算及最终面板转换时重新准备该贡献，不凭页面另算。新装备只重置当前面板命中的已含份额；新展示柜面板只清除共同白值及非历史命中的旧白值/已含份额，保留实际有效条件。既有历史快照没有被新面板替换，其自身基础ATK、已含份额和有效状态保持原输入，不要求无关重填。这个入口恢复已经收到的增益，不执行切人、600帧期限、1200帧持有者冷却、刷新或角色卡肉；团队自动领取使用独立的实际切人模型。

非历史命中只读取当前来源配装白值或共同显式白值，不用历史逐击字段遮蔽共同输入；修改共同白值后立即由核心重算。来源、负差/零差、与角色公式组合、JSON及面板转换的实际证据见 [独立计算器专项](validation/thrilling-tales-calculator.md)，这些条件测试不代替团队时序验证。

团队页另显式声明 `thrillingTalesModel` 的实际持有者与精炼，按普通宿主真实切换决定接收者；合法时间线在已完成的swap动作执行，旧式前台改变另标 `legacy-implicit`。持有者到期等号仍冷却；通过后先写1200帧冷却，再检查接收者共享`ttds`存在，已有则不刷新、不覆盖、不叠加且不退还冷却。领取后换下不会清除已生效增益。该模型使用无角色卡肉的固定来源，不把角色名字或任意选择的接收者当作触发条件。

讨龙属性只在 `[applyFrame, applyFrame+600)` 贡献ATK，但接收者记录到期相等时仍可阻挡再次领取；只有真实完整Stats读取才删除到期记录。已选动作攻击快照、召唤生成快照、真实落地的实时面板命中和追击触发按各自实际取样节点处理；空切人、未命中、治疗/EM/ER等单属性查询及审计读取不伪造Stats事件。动作或召唤在增益有效时保存的旧快照，可以在增益到期后继续用于伤害，不能改用交付时面板。

`thrillingTalesLog` 记录真实前后台、来源、精炼、动作身份、帧/顺序、结果与两类期限；持有者冷却阻塞时，接收者字段为null，表示尚未查询。独立结果校验从实际动作与取样事件重放来源状态，不接受日志自行证明领取；捕获命中返回已包含的真实讨龙份额，通过 `接收者基础ATK×来源系数` 的AST解释，不再加一次。实际时序与有限完整周期见 [运行时专项](validation/thrilling-tales-runtime.md)，共享恢复与四类篡改拒绝见 [结果校验专项](validation/thrilling-tales-result-integrity.md)。一次外部/本地对照恢复六次实际伤害和六次JSON回放均差0，范围仅限 [该样本](cross-validation/ttds-external.md) 的明确输入；外部未观察的持有者等号和R5成功领取不随本地结果升级为外部验证。

## 武器的独立追击

正常 `/calculator` 页面可直接选择钺矛、苍纹角杯、冷寂迸音、吃虎鱼刀、试作古华、雪葬的星银、龙脊长枪、忍冬之果、笛剑、以理服人、流月针、竭泽及R1–R5，打开一次已触发、已命中的独立追击，不要求先选完整队伍或运行轮转。首次载入使用明确标注且可编辑的教学最终面板；改变武器或精炼保留该面板和目标。共享定义共十二把、60个精炼位置；三把霜葬各有高低两档，总计75个条件倍率分支，不是75个精炼档。钺矛基数为触发时ATK×1.6/2/2.4/2.8/3.2，两把HP武器为触发时最大HP×0.4/0.5/0.6/0.7/0.8。HP不是剩余生命，最终面板也不再加入武器基础攻击或副属性。

新增吃虎鱼刀的ATK倍率为2.4/2.8/3.2/3.6/4，试作古华为2.4/3/3.6/4.2/4.8；三把霜葬普通档为0.8/0.95/1.1/1.25/1.4，原触发目标在回调时含冰或冻结则替换为2/2.4/2.8/3.2/3.6。高低档不相加，也不随本次范围受击目标重新选择。原目标条件未知时阻塞计算，不能默认无冰。共享轨迹先解释条件及倍率选择，再解释ATK乘算；`weaponProc`上下文随JSON保存，计算时由武器、精炼和明确条件重新生成来源项，已保存AST不成为改写来源倍率的依据。固定来源与精度边界见[五武器来源审阅](cross-validation/weapon-proc-five-source-audit.md)；新增两项计算核心检查首跑通过，实际记录见[日志](validation/weapon-proc-calculator-expansion.log)，不以此代替团队回调或浏览器验证。

随后新增四把状态追击的单击ATK倍率：笛剑1/1.25/1.5/1.75/2，以理服人0.6/0.75/0.9/1.05/1.2，流月针0.2/0.25/0.3/0.35/0.4，竭泽0.8/1/1.2/1.4/1.6。输入前提仍是追击已发生，不要求音符、技能窗口、实际拾球或团队历史，也不将这些状态乘进一次伤害。共享生命周期说明明确笛剑30帧是音符门槛、流月针没有每击伤害ICD。笛剑固定Optimizer sheet写死200%，R1–R4与gcsim及目录冲突；结果保留来源说明，明确采用后两者的精炼倍率，不能称20个位置三方一致。新增一个定点用例覆盖四把20个精炼位置的公式轨迹、ATK编辑及JSON，首跑通过，见[日志](validation/weapon-proc-calculator-stateful.log)和[来源冲突审计](cross-validation/weapon-proc-lifecycle-optimizer-source-audit.md)；本轮没有重跑旧八把。

`createWeaponProcCalculatorDocument()` 建立普通 `physical / proc` 单击文档；来源系数只读，随精炼选择，JSON保存相同来源与输入。共享AST展示基数、独立CR/CD、防御、物理抗性和适用增伤的公式、数值代入及结果；本击增伤只含适用通用/物理加成，不继承宿主普攻、战技或爆发专属加成。计算器的输入前提是这一次追击已合法触发且命中所选目标，不执行冷却、随机抽样、触发计数或范围目标数量推断，触发概率不再乘进已发生的一击。首批来源、可编辑例题和实际检查记录见 [独立追击计算器](validation/weapon-proc-calculator.md)。

团队模拟另通过正常控件显式启用 `fixed-source-no-character-hitlag-v1`，指定持有者、精炼、物理增伤及真实伤害标签。普通伤害实际回调（包括武器追击）触发时保存当前进攻面板，再于+1f创建自身物理命中，不继承宿主暴击结果、附魔、攻击标签增伤或防御忽略。钺矛只接受本人普攻回调，对原目标投递；苍纹角杯和冷寂迸音要求本人前台，依据触发目标实际位置建立半径3范围，并用目标位置/体型判定命中。冷却到期帧仍阻塞，下一帧才就绪。独立事件保留 `parentDamageEventId`、`weaponProcLogId`、触发/快照/伤害帧及目标结果；桥接恢复完整快照到同一计算器核心，并在轨迹解释触发至投递和来源基数。

新增五把另要求 `legal-frame-v1`：实际普通命中把武器回调排到同帧、同相位FIFO尾部，回调执行时才读取前台、冷却、原目标附着和快照。宿主之后已有同相位任务可能改变附着，不能无条件使用宿主自身的 `auraAfter`。吃虎鱼刀不筛选攻击标签，`roll ≤ 0.5`通过后才检查非零伤害；古华与三霜葬要求普攻/重击，严格`roll < probability`且没有零伤害门。霜葬R5概率为1仍消耗随机数；回调成功后按原目标Cryo/Frozen一次选档，整次半径3攻击共用系数。命名`independent-weapon-proc-v1`流记录实际抽样与顺序，只保证本地复现，不声明与gcsim共享随机流同seed一致。

结果完整性校验从真实普通命中重建新回调顺序及随机抽样，霜葬的Cryo/Frozen条件由共享目标时间线相位末状态独立恢复；不接受日志自报条件作为证明，也不声称整个Aura对象已经一致。桥接复用独立入口的倍率选择AST，随后执行同一普通伤害核心。[实际回放用例](validation/random-weapon-proc-integrity.md)观察到父命中后有冰、但同相位后续火命中先消耗冰，回调最终选择1.4倍；两个追击各700，第二目标捕获及JSON回放差0。该合成边界与四类篡改拒绝属于本地证据，不冒充外部游戏实测。

四把状态武器另要求真实合法时间线。`weaponProcLifecycleLog`关联实际接受的E或实际粒子分发，不把计划动作、能量不足拒绝或固定回能当触发；伤害回调仍在同帧同相位FIFO中执行，记录状态前后值。笛剑仅以本人前台普重累积音符，30帧门槛通过才检查1800帧窗口、加一并续期，第五次清音符和窗口后排追击。以理服人本人前台E刷新900帧效果并清除命中冷却，窗口内本人前台普重使用名义180帧伤害冷却。流月针按实际拾球时前台激活300帧，满能或零数量的实际分发仍有效，后台分得能量不代表前台拾球；之后本人普重非零伤害不复查前台，也没有追击ICD。竭泽E激活有720帧冷却，成功才刷新900帧窗口与次数；本人前台普通伤害不另筛标签或零伤，前两次写120帧伤害冷却，第三次删除效果而不取消已排伤害。效果及门槛到期等号仍有效，纯查询不清过期字段；精确转换及原文见[共享生命周期来源](cross-validation/weapon-proc-lifecycle-source-audit.md)。

## 来源角色命中

正式角色入口已接入杜林、批量来源分类的普攻和经审阅的技能映射，不再仅有杜林。`resolveClassifiedCharacterHits()` 对当前字段和固定来源的完整天赋倍率向量进行一致性检查；相关字段漂移或缺少所选等级时，仅阻塞对应动作。映射可包含多属性缩放、重复命中实例和“完整动作/所选组成”的区别，未分类参数不会自动升级为伤害。覆盖数由 `getClassifiedHitCoverage()` 派生，应查阅当前生成报告，不在本规格写死活动计数。

这些映射的数值证据是 `cross-checked`、机制是 `partial`，输出仍为 `provisional-conditioned`；完整角色/队伍模拟并不由命中字段分类自动建立。角色选择器的默认最终面板是明确标注的教学输入。例题区另有独立的 `source-backed-game` 凯亚最小真实配装实例，与合成面板和 `verified-game` 完整核验类别分开。

安柏的永久 `/calculator` 角色入口除原 N1–N5 外，新增“兔兔伯爵 · 自然到期爆炸”和“箭雨 · 18 段全部命中”，分别定义一段 E 与18个独立 Q 命中，可选单击或完整条件施放，不需要先运行来源情景。来源天赋向量按有效等级1–15精确读取；当前范围为 C0。E 输入兔在生成时的实际快照面板，Q 输入起手快照面板；已生效 A4 攻击力须含在该面板，或明确停用相关未执行状态，不自动建立弱点命中增益。E 不包含受击提前爆炸、冻结、位移、长按落点或额外命座；Q 全段命中是明确假设，不推断敌人移动、随机落点或每段实际反应覆盖。

普通命中新增角色来源 `critRateFormula`，与装备标签 CR 和面板合计后进入共享暴击步骤。安柏 Q 每段携带 A1 的10%暴击率公式，要求明确突破≥1，已锁定时不适用、未知突破时阻塞相应依赖；它不会改变 E、普攻或全局面板。已提供 `effectiveCritRate` 时保留来源式但不再加入，最终面板转换与 JSON 恢复保持该语义；命座范围检查仍保留。来源映射和生成的19击执行契约见 [安柏来源记录](cross-validation/action-library/amber-skill-burst-contract.md)，具体测试由来源/核心记录报告，本规格不替代本轮构建或浏览器验收。

基础动作来源补入迪卢克、雷泽、托马、重云、雷电将军，以及魈、钟离、神里绫人、艾尔海森、神里绫华、凝光、烟绯、芙宁娜、嘉明、荒泷一斗的已审分支。每个 N 表示一次输入，源多击分别保留，例如托马N3两击、雷电N4两击、钟离N5四击；钟离突破4的 `0.0139×MaxHP` 对每击分别加入。各动作声明必要的形态、附魔、层数与被动条件，不用整名角色的缺口阻止条件明确的单次伤害，也不把新增基础输入当作完整角色。无碰撞的低/高落地伤害以合法腾空已发生为条件；连续重击时长、附带追击、体力和动作帧须另有定义。精确分支与仍未纳入的动作见 [基础动作来源审计](cross-validation/basic-attack-gap-audit.md)。

第三批 `conditionedBasicActionMappings` 实际增加25个条件动作、30次命中：绫人、绫华、烟绯、嘉明、芙宁娜、魈、一斗、海森各两个无碰撞低/高落地动作；芙宁娜N1–N4各有始基力冷却中和就绪两个输入；海森另有双段CA。均为C0的明确条件计算。下落已合法腾空，且闲云等外部追加基础伤害和协同事件未生效；若实际生效须恢复对应独立加项，不能仅改最终ATK。海森CA/下落要求全程零镜，A1冷却覆盖每个回调，前一动作不是hold E；没有据此补齐有镜投影或A1就绪分支。

## 凝光有屏 Q 与独立历史最终快照

永久独立计算器另有 `ningguang-burst-with-screen`：六枚 Q 本体读取当前进攻面板，六枚屏宝石读取此前 E 命中时保存的历史面板，两组都使用 Q 的有效天赋倍率。原无屏六枚 C0 动作保持独立。新入口支持 C0–C6 的这十二枚自身伤害；C6 生成供后续重击使用的星璇不混入 Q，适用命座加级由有效天赋输入处理。来源和实际核对范围见 [凝光历史快照记录](validation/ningguang-screen-snapshot.md)。

普通命中可携带 `finalSnapshot`，明确保存最终 ATK/HP/DEF/EM/暴击率/暴击伤害、可选充能、角色等级、突破、适用总增伤、固定基础加值、反应加成及数值来源。核心恢复这份手动最终进攻上下文后进入原有普通伤害公式与 AST，轨迹仍展示定义、单位、实际代入和中间结果。快照不补造历史装备分解，也不再套用当前装备、转换、限定暴击或未决装备条款；仅选择历史命中时，不要求无关的当前构筑已经完成。目标等级、防御和抗性仍取命中时输入，逐击最终抗性可显式覆盖。

`gameContext.ningguangBurst` 保存屏是否存在、当前 Q 与历史 E 各自的 A4 活跃/已含标记，以及 `screenSnapshot`。两组12%岩伤分别执行 `0.12 × (对应快照A4有效 − 已含)`；当前获得 A4 不追溯改写历史 E。声明有效须对应快照突破至少4，“已含”但“未生效”会阻塞该组。没有历史快照或没有可销毁屏时，仅屏宝石依赖阻塞，本体单击仍可算；缺屏时完整无屏伤害使用原无屏入口。

正常界面提供完整历史面板草稿、数值来源说明及“应用／清除历史快照”；未知值保持空白，只有明确零值才填0，不从当前 Q 属性自动复制。历史段被快照覆盖的普通输入只读，通过专门控件修改；JSON 往返和转最终面板保留同一快照。这份条件完整动作明确要求十二枚都命中同一稳定目标，不认证散射、碰撞、精确时序、穿屏触发、能量或轮转。来源仍有屏宝石 hitmarks 与穿屏事件 TODO，固定来源可复现不升级为官服实测。

## 刻晴 Q 与行秋 E 的被动记账

刻晴十击 `keqing-burst-complete-cast` 与行秋两段 `xingqiu-skill-complete-cast` 均为永久独立计算器中的条件完整动作，可直接选择整次或其中一击。两者在固定来源中均逐击取样：行秋当前要求共享面板、装备及目标状态稳定；刻晴的 `statsStableAcrossHits` 限定基础面板及 C4/C6 以外的装备、目标状态，多击合计需要该声明，独立选中一击可恢复该击实际面板。刻晴 C4/C6 自身允许逐击变化，不能把其他未知面板变化也当成已支持。两者还要求明确突破，未知解锁状态不会当作被动尚未解锁。原 T1–15 来源核对见 [来源记录](cross-validation/keqing-xingqiu-source-audit.md)，后续刻晴 C0–C6 条件范围见 [逐击命座记录](validation/keqing-constellation-context.md)。

`gameContext.keqingBurst` 保存 `a4IncludedInPanel`、上述稳定条件与 `hitStates[hitId]`。Q 初击、八次连斩、尾击各自走共享核心；已解锁 A4 在 Q 起手提供15%暴击率，逐击来源式为 `0.15 × (已解锁 − 面板已含)`。手填 `effectiveCritRate` 保持最终值优先，修改记账不会自动改写覆盖；清空覆盖才重新合计来源。正常界面可编辑条件，派生的来源公式输入只读，JSON 保留相同上下文。

刻晴 A4 同时增加15%充能。来源配装把它作为 `pre-panel` 非转换属性送入原面板核心；绝缘等读取非转换充能的条款包含此值，西福斯等精通转换所得仍不被二次转换。刷新按固定来源 ID 替换旧条，切换其他动作移除这份 Q 状态。转换最终面板后不再重复加入；手动和导入最终面板须由用户恢复实际生效后的充能，暴击率记账开关不控制或反推充能分解。

C4 每击分别保存 `c4Active`、`c4IncludedInPanel` 和需要时的 `baseAttack`，以共享攻击调整步骤执行 `基础攻击 × 0.25 × (本击有效 − 共享ATK已含)`。差值直接加入本击最终 ATK，不再乘攻击百分比。来源装备读取角色基础攻击加武器基础攻击；手动/导入只有需要补加或移除时才必须明确基础攻击，不能从最终 ATK 反推。两状态相等时修正为零，不要求补造未知基础攻击。

C6 每击保存 `c6NormalActive`、`c6ChargedActive`、`c6SkillActive` 与 `c6IncludedStacks`，执行 `0.06 × (1 + 普攻类 + 重击类 + 初次E类 − 已含类别数)`。本 Q 起手同步刷新爆发类别480帧，十击于56–197帧取样，故计一次；相同类别覆盖刷新，旧 Q 不能再加一类。其余类别可逐击明确有效或失效，已含类别数为0–4。实际八连斩帧为82、93、104、115、126、137、148、159，来源注释的循环上界162不是另一命中。

逐击控件使用“未知／否／是”和可留空数值，缺失字段不默认为无效；未知只阻塞依赖该字段的已选命中。新来源配装把 C4/C6 已含份额设为零，新展示柜最终面板则清除相关记账与旧基础攻击为未知；展示柜不证明临时状态。所选反应不能推断伤害快照前已经触发 C4，控件也不自动模拟状态寿命、前序动作或卡肉。转最终面板、重新应用来源配装与 JSON 保留同一记账语义。这是 C0–C6 的所选 Q 本体条件计算，未注册为完整角色或自动 Q 时间线。

`gameContext.xingqiuSkill` 保存 `a4IncludedInPanel`、`burstActiveAtCast`、`statsStableAcrossHits`、`c2ShredActive` 与 `c2ShredIncludedInResistance`，正常界面逐项编辑。突破4的永久20%水伤以 `0.20 × (已解锁 − 每击增伤已含)` 补差额。C4 且 E 起手构造攻击信息时 Q 有效，基础式为 `ATK × 本段天赋倍率 × 1.5`；独立附加基础伤害在其后另加，不能把该50%写进普通增伤区，也不放大额外基数。

行秋 C2 只由既有 Q 剑雨命中施加，E 本身不建立该状态。目标已有15%水减抗及输入抗性已含份额分别记账；逐击 `effectiveResistance` 覆盖时不再应用来源减抗。当前支持 C0–C6 的本次 E 自身两段，有效 E 等级已含适用命座加级；各段反应独立输入，不默认双蒸发。新来源配装将 A4 记为未含；最终面板导入对已解锁永久 A4 采用已含假设并明确显示，可按实际输入更正。导入不会证明 Q 起手状态、目标既有 C2、剑雨生命周期或两段实际反应覆盖。

## 久岐忍独立 E/Q 的完整伤害与条件恢复

久岐忍已有四个条件完整伤害入口：`kuki-skill-c0-complete-cast` 为初击加8环、`kuki-skill-c2-complete-cast` 为初击加10环，分别对应 C0–C1 与 C2–C6；`kuki-burst-high-hp-complete-cast` 为7击，`kuki-burst-low-hp-complete-cast` 为12击。原三个 partial 注册由完整动作中的可选独立命中替代，不要求先组队或运行轮转。E 命中次数来自固定可执行回调，而非用持续时间除间隔猜测；Q采用实际循环的7／12击，保留源码旧注释“11”冲突，不用目录独立舍入的展示总倍率替代逐击求和。具体来源与检查见 [实施记录](validation/kuki-complete-casts.md)及[来源审阅](cross-validation/kuki-complete-casts-source-audit.md)。

`gameContext.kukiDamage` 保存 `statsStableAcrossHits`、`ringUninterrupted`、`burstHpRatioAtCast`，以及 C6 的有效、已含与最终EM恢复声明。多击合计要求进攻面板、装备、目标状态和 C6精通明确稳定；完整 E 另要求本次草轮完整持续且未被重放替换。未知条件可保持未知并独立选择实际发生且上下文已恢复的一击。C2角色可从短 E 模板独立选初击或前8环，C0不能选第9环；完整动作计数须与命座分支一致。界面默认“稳定／完整持续”是可编辑教学假设，文字明确区分实战观测。

完整 Q 以施放时实际生命比例选择：`HP≤0.5` 为12击，`HP>0.5` 为7击；恰好50%进入长分支，后续回血或消耗不重新判断次数。真实入口的该比例默认未知，不从所选动作名或最大HP推断；前7个独立命中可以不依赖这个条件，第8–12击仍须明确低生命分支。固定源 Q 在施放时保存一次进攻快照，每击按最大 HP 与单击天赋倍率执行普通伤害；最大HP与当前生命比例是两个独立输入。

E 每击通过共享 AST 执行 `ATK × 本段天赋倍率 + EM × 0.25 × A4解锁`，再进入普通增伤、暴击、防御、抗性与各自反应；A4是基础伤害加算，不再填入增伤区或另加第二次。gcsim 低突破初击无条件加入25%EM，而 Optimizer 为初击与环击都设置突破4门控，因此突破低于4时只阻塞初击，不擅自择一；低突破环击可按零 A4计算，Q不依赖此冲突。未知突破仅阻塞需要判定 A4 的 E 命中。来源 E 环击仍有快照 TODO，稳定条件不等于动态快照已实测。

C6恢复使用同一逐击精通步骤 `EM_hit = EM_panel + 150 × (有效 − 已含)`，可补加当前状态或移除已失效旧份额。手动/导入最终面板可明确声明已恢复实际EM，此时不再补加或反推C6；来源配装不能以最终EM声明替代有效/已含记账。新来源配装明确未含，重新导入的临时份额保持未知。未知C6仅阻塞实际依赖EM的命中或来源配装上下文；纯最终面板、无精通反应的 Q HP 单击仍可独立算。逐击最终暴击覆盖保持优先，反应逐击输入，JSON与转最终面板沿用同一核心。

C1只改变 Q 范围，C3/C5由明确有效天赋处理；C4需另一次普攻/重击/下落触发，其印记不混入本次 E/Q 自身总伤。独立伤害入口不自行执行 E扣血/治疗、C6触发与到期或完整队伍生命周期；下文另有固定 C0/C2 来源 E 与 E/Q 执行契约，已接入耗血、治疗、替换、产球和真实起手HP决定的 Q，但不会替代这些独立入口或认证 C4/C6及其他配装。来源分类、固定条件执行与游戏验证继续分开。

## 柯莱与夏洛蒂完整 E 的条件与历史快照

`.17` 注册表提供柯莱无新叶、两次新叶、四次新叶三个完整 E 分支，以及夏洛蒂 C0–1 点按和长按完整 E。九个参数映射展开26个条件命中，替换五个旧 partial，各击仍可独立选择。75个T1–15系数位置在固定gcsim、活动目录和固定Optimizer逐项一致；来源继续暂定，不等于实际游戏触发链验证，见 [来源审计](cross-validation/collei-charlotte-skills-source-audit.md)。

柯莱往返两击共用释放快照，新叶使用回收时另一份完整 `gameContext.colleiSkill.sproutSnapshot`，经 `finalSnapshot` 进入同一核心。新叶每击为回收时ATK的40%，不随有效E等级放大；两次/四次来自固定源的实际tick循环。C0–1按A1解锁与回收前草相关反应决定有无新叶，C2–5按飞行或新叶期间是否有一次有效延长选择两次/四次。任一时段明确延长即可，不要求补不影响结果的另一时段；完整C6仍未支持。缺真实回收快照只阻塞依赖它的新叶，单选飞叶轮不要求未选中新叶的历史面板，完整动作仍需明确触发、持续和次数条件。

反应声明须与完整分支一致：例如“回收前无草相关反应”不能同时为飞叶轮填写Spread而遗漏新叶。Spread的EM和反应加成取实际命中值，不自动随释放/回收面板快照；仅所选命中含Spread时，要求 `reactionStatsMatchSnapshots` 明确确认这些实际值与对应面板相同，未知不视为成立。核心与最终面板转换按共享角色上下文重新准备各击，不能通过修改JSON复制快照制造互相矛盾的新叶。该静态条件入口不自动执行光环、反应触发或延长时间线。

夏洛蒂点按为初击加4次标记，长按为初击加8次标记；`.18`沿用这两个动作和原命中，仅把条件范围扩展至C0–5，不增加覆盖计数。初击起手快照、标记逐tick取样，因此完整分支要求除下述逐击C2差值外的进攻/装备/目标状态稳定、标记未替换或提前结束、没有命中停顿延长至额外tick。单选实际一击不要求后续标记完整。`gameContext.charlotteSkill` 保存实际非枫丹其他队友人数、A4已含记账及完整持续/稳定条件；突破4已解锁时人数须明确为0–3，未知不当0。共享公式为 `0.05 × 非枫丹其他队友人数 × (1 − 已含)`，枫丹队友的治疗加成不当冰伤。新装备与最终面板导入按实际突破重置A4已含份额，保持实际人数；计算与转换入口均重新准备同一公式。

C2–5在同一上下文保存 `c2HitStacks[hitId]` 的实际0–3层、`c2IncludedStacks` 的共同面板已含份额，以及两者不同时所需的 `c2BaseAttack`。共享 `attackAdjustment` 逐击执行 `基础ATK × 0.1 ×（实际层数 − 已含层数）`，白值为角色与武器基础攻击之和，不含百分比或固定攻击；它修正输入最终ATK，不再次乘ATK%。实际与已含层数相同时，同来源轨迹明确解释零差，无需提供或伪造未知白值。来源配装直接读取并保存本次基础攻击，新装备将已含层数置0；最终面板在差值非零时须明确给出白值，展示柜导入清除旧白值和已含层数，保留实际逐击状态，未知不能反推或默认0。缺少实际层数只阻塞依赖该层数的所选命中，不要求为未选中的其他tick补值；完整合计则需全部列出命中的状态及其他稳定条件。计算与最终面板转换都由共享核心从角色上下文重新准备公式，共同面板保留未逐击修正的基底ATK，JSON中的逐击副本不能绕过该记账，见 [核心专项](validation/charlotte-c2-core.md)。

初击可带此前有效的C2；本次E的C2是在初击结算后的回调增加，不能倒填到初始快照。标记每次重新取样，12秒C2的实际刷新、角色卡肉延长及到期由明确逐击状态表达，不自动推演。[一次固定来源外部样本](cross-validation/charlotte-c2-external.md)在无其他增益、无卡肉的C2长按E中记录：初击不含本次C2，前七标记各有一层，第八标记于833帧恰好C2属性到期，已经无加成而标记仍生效。该属性的 `expiry <= frame` 排除规则与独立武器冷却的到期帧仍有效不同，不混用。C1只增加治疗，C3只升Q等级、C4只影响Q；C5读取明确有效E等级而不重复加3。C6新增伤害仍阻塞，两角色的来源几何、精确时点TODO、动态命中数及团队能量不因本次条件动作完成而获得认证。

## 诺艾尔的独立 Q 状态与逐击攻击转换

诺艾尔已有 N1–N4、重击旋转、重击终结、下落碰撞、无碰撞低/高落地和 Q 起手两段，可直接在 `/calculator` 选择，不要求组队或先运行轮转。旋转、终结和碰撞是部分组成，不能根据两条重击系数猜一整次持续重击。Q 起手两击均为 `burst`；第二击的来源名称包含 Skill，不改变它的爆发标签。

`gameContext.noelleBurst` 保存独立状态，正常界面提供四项输入：

| 输入 | 数值含义与边界 |
| --- | --- |
| `active` | 本段 Q 是否激活；普通/重击/下落据此为物理或岩，Q起手本身不能选未激活 |
| `effectiveTalentLevel` | 明确有效Q等级1–15，决定转换系数及Q两击倍率；不改普攻/重击/下落自己的天赋等级，不因C5再加3 |
| `defenseSnapshotNonExtra` | 建立这次转换时的历史非 Extra 防御；不能从当前最终DEF自动重采 |
| `accounting` | `add-to-panel` 表示攻击面板未含转换，`already-in-final-panel` 表示已含且不再加入；后者可不提供未知历史DEF |

`applyNoelleBurstContext()` 以已核对源表建立每击 `attackAdjustment`。共享 AST 执行 `来源固定ATK = 历史非Extra DEF ×（有效Q转换系数 + C6额外0.5）`，再以 `本段ATK = 面板ATK + 来源固定ATK` 进入天赋与适用装备公式；不乘攻击百分比，也不改变其他命中。转换前读取的装备条款不会再使用这份 Extra ATK 二次转换。所选动作缺必要历史快照或Q状态矛盾时明确阻塞，已计入模式保留来源式而不执行或反推历史。

C0–C6 的已审数值分支包括 C2 只对重击旋转/终结增加15%伤害、C6转换额外50%。普通/重击/下落在Q激活时保留原攻击标签并改为岩元素；C4护盾爆炸不属于这些输入，C3/C5由明确有效天赋等级处理。切换最终面板只结算装备基底，仍保留每段 `attackAdjustment` 与记账方式，不新增一个全局 `effectiveAttack`，也不把不同段的历史状态压成同一ATK。JSON保留同样上下文。

固定源码对立即取DEF快照、转换起效时刻和 `900+80` 帧持续仍有 TODO；Q的+24/+65是可受卡肉影响的角色任务。这里执行用户明确恢复的命中状态，不自动推断这些时点、续期、治疗、能量或空中资格。来源映射与三个已执行核心用例见 [诺艾尔来源](cross-validation/noelle/source-mappings.md)和[条件计算证据](validation/noelle-calculator-context.md)；它们不证明本轮UI、构建或浏览器验收通过，真实Q→N执行另按来源情景说明。

## 一斗的单次逆袈裟与两份防御快照

`aratakiitto-kesagiri-combo` 与 `aratakiitto-kesagiri-finisher` 分别提供一次连斩和一次终结，均可从永久单技能入口选择，每个动作只有一个自身命中。左右连斩使用同一倍率，不表示一次输入同时产生两击；“完整”只指所选单次动作，不包括整段持有重击或整个Q窗口。

`applyIttoChargedContext()` 经角色入口接入核心，正常表单与JSON保存 `gameContext.ittoCharged`：

| 输入 | 实际含义与边界 |
| --- | --- |
| `superstrengthStacks`、`c6PreserveStack` | 明确起手1–5层与本次C6保层判定。连斩要求至少2层，或1层且C6保层成功；终结要求1层且未保层。低于C6不能声明保层成功。 |
| `actionDefenseSnapshotTotal`、`actionDefenseStable` | A4使用本次重击起手的完整DEF，包含Extra。没有历史值时，只有明确声明DEF从起手至命中稳定，才按该条件使用面板DEF；A4未解锁时不需要这份快照，突破未知仍阻塞相关依赖。 |
| `burst.active`、`burst.effectiveTalentLevel` | 本段Q是否有效及独立有效Q等级1–15。Q有效时重击转岩，保留重击标签；不改变本次重击天赋等级，也不重复增加C5等级。 |
| `burst.defenseSnapshotNonExtra`、`burst.accounting` | Q建立转换时的历史非Extra DEF，与A4起手完整DEF独立。`add-to-panel`要求历史值；`already-in-final-panel`不重复加算，也不反推未知快照。 |
| `c4BuffActive` | 明确当前20%攻防增益是否有效；低于C4不能开启。有效且使用装备推导时阻塞，须恢复已包含增益的手动或导入最终面板。 |

共享AST依次执行 `Q来源固定ATK = Q历史非Extra DEF × 有效Q系数`、`本段ATK = 面板ATK + 尚未计入的Q固定ATK` 和 `A4附加基数 = 重击起手完整DEF × 0.35`。Q转换属于Extra固定ATK，不再乘ATK%；A4进入基数加算，不冒作ATK或伤害加成。两份历史值明确提供后，修改当前DEF不会重新取样。C6的 `critDamageFormula` 只给本段重击增加0.70暴伤；50%保层概率不转换为1.5倍伤害，也不在本入口随机决定连段长度。

最终面板转换保留构筑基底、逐击Q调整和两份历史输入；C6可固化为本段最终暴伤，来源公式保留并标记不重复应用。已有 `effectiveCritDamage` 时同样不再加C6。JSON往返维持这些语义，所选命中的缺失依赖仍阻止最终转换，C4未恢复的装备面板不能借切换模式绕过。

固定源码仍假定重击起手快照，命中时点未按攻速调整；Q起效、795帧持续及C1/C2延迟亦有未确认注释。本入口不模拟怪力获得/消费时间线、C6随机序列、阿丑、能量、冷却、取消或完整持有循环。来源、45个系数的独立Decimal比对及三个新增核心用例的实际结果见 [一斗条件计算记录](cross-validation/itto-kesagiri/source-calculation.md)；来源可复现与界面已接入不等于当前官服或本轮浏览器验收已通过。

## 烟绯的一次重击与条件 A4 贡献

`yanfei-charged-cast` 提供单目标一次重击，包含主击和已解锁、满足条件时的一次法兽灼眼；可直接计算整次，也可独立查看主击或已经触发的 A4，不要求队伍或轮转。`applyYanfeiChargedContext()` 保存 `gameContext.yanfeiCharged`，来源倍率与增伤都由共享 AST 执行。

| 输入 | 实际含义与边界 |
| --- | --- |
| `scarletSeals` | 本次起手实际消耗0–3印；4印要求C6，按明确有效普攻天赋选对应倍率。 |
| `onFieldAtMainHit` | 主击回调时仍在场；这是 A4 发生条件，不由主击伤害推断。 |
| `statsStableToA4` | 明确主击与 +10帧 A4 各自快照的共享面板、装备状态稳定；未声明则所选 A4 阻塞，独立主击不因此阻塞。 |
| `brilliance.effectiveTalentLevel`、`mainActive`、`a4Active` | 独立有效Q等级，以及两段各自的灼灼状态；不重复加命座等级，不自动延续主击窗口。 |
| `mainEnemyHpFraction`、`a4EnemyHpFraction` | 各段结算前的实际目标生命比例，C2分别按严格小于0.5判定；不猜目标生命上限或主击后的剩余生命。 |
| `priorA1BonusIncluded`、`includedBrillianceBonus` | 已确实包含在逐段手填增伤中的旧 A1／灼灼份额；默认0，只撤销明确声明的已含份额再加入本段来源值。 |

A1 在本次重击排队前替换旧效果，已解锁时加入每印5%；来源伤害加成公式执行 `新A1 − 已含旧A1 + 本段有效灼灼 − 已含灼灼`。突破未知时不能判断 A1/A4 解锁，因此相关计算阻塞；明确未解锁 A4 或主击回调离场时，该追击表示不发生伤害实例。C2 的逐击 `critRateFormula` 与其他暴击来源共享同一计算步骤；明确的 `effectiveCritRate` 始终优先，改变目标生命条件不会猜测并改写手填最终值，清空覆写后才重新按 C2 计算。最终面板转换和 JSON 保留来源公式、条件与这一优先级。

普通命中新增 `occurrence:{kind:"critical-hit",sourceHitId,enabled,sourceRefs}`。来源主击必须是同文档的另一普通命中且不能再有条件 occurrence，不支持任意触发链或循环。烟绯 A4 仅在主击暴击且其余条件成立时发生一次80% ATK火元素重击；它自己独立暴击和反应，不能默认主击与追击都蒸发。核心结果的 A4 `nonCritical`／`critical`／`expected` 表示已经发生的实际命中，另存 `castContribution`：整次非暴击分支为0、全暴击分支为A4自身暴击伤害、期望为 `主击实际暴击概率 × A4条件期望`。整次合计使用这份贡献；单击选 A4 则不乘主击概率。计算解释包含同一核心生成的贡献步骤，页面不另行乘算。

这是固定来源的明确条件计算：共享面板稳定不意味着主击和 A4 共用一次快照，逐段 Q 状态、目标生命与反应仍独立。产印/耗印时间线、完整 Q 生命周期、体力、取消、卡肉、多目标追击竞争，以及固定源的重击快照时点和 Q 结束产印 TODO 仍未完成。来源文件和实际核心数值记录见 [烟绯条件计算](validation/yanfei-charged-calculator.md)，不据此宣称本轮构建或浏览器已通过。

## 核心执行和就绪门

`calculator-model.ts` 定义带版本的严格输入结构；`calculator.ts` 的 `calculateDocument()` 是独立计算入口。命中种类包括普通伤害、剧变伤害、条件特殊反应、明确的非伤害事件、合成例题专用的中途数值入口，以及带原因的阻塞命中。

依赖按所选命中判断：相关依赖缺失时阻塞，不用零填补；未选中或不相关的队伍机制不会单独阻止已定义命中的条件计算。相关依赖为暂定时，结果明确保持暂定。支持状态与角色目录是否完整、是否有完整轮转是不同概念。

普通伤害支持 ATK、HP、DEF、EM 以及多个线性倍率项的合计，再按实际公式执行基础加算、伤害加成、防御、抗性、暴击、增幅与独立乘区。激化附加量先由同一反应公式执行，再进入基础加算。剧变伤害走独立等级/精通/反应加成/抗性分支，解释普通天赋、ATK、伤害加成、防御与暴击为什么不适用。非伤害状态保留说明，不编造一笔“伤害”。

普通命中还可使用带类型的 `baseDamageFormula` 代替线性 `terms` 作为基础伤害入口，表达式可明确表示资源、层数、队友贡献、条件分支、转换和上限。该字段保存规则 ID、标签、来源和逐个资源输入；输入带单位、含义、来源，可记录 `ownerId`。ATK/HP/DEF/EM 由核心注入，外部输入不得覆盖同名面板变量；重复输入 key 和非法表达式会被拒绝。页面可编辑显式资源值，来源表常量在真实数据文档中只读。表示能力不代表任何尚无来源的角色资源机制已实现。

同一通用输入界面也展示 `additiveBaseFormula`、`damageBonusFormula`、`resistanceReductionFormula`、`critRateFormula` 与 `critDamageFormula`，分别进入基础伤害附加量、来源伤害加成、来源减抗及本段限定暴击属性，而非一律当作基础倍率。每个公式保留自己的资源输入、单位、取值范围、规则来源以及适用命座/突破/伤害类型要求；依赖不满足时按核心判定为阻塞或不适用。编辑技能时，可编辑资源值按输入 key 和所有者匹配保留，来源表常量仍由对应技能定义提供。一斗、烟绯、刻晴与行秋来源式的派生输入由上述专用状态控件生成，通用公式区只读，避免两处输入互相冲突。带 `allowedValues` 的输入使用已审档位选择器，严格 schema 同时校验 JSON，不能只绕过表单填入来源范围之外的值。

洛恩来源条件动作的 `willConsumed` 当前开放 `[20,40,60,80,100]`，来自固定生产界面已核对档位；这不证明游戏只允许这些资源量，也不允许把来源空值回退理解成可零消耗起手。共享 AST 将资源增加项作用于 `B=ATK×天赋倍率`，不放大外部固定附加伤害；实际乘兴等级加成与 A4 面板仍须由使用者恢复。一次镂骨彻心为部分动作，Q 六斩为完整条件动作，不能据此声称资源获得、消费和整段循环已自动实现。

莉奈娅 A1 的 `resistanceReductionFormula` 明确执行突破≥1、露米在场、目标附近和月兆人数条件：人数<2时 0.15，≥2时总量 0.30 岩抗削减，再与其他已声明减抗合计。输入 `effectiveResistance` 时它表示已结算最终抗性；来源减抗表达式仍保留在审计中，但标记 `not-applicable`，不会再扣一次。最终面板转换和 JSON 回放保留该语义。露米普通双击是来源明确的两击部分动作，不包含月结晶 Hammer/Crush，也不按 25 秒持续时间猜总轮数。来源、数值和边界见 [洛恩/莉奈娅上下文](cross-validation/lohen-linnea-context.md)。

普通命中的 `elementalMasteryAdjustment:{formula,accounting}` 保存本段来源精通及计入方式。共享 AST 先算来源贡献，再执行 `本段精通 = 面板精通 + 来源精通 × 是否另加`；本段结果进入基础缩放、角色公式及精通反应，共享面板不被改写。每段可有独立条件，`add-to-panel` 表示面板尚未含此增益，`already-in-final-panel` 表示已含且不重复加入。最终面板转换与 JSON 保留逐段条件；重新导入展示柜最终面板会重置为“已在最终面板”，保留来源审计。控件明确呈现这两种记账方式，不能从角色命座猜测最终面板是否已经含临时精通。聚焦核心证据见 [逐命中精通验证](validation/per-hit-elemental-mastery-20260923.md)。

奈芙尔普通 E 已删除误套的幻戏帷幕乘区，仅保留来源明确的 ATK＋EM 缩放；E 标为部分动作，因施放状态先后尚未核实。普通 Q 两段按明确有效天赋等级读取倍率及每层增伤：C0/C1 消耗 0–3 层，C2–C6 为 0–5 层。突破≥1、月兆≥2且独立 8 秒增益仍有效时，C0/C1 来源精通为 100，C2–C6 为 200；后者替代前者，不相加，且可在 Q 消耗层数归零后仍有效。C4 的 20% 草抗削减由本段目标实际受影响的显式条件执行，包含退出影舞/远离后的 4.5 秒残留，不从当前施 E 或前后台推断。C3/C5 使用用户或导入已经明确的有效等级，不再加 3；C1/C6 的幻戏/月绽放能力不混入普通 E/Q。来源冲突、实测数字和未完成计时状态见 [奈芙尔普通命中记录](cross-validation/nefer-ordinary-context.md)。

逐段指定增幅只是条件化计算。核心检查火/水/冰等触发元素兼容性，并拒绝同一普通伤害实例同时指定增幅与激化附加反应。它不证明实战附着、元素量、ICD 或持续覆盖；这些必须由模拟事件状态建立。每个命中独立执行，不能将第一段反应复制到全部段数。

`special-calculator.ts` 将独立 Lunar/Stellar 条件公式接入同一文档和 trace。规则固定为代码中记录的 KQM Luna VI / 7.0 来源版本，不能视为当前游戏版本的完整支持。直接能力使用一位所有者的明确最终属性和天赋系数；排名反应使用至多四位明确参与者各自提供的等级基数。每位参与者可分别编辑精通、暴击、专属基础提升、专属反应加成、特殊加算与擢升倍率；相应伤害抗性另列。星导直接伤害还允许编辑条件化极星领域计数 `0–12`。

已有 `specialBaseBonusRules` 的参与者还显示月兆规则、提供者 `providerId` 和独立来源生命值 `maxHp`。条件化副本可编辑该生命值，核心据此重新执行来源规则及上限；提供者身份随规则显示。它与本段直接伤害的缩放生命值是不同快照输入，修改其中一个不会自动覆盖另一个。`state-resolved` 事件中的这些输入仍只读。

条件特殊分支的真实数值入口是这些独立参与者字段；界面隐藏无关普通面板与目标控制，普通面板、敌人防御和普通伤害加成不参与该分支。教学等级基数是明确输入值，修改等级不会自动插值或生成新基数。条件模式的启用选项为 `assumed-enabled`、`disabled`、`unknown`，后两者阻塞特殊公式，不能生成看似已启用的特殊伤害。此手动入口不执行普通反应回退轮转，也不证明参与资格与状态计数如何在游戏中产生。自动参考运行送入的 `state-resolved` 事件另按下文只读快照处理。例题 B 这类已结算伤害入口则只展示共享暴击输入及每段条件伤害/增幅，不提供无关基础面板或目标编辑器。

在当前来源规定的排名分支中，核心逐个枚举独立暴击组合，先计算各参与者贡献再排序加权，最后做概率加权；直接能力不使用多人排名。至多四位参与者对应至多 16 个暴击组合，表达式与中间结果均进入 trace。这是在“独立暴击、无暴击触发状态反馈”等显式条件下的解析期望，不是完整队伍模拟。

## 同一执行轨迹生成解释

`calculation-trace.ts` 定义受限表达式树，包含常量、变量、算术、最小/最大值、clamp 和条件分支，不使用字符串 `eval`。公式执行、符号表达式和实际数值代入来自同一棵树。`calculator-formula.ts` 与模拟公式共享此实现，界面不另算伤害。

每个 `CalculationTraceNode` 保存：稳定 ID、规则 ID、标题和解释的本地化 key、适用状态、表达式、输入、未舍入结果和格式化显示值、依赖关联、适用原因、来源与警告。输入包含数值、单位、含义、来源及适用时的上下文。后续算术读取未舍入机器数值，不回读显示文本。

普通视图保持三列“阶段 / 数值 / 公式”。每行可展开，查看该步解释、变量定义、实际代入、中间结果、适用条件和完整精度。来源与完整记录集中在审计区及 JSON 报告中。`applied`、`not-applicable`、`assumed`、`blocked` 分别表示应用、不适用、条件假设和缺少依赖，不把“不适用”等同于一个恰好为 1 的适用乘数。

教学例题与用户文档调用同一个 `calculateDocument()`；计算器和模拟命中检查使用同一个 trace 渲染器。修改输入后重新执行核心，再重画结果与代入，不维护一份与执行脱离的静态数字表。

例题目录由 `WORKED_EXAMPLES` 生成，分别展示合成教学、真实角色来源交叉核对、完整核验真实游戏及缺依赖阻塞类别。凯亚霜袭与普通攻击第一段使用固定真实身份、装备和来源，但保留暂定证据。资源表达式例题及特殊条件公式均为可编辑合成教学，不能因此升级真实机制的就绪状态。

## 模拟命中的完整上下文还原

`calculator-bridge.ts` 提供 `captureSimulationHit()`、`replaySimulationHit()`、`serializeSimulationHit()` 和 `parseSimulationHit()`。捕获格式 `calculator-event-v1` 保存事件 ID 和完整来源 `SimulationResult`，包括配置、规则根、命中时敌人状态、已解析面板、贡献者和反应决策，而非仅保存当前角色面板。

还原会通过原有 schema 与完整性门，重跑共享普通/剧变公式，检查各数值因子、附加贡献、潜在伤害和目标策略之后的最终伤害。允许误差为 `1e-10 × max(1, |reference|)`。手动反应覆盖仍标为条件假定；数值一致不能证明自动轮转中的反应覆盖。

当前 bridge 明确拒绝机制截断的命中，以及使用执行插件却缺少对应 `executionAudit.hits` 已解析上下文的旧结果。插件结果有完整上下文时按捕获记录核对，不根据当前面板猜测插件是否改写等级或暴击模式。拒绝是可见的上下文缺失，不把截断后的零贡献当作正确结果。捕获的源结果保留原规则与输入；未来编辑假设应另建计算，不能改变保存事件后仍声称复现原命中。

模拟命中提供“在计算器中打开”入口；`loadSimulationCapture()` 在独立计算器显示原伤害、核心重算值和差值，复用同一个步骤渲染器。该视图只读。导出 JSON 保留完整捕获结果，导入依据 `calculator-event-v1` 识别并重新执行还原验证。普通可编辑计算文档与只读事件捕获是两种不同的持久化格式。

当前唯一直接能力为哥伦比娅 C0、闲置起手的月露涤荡。实际开始前必须已经有草露，本帧随后产生的草露不能倒用于选择动作；前序动作须完整结束，124 帧锁内不能切换或开始其他动作。运行器在起手后第 55 帧实际消费一层，第 62、70、92 帧分别读取当时 HP、EM、CR、CD 和目标草抗，逐段调用共享特殊公式。三段不重复消费草露，也不造成普通附着或一份重复普通攻击；普通防御、普通增伤和普通加算不进入此直接月绽放分支。固有月兆生命值基础提升由来源规则执行；领域、月岭露、Gravity、额外命座和其他角色直接月绽放能力仍未接入。

`normalHitEnergyModel` 在已明确标记Normal/Extra的真实敌人命中回调后，以同帧任务执行来源概率：失败递增该角色武器概率，成功固定请求1能量并进入全队12帧间隔；切人按来源假定重置角色概率但保留共享间隔。未命中不触发，满能量和零伤害组不因此跳过抽样；成功所得不乘ER，真实上限和溢出另记。`normalHitEnergyLog` 保存概率、roll/drawIndex、间隔和实际能量，使用独立 `normal-hit-energy-v1` 子流。本地同输入可重现不代表与外部程序同seed逐抽样相同，12帧与切人重置也保留源码TODO；诺艾尔外部不同迭代的能量记录不合并成一份伪造等价结果。

团队页提供显式启用开关、全部已配置角色的武器类型选择及逐命中 `normal`/`extra`/不参与选择。启用时缺任一角色的武器类型会拒绝保存，不从名字推测；武器类型仅决定概率规则，不改武器伤害面板。逐击标签是明确输入，不认证游戏资格，界面显示的已标记数量也不是实际抽样次数。关闭模型保留标签，但不执行回能；开启且没有适用标签时没有抽样。来源情景的逐击标签只读，保存和公共模拟入口仍校验原来源契约，不能把不匹配的武器或回能模型写成来源已支持。

Worker批量摘要区分是否开启普通回能与随机暴击，导出 `normalHitEnergyPolicy` 的来源配置、命名随机流、算法及 `matchesGcsimRandomSequence`。暴击采用解析期望、全暴击或不暴击时，已启用的普通回能仍随机运行；实际有效seed可能由运行选项覆盖。批次首轮保存完整结果，其余轮次参与统计，没有以批量采样代替分布预热或随机稳态证明。

`favoniusModel` 提供显式的西风实际暴击产球配置。团队页可选择持有者的西风剑／大剑／长枪／猎弓／秘典、精炼及微粒到达延迟；此声明不改写角色伤害面板或其他装备属性。来源默认到达延迟为100帧，可明确修改；固定武器的安柏／诺艾尔来源情景不能添加西风后继续沿用原来源身份。机制标签为 `fixed-source-assumed`，只接入主模拟器的普通直接伤害，未接入特殊 Lunar/Stellar 宿主。

核心读取持有者实际非零敌人命中、二元暴击结果、当时在场状态及角色独立冷却，全部满足才按 `p = 0.5 + 0.1 × R` 抽样。成功条件为 `roll ≤ p`，R5 也实际取样；成功后冷却为 `810 − 90 × R` 帧，并生成三个无元素微粒。产物进入原有微粒队列，按真实到达帧、届时前台、队伍人数、ER与能量上限分配，因而可以改变后续轮转能否合法扣能，不能简化成触发时固定回复6能量。标准剧变不参与；解析期望伤害不能代替实际暴击，直接选择或插件改成平均暴击均拒绝此配置。

`favoniusLog` 记录实际命中、资格判定、概率/抽样值与序号、冷却前后边界及 `particleEventId`；关联 `particleEvents` 和 `energyLog` 可还原每位队员实际所得与溢出。结果校验重放实际暴击、随机流和冷却，并校验产物来源，不只相信一条触发日志。由实际 seed、NUL 分隔符和 `favonius-v1` 标识构成的独立 FNV-1a32/Mulberry32 子流可本地重现，与 gcsim 共享随机流的同seed序列不等同；所有实际命中保留完整捕获供独立计算器重算。本参考配置明确假定无角色卡肉，尚未实现来源冷却随角色卡肉延长，目标卡肉不能代替角色时钟。来源、接口和实际聚焦证据见 [西风执行记录](validation/favonius-runtime.md)。

通用合法帧动作可显式声明 `energyCostFrame`，未提供或为 0 时保留起手扣能。正数表示起手先检查并内部预留，实际能量保持不变；同一笔预留不能供另一耗能动作重复使用，期间粒子/固定返能仍按真实能量上限结算。到声明帧才执行 `max(0, 当前能量 − cost)`，更新消耗统计与能量曲线。未到扣能帧便结束观察时，不提前生成实际扣能记录。`energyCostLog` 的 `reserve/debit` 通过 `actionLogIndex` 关联起手，保存实际能量、预留前后值和主队列顺序；既有收入日志不伪装成扣能日志。

动作的 `summons` 声明生成帧、生命周期、到期攻击延迟及绑定命中 ID。核心在生成时保存人物属性与站位，实际自然到期后才将绑定命中排入同一主堆；人物属性使用生成快照，敌人状态、命中判定和产球走原命中路径。窗口内未到期就没有攻击，未命中就没有绑定产球。`summonLog` 记录生成/自然到期及取样、计划交付、归属和真实顺序；完整模拟命中仍经公共捕获桥接在独立计算器复现。实体 HP、受击提前销毁、位移、冻结和手动引爆不在这套定时到期契约内，详见 [来源动作执行原语](source-action-runtime-primitives.md)。

主结果 `#actionStateAudit` 的“行动、属性转换与召唤物记录”直接读取扣能、实体、属性转换、普通回能、西风及共享体力日志，每页25条可查看全部记录。转换行使用共享 `calculateStatConversion()` 和同一轨迹渲染器展示实际DEF分解与转换，普通回能行展示抽样比较、概率变化、共享间隔、真实入账与溢出；西风行展示实际暴击资格、精炼概率与冷却的数值代入，并关联微粒及各队员实际拾取记录。体力行展示核心的真实消费及恢复区间、公式和代入；扣能行关联起手，实体行保留生成快照与生命周期。计划交付时间不代表已结算，实际伤害以命中记录为准。这里使用 `renderActionStateLedger()`，没有在页面重新调度或补算事件。

执行延迟方案新版 `1.1.0 / runtime-energy-v1` 先用共享模拟器及实际能量、暴击、种子选项得到一条参考轨迹，再按明确输入/换人/取消延迟生成请求表。能量不足的请求仍保留输入延迟，但没有成功动画；取消附加延迟只取参考轨迹中实际接受且尚未结束的能力动画，等待与失败输入不创造新动画。保存的 `1.0.0` 保持结构编译和相邻能力输入语义，不按相同预设名称自动升级。返回记录保存实际基线选项、每项成功/失败状态和失败码，见 [真实资源基线](validation/execution-profile-runtime-baseline.md)。

每批以选定 base seed 生成一次固定参考请求表，再对各 sample 独立模拟资源和随机事件；不根据每个 sample 的随机结果自适应重新排动作。延迟不改命中相对帧、冷却、实体寿命或伤害倍率，最终运行仍负责报告延后后的能量失败、结构冲突和窗口外输入。这些可编辑工程假设不是实测玩家操作分布或稳态证明。

## 共享生命状态、治疗与生命消耗

普通团队页提供 `player-health-controls.ts`：显式启用已有 `reaction-self-v1` 生命模型，填写角色初始生命比例、各元素抗性、队伍位置与受击半径，并为 `rotation[]` 或 `timeline.abilities[]` 添加 `healthChanges`。未知字段留空且保存时要求明确；“满血、零抗性、原点与半径1”按钮仅提供可编辑合成条件，不代表角色实测。每项可声明治疗或生命消耗、相对实际起手帧、接收者和数值；固定来源声明只读，自定义输入带明确来源说明。关闭生命模型会移除这些声明，重新启用须重新填写；原安柏/诺艾尔来源契约不会因 UI 可编辑而失去限制。

治疗与生命消耗共用已有角色 HP、反应自伤和生命时间线，未建立第二个生命池。治疗基数可为固定量或事件前目标最大生命比例；消耗另可用目标当前生命比例。治疗加成、受治疗加成、消耗下限和来源均为明确输入，不从角色、武器或命座推导。`self` 指行动来源，`active` 在事件执行时读取前台，`party` 依配置队伍顺序，也可指定角色。必须同时提供有位置的兼容目标 `enemy-0`；当前最大生命取静态面板，改变最大生命的 `hpFlat`/`hpPct` 动作增益拒绝。

生命事件由实际成功接受的动作排入同一主队列，优先级2，在同帧行动输入/增益之后、普通命中之前；同优先级依事件序号执行。能量不足而未执行的动作不安排生命变化。此顺序是当前固定来源假设下的显式引擎政策，不证明所有角色回调时机。生命配置要求时长、周期和旧式秒制行动位置对齐60 FPS整数帧，实际使用 `legal-frame-v1`，公共入口拒绝显式 legacy；超过模拟终点的待执行事件不补做。独立计算器中的手动 HP 条件仍是快照输入，不能因模拟器已有 HP 状态而宣称所有角色门槛或被动已自动反馈。

`calculateHealthChange()` 复用伤害计算器同一 `TraceBuilder`/AST，生成基础量、治疗乘区、请求量、下限、实际变化、事件后生命和溢出七步。治疗请求为 `基础量 × (1 + 治疗加成 + 受治疗加成)`，有效治疗为 `max(0,min(请求量,最大生命−当前生命))`，溢出不计入恢复；消耗下限为 `最大生命 × 明确下限比例`，实际消耗为 `max(0,min(请求量,当前生命−下限))`。低于下限时消耗为零，不反向回血；消耗不属于伤害，不消耗护盾，也不进入敌人伤害归属。每步均保留来源、变量解释、实际代入及未舍入结果。

`playerHealthEvents` 关联真实动作、变化声明与事件顺序，`playerHpTimeline` 贯通治疗、消耗和反应自伤。生命汇总保持 `初始生命 + 有效治疗 − 消耗 − 生命伤害 = 最终生命`，结果校验核对同一状态链及事件来源。`renderPlayerHealthLedger()` 接在主结果与启动记录中，每页25条可遍历全部 HP 记录；展开时呈现核心已计算的轨迹，半开窗口只读取 `frame < endFrame` 的实际事件，边界生命由该角色最后一个区间内状态取得。引擎总终点仍采用其既有闭区间规则，页面不会将这个规则误当成半开观察窗。

周期治疗另使用 `periodicEntities` 的 `periodic-active-heal-v1` 声明。`PeriodicEntityRuntime` 维护同拥有者/定义的活动代次，主队列执行生成、tick、替换后旧tick取消和到期。tick先执行再判断到期，非整除持续时间的实体在首个到达或越过到期帧的tick后终止。`calculatePeriodicHealing()` 在真实tick读取拥有者最大HP、当前HP和EM，生成来源治疗基础与低生命条件的共享 AST，再交给原 `calculateHealthChange()` 写回同一HP池；`periodicEntityLog` 与派生生命事件关联，不另外补算生命。此原语已用于上文久岐忍固定 E 契约，其来源状态仍为暂定；替换和执行边界见 [周期实体执行记录](validation/periodic-entity-runtime.md)。

显式生命之契资源和动态最大生命现已接入固定来源模式，原未启用模式仍保持零债务／静态上限；零生命采用 `clamp-and-continue`，不模拟死亡/复活。负治疗状态、敌人攻击、一般治疗/消耗触发被动、HP门槛自动伤害增益、其他角色技能/装备数值映射和角色卡肉任务重定时仍未实现。静态 `healthChanges` 与确定性周期实体的实际状态、代次关系和后续任务均已按下述相位规则导出，不再仅因存在这些声明而阻塞确定性周期；缺少真实导出或其他独立状态仍拒绝完整性。超出普通附着首层的反应生命周期和随机等缺口继续适用。首次公式见 [生命执行记录](validation/player-health-runtime.md)，静态队列证据见 [生命相位记录](validation/player-health-phase-checkpoint.md)，周期实体证据见 [本轮检查点](validation/periodic-phase-checkpoint-core.md)，不以通用入口存在提高数据验证等级。

## 显式共享体力与合法行动

团队页可明确启用 `staminaModel:{mode:"shared-stamina-v1",profileId:"gcsim-b4ae769-stamina-v1",initialStamina}`，只适用于60 FPS的 `legal-frame-v1` 时间线。全队共享240上限，初始量为明确的0–240，切人不补满，也不随零／满能量起步选项变化。模型及其来源为 `fixed-source-assumed`；未配置模型的旧输入保留原行为，不凭动作名推断体力规则。

启用时每个能力和 dash/jump 指令都必须声明 `staminaCost:{amount,consumeFrame,source}`，包含明确的零费用。团队页逐行填写消耗、相对起手的扣除帧，以及可选 `consumeWhenZero`；固定来源声明只读，自定义输入不升级为角色来源证据。普通零费用不调用扣除，也不延迟恢复；只有显式 `consumeWhenZero:true` 表示零费用仍调用 UseStam。减耗、命座及特殊资源不会自动由显示名称生成。

输入时检查现有体力。strict 不足则记录 `INSUFFICIENT_STAMINA`，该请求不产生伤害、冷却、扣除或能量失败，后续指令继续；wait 等到实际恢复足够才尝试执行。等待期间行动状态可能到期，失败仍保留已经消耗的等待时间。正数 `consumeFrame` 延迟实际消费但不预留，实际扣除为 `max(0,S_before−declaredCost)`；另一动作可以先消费共享池，到回调时实际所得扣除量可小于声明值。每次真实调用都重置恢复延迟，不能把输入资格检查等同于消费已经发生。

恢复条件为整数玩家帧 `F−LastStamUse > 90`，每帧增加 `25/60`，上限240。同帧先玩家恢复、再延迟扣除、再输入行动；初始 `LastStamUse=0`，自定义初始量不足上限时也从F91才恢复。合法轮转编译与实际模拟使用同一状态机的独立实例，`result.stamina` 是真实模拟日志，不是编译预测的副本。连续恢复合并成区间，保留公式、变量解释、代入、前后值和实际变化量；`staminaTraceBefore(result.stamina,endFrame)` 在共享核心中把跨窗区间裁到 `endFrame−1` 并重算同一公式，页面只呈现该半开窗口记录。

模型、逐行动费用及结果由当前版本 schema 保存与核对；无模型却携带费用、遗漏费用或旧版本携带扩展均拒绝。体力量、恢复时钟及全部待扣任务已进入下述版本化完整相位状态，不再因启用共享体力本身阻塞确定性周期判断；仍须满足完整状态、重复未来输入与足够尾段。全角色已核实体力费用、动态减耗、恢复天赋、体力上限变化、真实角色卡肉、特殊冲刺连续费用、冲刺连用锁，以及攀爬/游泳/飞行仍未覆盖。首次运行边界见 [共享体力运行记录](validation/stamina-runtime.md)，后续检查点证据见 [体力相位记录](validation/stamina-phase-checkpoint.md)。

## 连续预热的启动诊断

团队结果分析另提供连续预热运行，与无需队伍的单技能入口独立。`renderStartupLedger()` 读取同一运行中观察窗口开始前的实际日志，分别提供成功行动、失败耗能请求、粒子/定值能量三张表，每页 25 条并可遍历全部记录，另列实际起始和观察边界能量。没有只保留前 50 条，也不在边界补满能量或重置其他状态。

能量展开行展示核心记录的充能前能量、ER 倍率、`clamp(变化前能量 + 本次能量, 0, energyMax)`、实际所得与溢出；定值能量明确不乘 ER，被内置间隔阻止的记录明确不应用。每张表保留自己的日志顺序，不推断不同表同帧之间的先后。完整连续结果仍可导出。分页与解释不是稳态证明；只有完整同相位状态和周期伤害满足核心条件时才建立稳态，超出下述普通附着首层的反应生命周期和特殊实体仍未获得完整状态支持。

启动区间还复用上述 `renderActionStateLedger()`，仅显示观察边界之前的真实预留/扣能、实体生成/到期、属性转换、普通回能、西风及共享体力记录；跨边界体力恢复区间由核心裁剪，生命账本同样读取边界前真实 HP 链。不截断为前若干条JSON，也不把边界之后的事件移入启动区间。

`nonreactive-phase-state-v2` 现已从同一次运行导出确定性的延迟能量预留、定时召唤和属性转换。`energy[].reserved` 与实际能量分开，待扣队列须与预留总量相符；`entities.timedSummons` 保留重叠实体的完整生成快照和相对期限，主队列保存待生成/到期任务；`buffsAndDebuffs.statConversions` 保存转换定义、真实历史源值、结果、完整快照及剩余期限。检查点在边界帧全部事件之前取得，等于边界的扣能与召唤到期还未执行，转换期限等于边界则已失效。未提供真实状态、队列不一致或观察尾部截断仍拒绝完整性，不用空对象代表缺失状态。

启用共享体力时，`StaminaRuntime.captureBefore(tick)` 先执行严格早于边界的恢复和待扣任务，再导出独立的 `shared-stamina-state-v1` 子状态。`resourcesAndHp.stamina` 保存来源模型、上限、实际共享量、下次可恢复的相对帧数及恢复基线/累计帧数；满池时规范已无未来影响的旧恢复历史。`pendingEvents.stamina` 保存同帧顺序和所有未执行费用，包含相对输入/到期帧、角色、金额、来源、零费用调用标志、队列次序及实际接受的完整命令。审计仍保留原始编号，相位比较不把每周期变化的绝对编号当作状态差异。边界帧本身的恢复、扣除和输入均尚未执行；待扣任务必须匹配真实接受动作，缺实际状态仍阻塞。未启用模型时不新增体力字段，保持九维 v2 原格式。

静态生命动作相位从同一次真实主队列读取 `healthChange`，关联实际 `actionLogIndex`、已接受动作和完整变化定义；核对来源角色、优先级2、施放及到期帧。`pendingEvents.inFlight` 保存相对到期/施放年龄、目标规则、完整公式输入、来源与真实 FIFO 顺序，不去重相同事件，也不把 `active` 提前固定为边界时的角色。`resourcesAndHp.hp` 继续来自实际共享 HP 状态；累计治疗/消耗与日志计数不影响未来执行，故不作为周期状态。只有实际 HP、接受动作和完整队列均提供时才解除该能力阻塞，schema 通过本身不构成完整性证明。

确定性周期实体检查点读取真实活实体与最近代次，收集在途旧tick及已排旧伤害引用的历史实体，保存相对代次、存活/取消关系、完整定义和原始命中快照。`actionPhase` 的输入优先级和自产事件顺序由同一主队列保留；有实体、在途任务或动作占用的接受动作，将真实HP/maxHP、完整条件和锁定结果写入 `lockedConditions`。不按当前HP重判历史分支，也不把所有代次身份抹去。没有声明时保持原检查点字段形状；有声明却缺实际状态或活实体缺下一tick仍阻塞，见 [实际导出范围](phase-checkpoint-runtime-state.md)。

普通附着首层以 `ordinary-aura-checkpoint-v1` 保存真实 raw gauge、衰减率、来源槽、物化年龄、实际附着ICD、直接伤害组窗口及自然消退调度读取的最新观察状态；只读捕获不推进引擎时间，也不使用已舍入的展示快照。全未来声明须属于普通持久单元素或水火/冰火域（可含物理），检查包括未选中的能力、默认属性所有者元素、休眠附魔和目标初始附着。原生 `aura-v7 + legacy-event-heap-v1` 的历史连续证据见 [首层专项](validation/ordinary-aura-phase-checkpoint-core.md)。

后续已支持目标时钟关闭的 `target-phase-v2`：保存真实待执行/已完成衰减去重键、阶段旗标及任务/Reactable.Tick前后快照，逐项核对主堆 `targetDecay`；原始Aura包含实际 `cached-boundary-v2` 生命周期缓存。主堆仍保存targetId、相对期限、优先级与FIFO；已执行当前帧、缺任务、重复键或截断尾段不能标为完整。仅排除无未来效果的过去阶段和审计游标，不能用空占位代替真实捕获。原生aura-v9在同一普通闭合域的合成连续运行已有period1、1250伤害/2秒=625 DPS证据；v8可走相同支持路径，但本次未单独运行v8。感电、冻结、激化、燃烧、剧变、反应实体/反应拥有任务、目标时钟、target-phase-v1/v3、特殊注入和随机/插件仍独立阻塞，见 [目标阶段增量](validation/ordinary-aura-target-phase-checkpoint-core.md)。

连续预热以共享 `action-pending-horizon.ts` 补足证明用尾段，涵盖扣能、召唤、体力、生命变化、全部候选条件命中，以及周期实体首个到达或越过到期的末tick、延迟伤害和产球旅行；用户请求的DPS观察窗口保持不变，周期状态不重置。完整确定性状态、重复未来输入与周期伤害均满足条件时可建立稳态，详见 [相位检查点实际范围与定向证据](phase-checkpoint-runtime-state.md)。共享体力的390帧延迟场景在1470帧真实连续运行中建立周期1；确定性 HP 的390帧消耗/391帧治疗场景在1471帧实际连续运行中建立周期1，合法时间线和旧式重复 rotation 均保留相同完整队列，原观察窗仍结束于1200帧。它们是固定声明的合成证据，不证明真实角色费用、治疗机制或任意未来输入。普通随机回能的概率/共享间隔/随机数状态、西风私有冷却/随机数状态，以及普通附着首层之外的生命周期、未导出触发状态、概率产球和随机暴击仍各自保留阻塞。久岐忍 E／E/Q、诺艾尔与当前安柏来源场景不会因普通Aura/伤害组、周期实体、锁定条件、转换、共享体力或生命队列已导出就自动成为完整稳态。实际窗口结果、逐击恢复与稳态证明分别报告；本次文档同步未运行检查，不由专项记录推定本轮构建或浏览器通过。

钺矛、苍纹角杯、冷寂迸音三把确定性独立追击另由真实 `weaponProcState` 和主队列导出 `icdAndTriggerHistory.weaponProcs` 及待执行命中。冷却到期与边界相等时保存剩余0；已过期和从未触发才规范为就绪。待命中保留实际属性、增益快照、目标几何、优先级和FIFO，包括边界已到期但触发时仍有效的增益。动态日志身份只规范为稳定角色/武器身份，不抹去不同快照或目标顺序；无模型时不增加字段，声明而缺实际状态仍阻塞。共享尾段仅为对应持有者的适用宿主命中增加真实交付的1帧，不给粒子或生命任务盲加延迟，也不额外等武器600/900帧冷却。原生v9和target-phase-v2的普通水火域三武器连续场景已建立周期1，详见 [追击检查点](validation/weapon-proc-phase-checkpoint-core.md)。新增五把的随机流与待执行延后回调仍未完整导出，R5霜葬也不例外；这些旧证据不解除它们或其他反应域、随机、目标时钟的独立缺口。

笛剑、以理服人、流月针、竭泽的真实生命周期及待执行回调已另行纳入确定性检查点：保存有效音符/次数、各类剩余期限、父命中与FIFO，以及已排追击的原始属性、几何和触发前后历史状态。过期计数只有在已证明下次合法事件必重置时才归一，源日志不随之清零。实际32秒闭合合成输入建立周期1、1880伤害与58.75 DPS，边界竭泽历史+200ATK仍产生480伤害并经完整JSON恢复差0，详见[四状态专项](validation/stateful-weapon-proc-checkpoint.md)。这不解除五把随机追击或其他未导出状态的限制。

该用例发现并修复了合法时间线固定增益字段错配。新合法运行记录`flatStatBuffSemantics: "canonical-v1"`，把`atkFlat/hpFlat/defFlat`映射到实际属性的`flatAtk/flatHp/flatDef`；当前结果和捕获回放保留该标记。旧当前结果缺标记仍按历史读法解释，解析不能自行补标记；冻结旧格式拒绝标记，legacy行为保留。固定面板属性修复不等于动态最大生命或生命池机制完成；来源样本的运行时间与当时源码指纹也不因此成为最后一次修改后的证明。

## 有限随机起步与 W／2W 观察窗

`analyzeStochasticStartup(config, policy, options, controls)` 返回 `stochastic-startup-v1` 的 `completed-diagnostic`，与上文确定性稳态证明保持独立。`sampleCount` 默认为8、范围2–32；`warmupCycles` 默认为5个配置周期，作为W。每个种子从零能量和满能量分别运行一条真实连续轨迹，运行总长为 `2W + 原配置duration`，上限600秒，共2N条最终轨迹；合法时间线仍经过原来的延展与来源契约。两次观测之间不重置能量、冷却、增益或在途事件。

核心在每条轨迹读取 `[W,W+duration)` 与 `[2W,2W+duration)` 两个整帧半开窗口，允许重叠。四组结果是零／满起步各自的W／2W；四项比较先逐种子配对求差，再汇总零起步的2W−W、满起步的2W−W、W时满−零、2W时满−零。窗口不是额外独立样本，动作分叉后同种子也不保证同一随机抽样对应同一命中。

伤害直接调用 `measureDamageWindow()`，DPS以完整观察窗秒数为分母。边界能量取边界帧全部事件发生之前的实际值；右端事件不计入该窗。正耗能请求包含成功行动与被拒绝请求，能量不足和其他合法性拒绝均计入失败，能量不足另列子集且不会在两份日志中重复计数。无请求时失败率为 `null`；有请求时每次运行先计算失败率，再汇总各次运行的均值，不合并请求数掩盖不同轨迹的差异。配对率差任一侧缺值则不计该对，保留实际有效样本数。

每组伤害、DPS、逐角色起末能量、请求数、失败数及失败率都区分经验p05/p50/p95与均值区间。经验分位数按排序下标 `(n−1)p` 线性插值；95% Student-t近似均值区间使用 `平均值 ± t×样本标准差/√n`，样本方差分母n−1，df1–31的临界值保留NIST原表三位小数。单样本不生成区间，无有效样本为null。均值或配对差的近似正态、跨种子独立是假设，小样本、偏斜分布和离散失败率可能使区间不可靠；失败率区间不裁剪到0–1，多指标未做同时覆盖校正，不设置p值通过阈值。

导出保留原配置与内容哈希、实际运行选项、窗口政策、随机算法和各种子、逐运行manifest、原始窗口数值与配对差；首个种子的零起步保留完整代表轨迹及详细公式，其余不将完整轨迹装入统计报告。现有随机暴击审计仍可在内部产生必要捕获，不据此声称所有运行都没有完整命中数据。Worker可报告0至2N的进度和终止当前任务；网页展示核心返回的统计和代表日志，不自己重新计算伤害或置信区间。

启用西风时，同一连续轨迹保留其独立冷却和随机数状态，两个窗口之间不重置；报告的 `randomness.favoniusPolicy` 记录实际策略。代表轨迹仍展示西风真实抽样、产球和能量拾取，未把解析期望暴击当成触发事件。此支持不意味着西风私有状态已进入确定性相位检查点。

区间包含零、样本方差为零或零／满起步均值接近，都不证明完整状态分布收敛。主模拟器只能部分汇总的运行会拒绝生成完整诊断；独立特殊反应包络、插件私有状态及除已接入西风外仍未映射的暴击反馈，不因该入口存在而补齐。统计来源、边界和实际聚焦检查见 [随机起步核心记录](validation/stochastic-startup-core.md)；最终集成状态仍由 QA 报告记录。
