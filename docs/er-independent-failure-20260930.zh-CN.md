# 充能无解原因与可复核证明（120）

本批落实主提示 §20 中“报告堆多少充能都无法解决的情景”。原先结果类型和界面虽有 `er-independent-failure`，求解器没有产生此状态的分支；现在只在取得充分证明后返回它，同时保留具体指令、公式、变量说明、数值代入、前提和实际执行证据。

## 实际变化

- **耗能超过容量**：先观察到固定动作的真实能量拒绝，再使用与执行器共用的 12 位小数量化和 `1e-9` 比较误差，验证费用超过角色固定容量。初能、粒子和固定回能均受容量上限约束，因此提高 ER 无法解决。排除会替换占位能力的动态普通攻击链，不以静态费用冒充实际费用。
- **全部耗能动作成功后，严格轮转仍非法**：重新编译不含能量拒绝的成功路径；其固定冷却、动作重叠、前台角色、状态、体力或时长约束仍失败，就无法完整执行原轮转。任何能量拒绝已使完整轮转目标失败，剩余成功路径也失败，故结论不依赖外推网格。动态战技冷却、星旋腾空反馈和插件不进入这类证明。
- **中文界面和导出**：分析面板直接展示证明，动作编号按用户习惯从 1 开始；JSON 保留从 0 开始的实际指令索引、原始拒绝记录及候选重现键。Worker 沿用现有结果传递，完整配置和运行选项随分析报告导出。

执行器的能量比较没有改变，只将相同精度函数和常量移到共用模块。求解继续枚举有限网格，不引入二分搜索或单调性假设。没有粒子、某组候选全失败或机制尚不完整，都不会单独得到“任何 ER 均无解”。无效输入继续返回 blocked；抛出异常而没有模拟结果时，只保存真实异常证据，不编造伤害和重现键。

主要文件：`packages/sim-core/src/er-independent-failure.ts`、`simulation-analysis.ts`、`energy.ts`、`simulator.ts`，以及 `apps/web/src/analysis-panel.ts`。Luna 负责界面和单个浏览器用例；独立审阅负责证明条件核对。独立单击／完整技能计算器、两档配装和队伍编辑入口保留。

最终覆盖 4 个不同核心用例：容量与误差边界、全部成功路径的冷却冲突及动态反馈排除、体力失败、既有动态粒子／安全裕量／无产球有限结论。冷却案例分别经过返回真实失败结果和抛出真实时间线异常两条路径；异常路径没有伪造候选回执。没有运行全套测试、角色矩阵、性能套件、Go/WASM 构建或数据刷新。

页面采用明确的合成配置：2 秒窗口、角色容量 60、初能 60、动作耗能 61。100% 和 200% ER 两个候选各真实产出 1 个同元素粒子，原始粒子能量均为 3；Q 在第 2 帧以可用能量 60 / 费用 61 被拒绝。证明实际代入为 `61 > 60 + 1e-9 = 60.000000001`。两候选伤害均为 427.5，仅来自前面的合成 E；并非真实角色或游戏伤害验证。

候选重现键分别是 `gdl-v2-fnv1a32-76943707`、`gdl-v2-fnv1a32-9965dee2`。导出的证明引用首个候选的同一重现键和指令索引 1；界面显示第 2 条动作。完整证据见[浏览器导出](validation/er-independent-failure-browser-20260930.result.json)、[测量与执行记录](validation/er-independent-failure-measurements-20260930.json)。

## 剩余边界

两类证明是充分条件，不是所有无解情景的完备判定。其他情景保留有限网格或 blocked 结论。本批针对本地 TypeScript 求解器，没有给固定来源 Go/WASM 增加 ER 逆向求解，也没有新增原生稳态或随机分布证明。

正式／预览数据文件哈希与 119 批相同，没有数据晋升或新增游戏 verified。更多完整技能／资源和共享状态、原生相位收敛、7.2 V1 来源映射及许可证据、远端更新工作流实际运行仍未完成。全量 goal 保持 active，不能因本项交付而标记全部完成。
