# 来源辅助公式：治疗、冷却、减抗与护盾强效

本轮把固定来源 b4、a7 中若干辅助数值交给共享公式 AST 和可编辑捕获流程；两份来源仍属固定第三方源码的 provisional 实现依据，不代表游戏实测或官方规则验证。Go 宿主继续负责状态读取、触发条件、目标/受益者、持续时间、队列及实际状态变更。此批不调整游戏数据或已验证覆盖的统计分母。

## 实现范围

- 治疗：`source-host-healing-formula.ts` 按原调用顺序拆分基础量、治疗加成、原始治疗量、生命之契抵扣后的实际治疗及过量治疗。绝对治疗不读取 MaxHP；百分比治疗使用计算基础量时实际读到的 MaxHP；抵债和过量治疗各自保留后续独立读取。捕获与页面允许编辑对应数值并导入/导出 JSON，原始捕获保留。Go 仍执行属性 getter、HP/债务变更和事件派发；独立编辑不会重新运行这些状态读取。
- 冷却：`source-host-cooldown-formula.ts` 覆盖持续时间乘冷却倍率并向零截断、由 worker 起始帧/队首时长/当前帧计算剩余时间，以及队首剩余值减去缩短量。原生充能队列、worker 调度、触发来源和重置分支仍由 Go 执行；`reduction >= remaining` 时 Go 走原重置路径。b4 与 a7 的可用充能/空队列提前返回规则分别保留。页面的独立编辑器只重算捕获的数值步骤，不模拟队列。
- 圣遗物辅助标量：共享注册表含 8 条数值规则，涉及 5 套：少女四件治疗加成 +20%；逆飞两件护盾强效 +35%；千岩四件护盾强效 +30%；深林四件草抗 −30%；翠绿四件冰、雷、水、火抗各 −40%。数值只在固定源码的既有治疗加成回调、护盾回调或减抗修正创建点调用共享公式。触发、受益者/目标、到期及修正实际消费仍由 Go 决定；减抗捕获保留来源持有者、创建帧、目标和元素元数据。

## 保留的源码边界

治疗补丁保留 Go `ReceiveHeal` 中的 TODO：尚未证实同一次治疗清除生命之契债务后，剩余治疗是否会立即恢复 HP；源码示例以债务 10、治疗 11 得到 1 点治疗。百分比治疗之外的未知 HealType 按原 switch 零基础量处理，不推断其效果。角色覆盖方法若绕过模板路径，也不能由本共享公式自动覆盖。

护盾源码仍有 hitlag TODO：通用护盾强效读取注释指出其可能应受 hitlag 影响，千岩回调处也保留同类 TODO。本补丁记录实际读取及闭包结果，不改变该时序假设。冷却的 modifier 条件、到期清理、worker 与版本差异同样不由独立算式复演。以上固定源码数值不证明游戏内触发、数值或时序。
