# 基准、比较与能量分析

2026-09-28：来源队伍新增八项执行方案选择与 source-host-batch 连续观测窗。Practical 复用 GCSim `frame_defaults=human` 的8/5值；Ideal全零及Conservative12/8为工具政策/假设，不构成 KQMS 要求或合规认证。预热双窗在每个 seed 的单次连续运行内取样，先计算同 seed 差再跨 seed 汇总；重新分析已保存轨迹不触发新运行。Classic/a7构建与有限页面实测边界见[来源执行方案报告](source-profiles-observation-windows-20260928.zh-CN.md)。

本次实现位于 `packages/sim-core/src/benchmark-profiles.ts` 和 `simulation-analysis.ts`。这些是可直接执行、由测试覆盖的核心 API；它们不会把未核验角色数据升级成真实游戏结果。第二轮接入了 `/rotation` 的真实请求延迟方案，以及 `/results` 的窗口、Worker ER求解和连续预热启动分析；浏览器验收以QA记录为准。

## 命名且有版本的基准

两个配置版本均为 `1.0.0`，结果调用者可保存完整配置、假设及比较签名。

| 控制 | `legacy-110-zero-120s` | `kqms-inspired-custom` |
| --- | --- | --- |
| 显示名称 | 旧基准 · 110级单目标 / 零能量 / 120秒 | KQMS 启发 / 自定义（非合规认证） |
| 默认观察时长 | 120秒 | 90秒 |
| 目标 | 1个、110级、基础抗性10%、无防御调整 | 1个、100级、基础抗性10%、无防御调整 |
| 起始能量 | 零 | 满；仍逐次扣除大招能量 |
| 暴击 | 解析期望 | 解析期望 |
| 外部/击杀产球 | 不注入 | 不注入；偏离KQMS的gcsim掉落配置 |
| 角色面板/产球/动作/轮转 | 保留输入，不推断 | 保留输入，未自动符合KQMS配装及延迟要求 |

`applyBenchmarkProfile` 返回新配置及运行选项，不修改原对象，不改变 `cycleLength` 或自动补写重复命令。它重设目标基准，清除原目标的阶段、移动和覆盖值；保留已有单目标的ID、位置、碰撞尺寸，并把处理写入 `assumptions`。多目标场景拒绝直接套用单目标基准，避免默默删除目标。若输入具有初始附着，保留并明确告知。

角色动作内已有的产球和固定回能不会被擅自删除。当前旧格式没有可审核的“外部/击杀/角色技能”来源枚举，所以“无外部产球”仍要求核对输入来源，不能仅凭来源名称认证。配置包含这一必要声明。没有任何隐式循环回能或无限能量开关。

产品时长控制包括 **15、18、20、60、90、120秒**及自定义整帧时长。默认120秒是用户指定旧基准，不是“统一社区标准”。观察时长、期望轮转长度和实际执行时间是不同量。合法时间线只运行已有指令；把观察窗口拉长不会自动变成持续作战。

## KQMS依据及偏离

本次读取的 [KQM Calculation Standards](https://compendium.keqingmains.com/)自报2.0.2、2024-05-03，取证见 [来源核查](./research/source-verification.md)。其默认角色/武器90级、天赋9（适用时+3）、特定命座/精炼/投资、满HP及满大招、100级10%抗性目标不等同于只修改敌人等级。其gcsim条目还要求至少90秒、1000次迭代、规定的执行延迟和掉落。

本配置没有重建上述全部配装、HP、1000次迭代、Kolibri延迟分布、能量掉落及目标尺寸/位置。因此代码内的 `compliance` 固定写为 **KQMS-inspired/custom**，并包含逐项偏离声明。用户选择更短窗口也会单独记录默认时长偏离。

## 比较签名

`createComparisonSignature` 把数据版本/渠道/快照、机制根、观察区间、能量及暴击模式、目标、配装、动作、轮转、位置、初始附着、执行方案、圣遗物投资、外部能量假设及种子写入签名。完整结构保留在 `fields`，FNV散列仅用于变更检测，不是密码学认证。

`compareSimulationSignatures` 列出逐字段差异，不把不同持续时间、目标或能量场景混成一个排名。预览、official-next、合成、未知来源、未核验或机制截断结果均不能进入“已验证排名”；缺少圣遗物投资或关键声明也阻止该标签。来源核验状态是调用方给出的证据声明，不能靠把字符串改为 `verified` 代替取证。

## 时间窗口

`measureDamageWindow` 直接聚合模拟器的原始 `finalDamage`，区间严格为 **[startTick, endTick)**。左端包含、右端排除，不重复加入子反应事件，不使用UI四舍五入值。DPS分母为完整窗口秒数，包括空转，另报主目标与全部目标伤害/DPS。所选窗口必须在已模拟范围内；不能外推末次攻击后的持续伤害。

`summarizeRotationExecution` 另分开请求周期、已观察区间、实际输入占用终点及来源命令的尾段归属。完整轮转窗口涵盖输入前／中间空转和已声明尾段，分母为完整半开窗口；输入占用秒数另列，不拿末击时点或施放时长冒充团队DPS。未执行、拒绝、观察不足或未捕获完整尾段时不提供伪造完整轮转。此派生摘要随模拟记录导出，导入仍重跑原始输入。本批接线尚待统一验证。

## 有界ER求解

`solveEnergyRecharge` 仅接受严格合法时间线及确实存在的耗能动作。它逐点修改指定角色的ER面板，通过原 `simulate` 重跑，从最低值到最高值**穷举整个有限网格**；不使用二分、不预设单调性，不同时更换装备、动作或其他词条。ER用比率表示：`1 = 100%`。

每个点返回是否所有指令成功、失败指令与原因、伤害及重放键，并保留实际请求／接受的耗能动作、真实粒子及固定回能证据；结果保存边界、步长、种子、起始能量及观察时长。第三参数 `controls.onProgress` 按真实候选完成回报进度；传出的候选是复制品，不能通过进度监听修改数值结果。该核心可在Worker运行，取消由终止Worker执行。`observedGridMonotonicity` 仅是已检查网格的观察，不证明网格间或边界外的单调性。用户指定的加法安全裕量必须实际重跑；超出边界或重跑失败就不返回已验证推荐值。

返回状态分别是：

- `feasible-on-grid`：给定窗口、种子和网格上存在可行点；不是连续实数最小ER，也不是无限循环证明。
- `infeasible-within-bounds`：只有本次有限范围不可行，不能声称任何ER都无效。
- `er-independent-failure`：历史兼容值；当前求解器不再仅因静态技能表没有产球便输出该结论。西风等动态来源必须按实际执行证据计算，有限网格不证明任意ER都无效。
- `blocked`：输入不适用、目标未定义、模拟拒绝或超过评估上限；没有伪造零值结果。

合成验收场景只有一枚同元素、前台粒子：`原始能量 = 3 × 1 × 1 = 3`，大招需要6点，因此 `3 × ER ≥ 6`，网格最小值是 `ER=2`；`+0.25`裕量在2.25处另跑通过。这是合成数学/执行测试，不是某个真实角色最低充能建议。

## 稳态判定边界

`evaluatePhaseAlignedSteadyState` 是可重用的确定性检查点评价器。它要求完整状态维度：能量、冷却及充能队列、增益/减益、实体、附着、特殊资源/HP、ICD/触发历史、待执行事件、前台角色/动作相位。调用方须提供相位相对计时器，不能比较绝对时间戳后随意丢弃差异。

默认同相位周期、绝对容差 `1e-8`、3次确认、最多4周期周期性、100周期预热上限；检查所有中间相位及每段周期伤害，允许2周期等多周期状态。成功状态明确为 `established-for-supplied-checkpoints`，即只对给定完整检查点成立。随机状态、缺失维度、错位检查点、伤害不稳定或预热范围不足都返回 `not-established`。

第二轮把判定器接到模拟器真正生成的 `executionAudit.phaseCheckpoints`。生产者 `nonreactive-phase-state-v1` 在指定帧**所有事件执行之前**捕获能量、技能充能/冷却、增益、在途命中快照与粒子、HP/时间线状态、触发冷却、前台/动作占用和完整待执行事件；相对计时器保留，同周期未来输入只在逐项验证重复后折叠。后续已补普通闭合 Aura、受支持目标相位以及确定性武器状态的真实捕获；只有未导出的具体 Aura／反应生命周期、目标时钟、插件私有状态、直接伤害组及随机流仍阻断。不能给缺失维度填空数组冒充完整，亦不能继续一律拒绝全部 Aura。适用域以当前检查点返回的完整性状态与原因列表为准。

`evaluateSimulationSteadyState` 只接受生产者标记完整且没有缺失维度的实际检查点，成功返回 `established-from-simulation`。调用 `simulate()` 却未请求检查点仍返回 `not-established`。周期DPS相近或能量曲线稳定并不能绕过该门槛。

`simulateWithStartup(config, policy, runtimeOptions)` 支持full、zero、configured、逐角色custom，以及steady-state。稳态模式在**一次连续模拟**中先执行有限预热，再测量指定窗口；不把预热后的能量拷贝到一个其他状态已重置的新模拟。合法时间线通过原编译器解析后按显式起点重复，保留循环间真实空转；序列长于周期或循环末前台不闭合会阻断，不自动补换人。预热及完整观测尾段受现有600秒上限约束。

检查点取预热末尾的有限确认区间，不把初始设置或早期尚未稳定的队列当作后续周期状态；原始起步动作、失败、到球、能量仍保留在完整返回结果中。观测区间为 `[warmupTick, warmupTick + requestedObservationTick)`；若为了检查至少两个完整未来输入周期或跨周期在途事件多运行一段尾部，这段不进入观测总伤。返回完整模拟、实际测量窗口、起步政策及边界能量，导出可重放。若未收敛，窗口伤害仍可检查，但不能标成稳态DPS；若观测窗口仍有大招失败，也会明确说明“周期状态相等”不代表所要求轮转全部可执行。

真实执行测试：同元素前台1粒子、ER2、能量上限6、大招消耗6，每2秒一循环。零能量启动，预热6循环，再观察1循环；整次执行8次产球并花费48能量（含不计入观测DPS的验证尾段），边界能量始终0，最后5个真实检查点证明周期1，观测中1次伤害，状态求出的DPS等于观测窗口DPS。没有循环补能。另一个150帧飞行时间案例在最初第2/122帧真实缺能失败，此后实际在途粒子建立了完整重复状态；失败仍保留，未被满能量补齐。随机粒子场景及非闭合前台场景分别被正确拒绝稳态认证和隐式重置。

## 执行延迟方案

新增 `execution-profiles.ts` 的 `applyExecutionProfile` 使用同一个合法时间线编译器确定原起点，再将人为延迟加在**后续行动请求的atFrame**上。技能定义、取消窗口、动画、命中、产球、冷却和增益/实体寿命完全不改；没有伤害或DPS固定百分比折扣。严格模式原本非法的时间线仍报错；原有auto-wait模式保留其明确等待语义。

| 方案 | 技能/移动/拾取请求 | 换人请求 | 接技能后的闪避/跳跃/换人取消额外延后 |
| --- | ---: | ---: | ---: |
| idealized-input | 0f | 0f | 0f |
| practical-assumed-input | 2f | 6f | 4f |
| conservative-assumed-input | 6f | 12f | 8f |
| custom-input | 用户指定0–600f | 用户指定0–600f | 用户指定0–600f |

这些是版本1.0.0、60FPS参考下的明确工程假设，不是实测人群分布或KQMS合规方案。输出保存完整方案、版本、假设、原起点、延后请求及逐次累积延迟。原有显式wait保留；原始配置不被修改，重复点击不会在已经延后的副本上继续累加。

实际执行测试中，原命中帧 `[4,26]` 变为 `[6,40]`，第一技能的合法换人取消点仍是出手后10f；用户换人请求较晚到来。产球仍在技能出手后5f、飞行20f，增益仍持续30f。这证明变化来自输入时刻，而不是篡改游戏计时器。

## 随机与性能证据

传统暴击模式为 `noCrit`、`allCrit`、`average`；第二轮增加独立的 `execution.criticalSampling='seeded-random-v1'` 真实暴击采样，具体执行和限制由模拟桥接文档记录。比较签名按实际运行选项记录是否启用暴击随机、独立流算法、种子及抽样计数，不能仍把所有运行写成“没有暴击采样”。粒子数量和适用场景的结晶碎片/草原核位置保持独立随机来源。

第一轮性能历史快照见 [simulation-benchmark.md](./cross-validation/simulation-benchmark.md)及其JSON；当时没有trace开关，其 unsupported 结论只适用于该快照。第二轮的 `execution.detailedTraces` 控制完整公式追踪生成，关闭后仍保留模拟事件与必要审计成本。[当前真实开关/随机暴击基准](./cross-validation/simulation-execution-benchmark.md)各运行12次：关闭轨迹中位数30.500ms、开启129.735ms、随机暴击29.397ms；开启轨迹的中位数超过100ms，不隐瞒为达标。两个确定性模式的269个伤害事件逐字节一致；轨迹分别为0与4842个节点。真实随机暴击每轮263次抽样、6个不可暴击事件不抽样；12个种子产生12个不同总伤害，首种子完整重放一致。数字只对应报告中的源文件快照和Apple M5 Max/Node环境，不把旧数字冒充新实现测量。
