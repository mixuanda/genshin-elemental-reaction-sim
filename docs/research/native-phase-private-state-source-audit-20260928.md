# Native phase private-state source audit (2026-09-28)

Scope: source-host [079-phase-private-state.patch](../../packages/source-host/patches/079-phase-private-state.patch) against the pinned classic GCSim revision `b4ae769d7c1c1bce68fce5faf0b460c5b5b7f541` and stellar revision `a7dc4bf4f5e18390035ca0333fb6eb1d5fac32bd`. These are **native simulator implementation** observations, not independent game-mechanics verification.

The source keeps each concrete character in `CharWrapper.Character`, each constructed weapon in `CharWrapper.Equip.Weapon`, and each artifact set in `CharWrapper.Equip.Sets` ([character.go](https://github.com/genshinsim/gcsim/blob/b4ae769d7c1c1bce68fce5faf0b460c5b5b7f541/pkg/core/player/character/character.go), [core.go](https://github.com/genshinsim/gcsim/blob/b4ae769d7c1c1bce68fce5faf0b460c5b5b7f541/pkg/core/core.go)). The patch reads these retained objects with reflection. It records scalar, struct, array, slice, map, pointer, and alias state without invoking gameplay getters or writing to the source runtime. Embedded `template.Character`, `CharWrapper`, and `Core` pointers refer to the separately captured shared providers; template and wrapper references carry the directly read character index. Pointer addresses are used only within a single snapshot to identify aliases and are never emitted. Non-scalar map keys, unsupported pointer graphs, non-nil functions, and unreviewed private numeric clock semantics yield explicit coverage gaps. Existing event/task/modifier callback-capture gaps remain even when the weapon or set object itself is captured; for example, [Foliar Incision](https://github.com/genshinsim/gcsim/blob/b4ae769d7c1c1bce68fce5faf0b460c5b5b7f541/internal/weapons/sword/foliar/foliar.go) keeps `procCount` in an event closure, not in its retained `Weapon` object.

The only generic numeric exceptions are source-reviewed initialization values: [Amber](https://github.com/genshinsim/gcsim/blob/b4ae769d7c1c1bce68fce5faf0b460c5b5b7f541/internal/characters/amber/amber.go) initializes `burstRadius`, [A1](https://github.com/genshinsim/gcsim/blob/b4ae769d7c1c1bce68fce5faf0b460c5b5b7f541/internal/characters/amber/asc.go) changes it during `Init`, and [Burst](https://github.com/genshinsim/gcsim/blob/b4ae769d7c1c1bce68fce5faf0b460c5b5b7f541/internal/characters/amber/burst.go) reads it as an area radius. [NoEffect.Index](https://github.com/genshinsim/gcsim/blob/b4ae769d7c1c1bce68fce5faf0b460c5b5b7f541/internal/weapons/common/common.go) is the player slot assigned by `SetIndex`; it is not a frame stamp. Other private numeric values remain gaps until their clock semantics are reviewed.

Venti has one narrower complete private-state case. [NewChar](https://github.com/genshinsim/gcsim/blob/b4ae769d7c1c1bce68fce5faf0b460c5b5b7f541/internal/characters/venti/venti.go) leaves six own fields zero: `qPos`, `qAbsorb`, `absorbCheckLocation`, `aiAbsorb`, `snapAbsorb`, and `c4bonus`. [Burst](https://github.com/genshinsim/gcsim/blob/b4ae769d7c1c1bce68fce5faf0b460c5b5b7f541/internal/characters/venti/burst.go) initializes the Q fields, while the C4 setup in [cons.go](https://github.com/genshinsim/gcsim/blob/b4ae769d7c1c1bce68fce5faf0b460c5b5b7f541/internal/characters/venti/cons.go) initializes `c4bonus`; [Skill](https://github.com/genshinsim/gcsim/blob/b4ae769d7c1c1bce68fce5faf0b460c5b5b7f541/internal/characters/venti/skill.go) does not write them. The patch therefore emits a dormant-state receipt only when **all six fields are exactly zero** and the shared template's character index is readable. Any Venti state after those fields change falls back to the generic reflector and retains its numeric/closure gaps. In particular, it does not reinterpret `Snapshot.SourceFrame` as a relative timer or infer Q state from a label. The source's skill `HitWeakPoint: true` is a native implementation fact and does not establish game accuracy.
