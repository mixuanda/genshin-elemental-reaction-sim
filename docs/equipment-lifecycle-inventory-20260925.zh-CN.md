# 装备生命周期覆盖清单与共用实施族

本清单审阅现有生产模块、固定 gcsim `b4ae769d7c1c1bce68fce5faf0b460c5b5b7f541` 以及仓内固定 Optimizer／目录来源。它整理的是已有可审阅来源、但尚缺实际事件执行的规则族，不把只有说明文字的新武器列作已证机制。成员栏用于明确范围，不是全装备覆盖率统计分母。当前角色／装备总数以生成状态页为准。

主提示要求真实等级／精炼／件数、可执行被动、独立来源与覆盖状态。`game-data` 的显式有效层数、窗口或已发生次数输入可以支持独立单击；这不证明模拟器能生成这些状态。反过来，部分旧条件模块仍写“未自动执行”，但实际运行时已在后续批次接入；本清单以当前运行时和中央调用为准，不能直接汇总旧 blocker 文案。

## 已有自动模块，不重复实施

- 西风、讨龙、祭礼：真实暴击粒子、切人转授、技能冷却／充能重置，各有实际日志与来源限制。
- `weapon-proc.ts`：独立伤害追击及其延迟、次数、状态和目标回放；昭心仍有固定来源系数／概率冲突。不能把所有旧装备条件文件里的“追击未执行”当当前全局事实。
- `artifact-runtime.ts`：流放者、学士、赌徒与烬城二件套的实际能量／冷却事件。
- `artifact-damage-runtime.ts`：余响的概率／窗口、昔时的治疗记录／转化／次数消费。
- `artifact-buff-runtime.ts`：宗室、教官、饰金、谐律、乐园普通绽放、辰砂六套的实际触发与状态。
- `lunar-artifact-runtime.ts`：已选择的如雷、乐园和晓歌月曜条款。它不等于所有月曜、星辉装备被动已经接入。

## 本批落地：13把命中叠层条款

新增 `weapon-hit-stack-model/runtime/text/trace`、独立 `weapon-hit-stack-replay` 及正常队伍控件／账本；[归档清单](../packages/game-data/sources/weapon-hit-stack-lifecycle/manifest.json) 保存实际原文件与 SHA。中央配置、普通模拟、JSON 完整性和阶段检查点已接，尚待根任务统一检查，不能把生产代码落盘当成通过验收。

- 宗室五把：非零本人伤害；实际暴击先清层且保留原ICD；未暴击只在18帧来源ICD结束后加层，上限5。没有前台门或层数期限。R1–R5每层CR为8%–16%。
- 金璋皇极四把：本人前台真实敌方伤害，18帧ICD，上限5，整组480帧刷新。每层ATK为4%–8%，实际Stats读取时受盾才翻倍。常驻护盾强效不由本叠层模块重复加入。
- 试作斩岩／白影：本人前台普重命中，上限4，整组360帧；ICD分别18／30帧；每层ATK与DEF分别为4%–8%／6%–12%。`StatModIsActive` 与 `StatusIsActive` 在固定源都是同一个 `modIsActive`，白影不能只因函数名字不同被误判为检查不到Status。
- 和璞鸢：本人前台命中，18帧ICD，上限7，360帧刷新；每层ATK3.2%–6%，满层另12%–24%伤害加成。
- 铁蜂刺：本人前台非物理伤害，60帧ICD，上限2，360帧刷新；每层6%–12%全伤加成，已有窗口可增强物理伤害。

所有实际层数、到期帧与属性贡献由同一 AST 执行和解释；没有UI算术。真实 `stats-sample` 在到期帧删除属性modifier，普通存在性查询在到期帧仍包含等号。只读 `peekValues` 不修改源状态。`captureState/restoreState` 保留私有层数、属性窗口和ICD，来源配置身份不能换武器或精炼后沿用。

中央把新属性应用于后续真实取样，不能追溯改写已有快照；宗室需要真正的随机／强制暴击结果，解析期望只产生 `actual-critical-required`，不得静默当作未暴击。金璋皇极需要玩家盾模块返回实际受盾资格。无角色卡肉的固定来源配置、贡献者与日志仍须明显标为 source-assumed。已接中央、结果完整性、检查点与正常 UI 模块；主界面挂载及必要验收由根任务统一执行。伤害回调按 `pkg/enemy/attack.go` 保留同帧延迟任务，普通直接伤害与经典剧变均产生实际回调；宗室剧变反馈为非暴击。

本批未运行测试、构建、外部模拟或数据覆盖生成；源文件复制与SHA仅用于保存证据，不是新的通过结论。
