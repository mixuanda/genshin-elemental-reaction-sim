# 角色与武器基础属性推导

装备入口位于独立计算器。选择有可执行命中定义的角色后，可选择匹配的武器、双方等级与突破、合法精炼、五个槽位的圣遗物，以及明确启用的装备效果；点击“以此基础配装替换当前面板”后使用同一计算核心。导入最终面板不会被自动追加装备数值。

本次实现从运行时活动快照读取固定来源目录及同一快照的精确等级曲线（当前为 `genshin-db 5.2.14`、7.1 released，固定提交 `49a6544a6c6ae36089cb42fa591fc46f01de8bcf`），不通过插值补足数据。角色与武器的基础属性按 `基础值 × 该等级曲线值 + 突破加值` 计算；武器副属性按 `基础副属性 × 该等级曲线值` 计算。角色突破属性、武器副属性与角色基础暴击属性分别保留来源。攻击、生命、防御的固定与百分比贡献、精通和暴击进入对应面板；元素／物理增伤只用于相符的普通伤害，治疗加成和充能加成单独保留。

角色、武器、等级、突破、精炼、圣遗物强化档位、效果启用状态、条件输入、来源版本、原始基础值、曲线值、突破加值及停用效果假设进入计算 JSON。共享核心再次执行来源公式并生成结构化轨迹，最终面板使用未舍入结果。示例来源数值：90 级满突破神里绫华基础攻击力 `342.0250874`，90 级满突破黎明神剑基础攻击力 `401.2935898`、副属性暴击伤害 `0.468588`；黎明神剑 R5 被动只在明确启用且已提供满足条件的生命比例时增加暴击率，恰好 90% 的来源冲突单独列为阻塞。

等级与突破必须匹配。20/40/50/60/70/80 级突破前后是独立选择；一、二星武器按实际来源上限限制，不能一律升到 90。降临之剑等只有 R1 的来源记录不会补造 R2–R5。来源虽有角色 91–100 级曲线，但突破表上限为 90，相关解锁条件未映射，因此本入口阻塞 91–100 级，而不是仅凭曲线存在认定可装备。

圣遗物使用 [genshin-optimizer 固定提交](https://github.com/frzyc/genshin-optimizer/tree/180a0a1015cb725c7570cd828eb086749960df98/libs/gi/stats/Data/Artifacts) 的一至五星主词条等级表和副词条档位表。原始文件、MIT 许可及 SHA-256 位于 `packages/game-data/sources/artifacts/`；没有运行时网络请求。槽位、套装允许星级、等级上限、初始副词条数量、主副词条互斥、四条词条解锁前必须新增词条、总强化次数都参加实际校验。每次副词条档位都是一条有来源的数值贡献，共享核心逐项求和；不会用显示面板反猜强化历史，也不会把未知档位填为零。

圣遗物编辑器可装备 0–5 件，显示每项精确主词条及副词条档位。选择新套装时给出明确显示的 +0 低档位配装默认值；“合法低档位示例”按钮生成的是可编辑配装示例，不声称是用户的实际掉落记录。升到 +4/+8 等强化节点后，必须提供对应新增或强化档位才能应用。

已映射的武器与套装条款见 [基础装备效果](equipment-effects.md) 与 [属性转换、阈值及叠层公式](equipment-formulas.md)、[常见四件套条件规则](artifact-conditional-effects.md)、[装备反应系数与敌人减抗](artifact-reaction-effects.md)、[新增武器条件规则](weapon-conditional-effects.md)。支持的转换与叠层只生成公式树，由共享核心执行，界面不预先算成平值。明确启用的已支持条款缺少必要条件时拒绝应用；关闭的效果仅记录停用假设。伤害加成按元素、攻击标签和武器类型资格逐段执行；不能把普攻加成算进元素战技，也不能把普通增伤算进所有特殊反应。新配置用 `bonusAccounting: core-sourced-v1` 表示来源增伤由共享核心结算，避免 UI 和核心重复追加；旧文件没有该标记时沿用已输入的逐命中加成约定。

目前仍是**暂定、有条件的配装**：C0、停用角色被动与命座，仅执行明确启用的已映射装备条款。动态武器／套装触发、持续时间、自动层数生成／衰减、追击、其余套装规则以及独立游戏验证仍有缺口；这些缺口随结果列出。源表按原始小数在 binary64 中运算，未宣称所有游戏 float32 舍入与显示细节完全一致。目录统计不是可完整模拟角色／装备数量。7.1 的发布身份与数值／机制证据分开记录；本模块仍标为暂定，不能把 released 当作全部数值或机制已独立验证。三把任务专用试用刀（11419、11420、11421）不允许在常规配装中使用，普通笼钓瓶一心（11416）保留。

专项测试覆盖精确数值、突破边界、武器类型、受限精炼、任务专用武器拒绝、圣遗物词条合法性、来源条件效果、属性归属、计算 JSON 往返和导入最终面板不重复计算装备。当前活动快照 `.inventory-20260923.2` 上执行 `npx vitest run packages/game-data/src/equipment-build.test.ts packages/game-data/src/equipment-effects.test.ts`：27 项通过，1.13 秒（测试执行 24 ms）。新增公式模块另执行 14 项参数化测试，通过，857 ms；前两批静态与转换公式模块实际执行 28 把武器的 140 个精炼条款。圣遗物基础模块此前与基础装备一同通过 32 项检查，1.38 秒；本轮该模块未改动，未重复运行。共享核心分阶段执行与最终产品集成状态以主任务最终检查为准。

`getConditionalEquipmentCoverage()` 按活动目录与实际规则导出当前 47 把部分或完整映射的武器、235 个精炼变体、50 个二件套、17 个四件套。这是 `conditioned-snapshot` 执行覆盖率，不是已独立验证或完整实战覆盖率；`independentlyVerifiedDefinitions` 仍为 0。
