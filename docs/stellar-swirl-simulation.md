# 星扩散指南参考：真实主模拟器接入

2026-09-25 高跳补充：下面的资格消费、腾空反馈与下落落地代码已写入；新增定向用例尚未运行，历史验证记录不代表这次增量已通过。

`simulateStellarSwirlProfile(config, { party, ...runtimeOptions })` 执行普通命中与实际星扩散事件的合并模拟。规则标识 `stellar-swirl-guide-reference-v1`，证据标识始终为 `guide-profile-source-conflict`。用户必须显式选择；默认普通模拟不改变。

范围固定为 aura-v3、单个静止且在范围内的目标、风／冰／物理输入、合法 60 FPS 时间轴、无卡肉、无插件与玩家伤害反馈。初始冰附着须由实际角色建立。冻结、多目标、移动、其他元素混合及特殊贡献者随机暴击未接入；暴击可选择精确期望、全暴击或不暴击。

## 实际执行

1. 主 Aura 完成真实 ICD 后，风遇到冰时消耗 `min(0.5 × 入射风量, 现有冰量)`。转换发生在普通冰扩散任务创建之前，因此没有普通冰扩散自伤、传播伤害或传播附着重复计数。贡献者来自消费前仍有个人冰附着的所有者及风触发者。
2. 每次初始人物属性在触发帧取样，初始风伤排在 +3 帧；该伤害本身不附着风。送达时读取目标风抗。
3. 按显式指南参考规则，漩涡总计三次触发升到二级，总计六次提前爆炸；否则在创建后 180 帧爆炸，追加触发不刷新寿命。集合为该漩涡生命周期各触发贡献者的并集，归属为最后触发者。爆炸时取样，一级／二级使用共享特殊公式系数 2／3。
4. 状态唤醒与伤害投递进入真实主事件堆。状态唤醒优先级 2.5，投递优先级 3；同帧按事件序号排列。第六次触发先完成其普通命中与 Aura 审计，然后执行刚排入的零延迟特殊投递。不能在适配器 `application` 内先修改当前命中的 Aura。
5. 漩涡投递实际调用主 Aura 的 1U 冰附着；新附着按普通 0.8 税得到 0.8U、570 帧期限，已有元素保留衰减率并按个人来源取 max refill。归属为最后触发者。这次冰附着进入同一目标状态时间线，能被之后的风命中真实消耗并触发下一次星扩散。

`specialDamageEvents` 保存原始贡献者快照、实际抗性、共享可执行轨迹、附着前后状态、`cryoDelivery` 回执与 `executionOrder` 主队列帧／优先级／序号。当前专属目标轨迹原因 `stellar-swirl-attachment` 通过严格来源、1U→0.8U、个人 refill、衰减和期限校验；历史 schema 不接受这个新原因。

结果返回普通分项 `classicDamage`、特殊分项 `stellarSwirlDamage`、合计 `totalDamage` / `totalDps`。普通命中沿 `captureSimulationHit(baseResult,id)` 恢复；特殊事件沿 `stellarSwirlEventToCalculatorDocument(result,id)` 恢复。

爆炸授予全队共用的一次高跳资格，持续 300 帧，恰在到期帧不可消费。真实 `jump` 开始时才检查并删除有效资格，同时保存独立的腾空角色、起始帧与来源动作；结果字段现为 `consumptionImplemented:true`，资格与 `airborne` 分别报告。主队列中的实际跳跃日志反馈给合法时间轴编译，普通跳跃占用或静态动作标签不能凭空证明腾空。未消费资格到期不会让已经起跳的角色自动落地。

腾空期间拒绝非下落角色动作。明确以 `timelineState.requires` 和 `timelineState.consumes` 声明 `airborne` 的 `plunge` 在实际执行时结束腾空，其普通下落命中仍沿原伤害队列计入 `classicDamage`，不改记为星扩散伤害。消费与落地分别留下 `high-jump-use`／`high-jump-land` 日志，并保留实际同帧执行次序。

`jump.frames` 仍由用户明确输入；本接入不根据武器类别推导 4／8 或 5／9 帧，不推算跳跃高度，也不补造角色下落定义。普通跳跃已开始后才遇到漩涡爆炸的增强分支在固定来源中仍带 TODO，本次未支持。源码行号、哈希、全局状态与到期边界见[高跳来源审计](research/stellar-swirl-high-jump-source-audit.md)。

## 来源冲突仍然存在

固定源码的加计是 `1 → 3 → 7`，实体以 `PolestarField` 注册却按 `StellarVortex` 查找，寿命写 181 帧，范围与指南提前爆炸扩大范围的描述不同。总计六次及 180 帧是明确选择的指南参考规则，**没有证明这些冲突已解决或与当前游戏一致**。非冻结单目标约束避免把未知冻结贡献者、范围和多实体归属补造成确定数据。专属基础提升、特殊增伤、加算、擢升及额外攻击在此配置明确关闭，不凭角色身份自动补齐。

完整证据及固定 URL 见 [状态证据](./research/special-state-evidence.md) 和 [数值与适配器取证](./stellar-swirl-adapter.md)。早期主接入未新增联网研究；本次另补上述固定高跳源码审计，仍未执行上游模拟器或游戏实验。

### 浏览器导入回归修复

真实浏览器在进入专属模式前会先运行同输入普通模拟并捕获逐击上下文，暴露普通冰扩散第 3–5 个反应组命中被抑制时的校验遗漏：事件保留真实正数公式输入，实际反应组乘数为 0，但执行审计曾漏乘这个已经由反应组日志独立证明的乘数。现校验使用同一 `damageFactors.groupMultiplier`；既不跳过验证，也不把反应基础倍率伪改为 0。独立计算器原有 `reactionGroupPolicy` 继续完整显示 `1917.738548181818 × 0 = 0`。

唯一新增普通导入回归用例验证了显式 `captureHits:true`、完整 JSON 导入、事件 6／8／10 的正基础与零组乘数、零伤害复算，以及把组乘数改为 1 时拒绝。只运行该新增用例，未重跑已通过的特殊反应集成矩阵。

正常UI导入及星扩散单项浏览器复验随后实际通过：1/1、2.2秒、exit 0。合计、9个事件与真实冰回执、初始/漩涡两类命中的同次完整计算器恢复及冲突披露均有数值/结构断言，见[浏览器记录](validation/stellar-swirl-e2e.md)。没有重跑先前已通过的三个综合场景。
