# 固定来源直接事件攻击组件（113）

## 范围

本批扩展共享来源事件组件登记：在 112 批白术 C2 `OnEnemyDamage` 与达达利亚 `OnTargetDied` 两个组件基础上，新增九个直接事件攻击站点，当前 registry 共 11 个组件。它们描述一次已登记监听调用及其直接排队的攻击，不把触发命中或监听时已有状态倒推为某次 E/Q 施放的所有权。既有共享组件 schema、组件选择器与来源公式重放路径复用；攻击数值继续使用现有共享核心公式。

新增组件如下：

- 阿贝多阳华协同攻击、迪希雅净焰剑狱协同攻击、雷电将军雷罚恶曜之眼协同攻击。
- 坎蒂丝 C6 漫溢攻击、绮良良 C4 协同攻击、久岐忍 C4 雷草标记、克洛琳德 C1 夜巡之影。
- 千织 A1 协同攻击、宵宫琉金火光爆炸。

九项均绑定到固定 `OnEnemyDamage` 监听站点及各自直接排伤害的具体调用。阿贝多、迪希雅、雷电将军保留其既有快照／队列语义；千织保留原有快照读取、天赋读取、防御力固定伤害计算、几何和 guard 顺序；宵宫保留原始共享属性 modifier callback，不把它重新包装成攻击来源。各站点的注册、发射、排队调用、固定版本来源行与边界详见 [sites-a](validation/source-direct-events-sites-a-20260930.json)、[sites-b](validation/source-direct-events-sites-b-20260930.json)、[sites-c](validation/source-direct-events-sites-c-20260930.json)。

## 精确调用计数与归属边界

每个新组件对一次已完成的监听调用记录来源已知的直接 AttackEvent 数，不把目标数或命中数当成排队数。其余八个站点的允许计数为 0 或 1；克洛琳德 C1 循环为 0 或 2。计数事实仅在原有直接排队分支赋值，不重复运行 guard、getter、随机数读取、目标选择器或伤害表达式。回执保留父事件、触发攻击／派发及目标身份，使组件关联使用实际 listener call 和调用内标记的 queue site，而非角色名、动作名、帧相邻或全局时序。未进入排队分支时计数为 0；目标结算状态仍由实际派发和目标证据区分。

这些站点均不证明此前领域、护盾、状态或爆发效果由哪个动作施加，也不闭合后续事件、回调派生伤害、召唤物与完整生命周期。阿贝多阳华的建立、未来协同攻击和 C2 层数；迪希雅领域生命周期及独立受伤监听器；雷电将军恶曜之眼施加者及未来协同攻击；坎蒂丝赤冕祝祷的先前施加；绮良良护盾生命周期；久岐忍圆环其余攻击；克洛琳德更广泛技能状态；千织 dolls／C4／C6；宵宫爆发前置状态与后续派生，均不因本批登记而闭合。现有受阻的白术 C6 护盾后续、达达利亚既有断流状态来源及 C4 仍受阻。

固定候选 inventory 仍是静态源码清点：23 个候选 family 中目前 11 个有事件组件，其余 12 个仍仅为 inventory 候选，不计作运行支持。此批不改变 60 个 finite contracts／51 项 plans，也不代表全技能 E/Q、生命周期闭合或游戏机制验证。

## 验收结果与边界

首次验收即全部通过：classic／stellar 来源构建分别用时 15.653／14.666 秒；typecheck 3.312 秒、registry 0.116 秒、Web build 1.185 秒（Vite 0.923 秒），浏览器单案例用时 32.99 秒（Playwright 测试 31.0 秒，runner 32.5 秒）。构建命令显式使用持久 cache-dir。

唯一原生样本是 classic 四角色轮转、两个目标、实际观察 770 帧；共 24 个团队应用，捕获 7 次事件注册、24 次发射、168 次监听调用、0 个事件 producer，该捕获记录的模拟总伤害为 18851.851237575444；它只是该轮转样本结果，不是 DPS benchmark。该轮转中观察到阿贝多、迪希雅、雷电将军三个直接事件组件，各自各选择一次监听调用、直接排队一次攻击并命中两个目标；六个命中重放差值均为 0。页面列出三项组件，导入／导出一致，共享核心编辑后小计变化；移除阿贝多计数事实的离线负例正确阻止交付闭合。捕获的 Kaeya 是触发角色而非本批审计组件；轮转 E 设置期间可先触发协同攻击，但不能据此声称 Kaeya 的所有攻击均触发这些组件。
