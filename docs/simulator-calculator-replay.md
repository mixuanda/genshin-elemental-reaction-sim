# 模拟命中到独立计算器

`captureSimulationHit(result, eventId)` 生成 `calculator-event-v1` 捕获文件。捕获保留完整源结果，而不是仅复制当前角色面板：配置、数据/引擎版本、所有固定公式/策略根、快照属性、实际附着与 ICD 判断、增益、目标状态、追加伤害所属角色及数值、反应所有者、事件顺序和随机种子均随文件保存。

`replaySimulationHit(capture)` 先执行既有结果 Schema 与因果完整性校验，再将命中时已解析数值传入模拟器共用的普通/剧变表达式执行器。每个普通伤害因子及最终值均对比原命中；剧变独立校验等级表、精通、反应、抗性，随后应用记录的反应伤害组和目标策略。数值允差为 `1e-10 × max(1, |参考值|)`；没有从显示舍入值重建计算。

还原入口已在属性结算之后，不再叠加装备、导入最终面板或快照增益。追加伤害贡献逐项显示所属角色的数值乘系数；激化追加项通过同一反应表达式执行。独立计算器渲染相同 trace。免疫目标保留正的潜在伤害和最终零贡献，明确显示目标策略。

自动引擎判定与人工反应覆盖分开标记。人工覆盖可以数值复现，但其 trace 标为条件假设，不证明自动附着、ICD 或实战反应覆盖。截断机制命中直接阻止完整复现，不把已截断的零贡献当作正确伤害。

当前模拟通过 `execution.captureHits` 选择记录 `execution-audit-v1`：它保存每段插件处理后的全部公式输入，包括被改写的角色/敌人等级、缩放面板、追加伤害与暴击模式。Worker 默认启用此捕获。带有该记录的插件命中可以独立复现；旧结果若只有插件清单而缺少实际输入，仍明确阻止复现。历史结果没有请求 execution 时保持原有字段和数值不变；新执行选项参与运行身份哈希。

`execution.criticalSampling: "seeded-random-v1"` 使用独立种子后缀 `:critical-hit-v1` 与 Mulberry32 随机流。每个符合资格的普通目标命中记录抽样值、从零开始的抽样序号、有效概率和实际暴击结果；剧变与 `critEligible: false` 不抽样、不暴击。明确由插件覆盖的暴击模式优先，记录实际模式而不额外抽样。JSON 导入会独立重放随机流并核对结果；计算器显示实际 `roll < CR` 判定，不把抽样值称为解析期望。尚未实现的暴击触发反馈不会被暗中添加。

`execution.detailedTraces` 是实际可选执行开关：关闭时保留输入捕获而不生成逐段公式节点，开启时执行共享表达式并记录 trace。因此性能对照可以测量同一场景、同一命中数在开启/关闭详细 trace 时的实际成本。

`serializeSimulationHit` / `parseSimulationHit` 对 JSON 往返重新验证；修改事件伤害、快照或相关上下文会触发校验失败。该完整性检查是内部数值/因果一致性，并非数字签名，也不意味着来源本身已获官方游戏机制认证。

# Worker

Web 主线程调用 `runSimulationInWorker`；模拟在专用模块 Worker 中运行。取消通过 `AbortController` 终止 Worker，可中断同步模拟；成功和失败也会释放 Worker。进度报告已完成轮次，不伪造单轮内部百分比。

批量接口 `runSimulationBatchInWorker` 使用显式种子和轮次后缀，返回第一轮完整轨迹及所有轮次摘要。随机性覆盖已有粒子数量、空间随机和显式启用的独立逐命中随机暴击。非暴击/全暴击/解析期望仍可单独选择。摘要区分样本分位数与均值 95% 正态近似置信区间，后者只在至少 30 轮时显示；记录迭代数、种子、随机算法标签、暴击策略与实测耗时。

# 实际相位状态检查点

`execution.checkpointFrames` 请求事件执行前的整帧边界快照，累计伤害仅包括 `event.frame < tick`。生产者输出能量、冷却/充能、增益/减益、实体、附着、资源/生命、ICD/触发历史、在途事件及前台/动作阶段九个维度。计时换成相位相对值；不会在名义周期重置能量或队列。

已支持的非反应确定性子集保留在途命中与粒子，且只有检查剩余完整输入确实按最多 16 个周期重复后，才折叠静态输入调度。至少需要两次完整模式与足够的尾部时段；普通闭合 Aura 与适用目标相位已有真实捕获；其余私有附着／反应、未导出的目标停顿时钟、插件私有状态等会按实际缺失维度明确阻止 complete。完整状态比较与真实连续预热由 `simulation-analysis.ts` 消费，不能仅凭相近 DPS 或循环计数认定稳态。

# 特殊反应主循环接入边界

`auditSpecialReactionIntegration` 已把真实普通引擎的附着/ICD、逐角色元素所有权和事件身份接入独立特殊状态机，输出转换、实体/资源日志与待执行伤害意图。没有手动标签冒充自动判定，也不外推缺少观察帧的附着所有权。

`auditSpecialReactionIntegration` 是普通运行结果的旁路诊断，不会事后改写已执行的普通反应消费与任务。因此其启用转换仍带 `conversion-not-applied`，特殊总伤害为未知 `null`，不会双计。

真实自动月感电与月结晶现分别由 `simulateLunarChargedProfile`、`simulateLunarCrystallizeProfile` 执行：两者在主 Aura 引擎真实转换、消费，实际特殊队列交付之后，才合并正式总伤害；对应 `lunarChargedEventToCalculatorDocument`、`lunarCrystallizeEventToCalculatorDocument` 恢复独立计算器。它们保留严格的单目标、无卡肉、元素组合与来源版本边界，详情见各专用文档。月绽放、星导、星旋也已有各自限定来源与元素范围的主队列入口，另有 Lunar 混合 v1／v2；对应结果、来源冲突与捕获边界见[反应支持矩阵](reaction-support-matrix.md)。旁路诊断意图仍不能拿来作自动DPS排名，已有独立模式也不能相加冒充一般混合模拟。

## 本批新增：特殊贡献者实际抽样

已接的月感电、月结晶、月露涤荡及混合v1/v2使用独立 `special-contributor-critical-v1` 流。每个实际合格且去重后的贡献者保存原暴击率、抽样值、序号和结果，按该结果暴击后再排序；CR为0或1时仍遵循该来源分支的抽样政策。月结晶在快照时抽样，交付时保留原结果。计算器同时列出实际样本与解析期望，捕获重现实际值；创建条件编辑副本时清除历史抽样上下文，原捕获不变。

本批贡献者随机综合用例已在统一核心检查通过，捕获与JSON回放纳入其中；[专项实施记录](validation/special-contributor-random-implementation.md)列出适用域。种子算法、比较运算和流身份独立记录，不能将本地流说成上游程序相同序列，也不能据此认证未实现的暴击反馈或随机精确周期。
