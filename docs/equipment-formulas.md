# 装备转换与叠层公式

新增模块只生成 `FormulaExpression` 表达式、变量定义与来源引用，不在界面计算面板或伤害。共享核心执行这些树并生成公式、实际代入与结果。当前有12把武器与2个四件套范围；每项均是用户明确恢复状态后的条件计算，验证等级仍为 `provisional`。

## 已登记公式

下表展示精炼1的公式。其他精炼精确读取活动目录对应字段；不从精炼1插值。`HP`、`EM`、`ER` 是核心的转换前面板，ER以倍率计，如200%为2。`s` 是命中前仍有效的层数。

| 范围 | 本次执行的公式 | 必须恢复的条件 |
|---|---|---|
| 护摩之杖 | HP增加20%；攻击增加 `HP×0.008`，低血量另加 `HP×0.01` | 当前生命比例；恰好50%因来源冲突阻塞 |
| 磐岩结绿 | HP增加20%；攻击增加 `HP×0.012` | 无额外触发条件 |
| 薙草之稻光 | 爆发后ER增加0.3；攻击百分比 `min(0.8, 0.28×max(ER−1,0))` | 爆发增益是否仍有效 |
| 赤沙之杖 | 攻击增加 `EM×(0.52+0.28×s)` | 0–3层；精通动态读取，不假造触发快照 |
| 西福斯的月光 | 自身ER增加 `周期触发时EM×0.00036` | 周期效果是否有效、最近触发时非转换EM |
| 玛海菈的水色 | 自身攻击增加 `周期触发时EM×0.24` | 周期效果是否有效、最近触发时非转换EM |
| 无工之剑／尘世之锁／贯虹之槊 | 攻击百分比 `0.04×s×(1+有护盾)` | 各0–5层，当前护盾是否有效 |
| 和璞鸢 | 攻击百分比 `0.032×s`，满7层才增加0.12伤害加成 | 0–7层 |
| 息灾 | 全元素伤害加成0.12；攻击百分比 `0.032×s×(1+在后台)` | 0–6层、命中时是否在后台 |
| 圣显之钥 | HP增加20%；自身EM增加 `自身触发HP×0.0012×s`；团队效果含自身份额 `团队触发HP×0.002` | 0–3层，自身与团队分别的HP快照，团队效果是否有效 |
| 绝缘之旗印四件套 | 爆发增伤 `min(0.75, ER×0.25)` | 命中必须标记为爆发 |
| 华馆梦醒形骸记四件套 | 防御百分比与岩伤分别 `0.06×s` | 当前0–4层；岩伤只应用于岩元素 |

已有二件套由 `equipment-effects.ts` 执行；这里仅增加四件套项，避免重复计入绝缘的20%充能或华馆的30%防御。常驻生命、显式叠层攻击、防御、薙草爆发ER属于 `pre-panel`；HP/EM/ER转换属于 `conversion`。所有转换读取同一转换前面板，不把转换结果迭代反馈给另一转换。

## 采样与排除

固定 [gcsim角色属性实现](https://github.com/genshinsim/gcsim/blob/b4ae769d7c1c1bce68fce5faf0b460c5b5b7f541/pkg/core/player/character/stats.go) 的 `NonExtraStat` 排除标记为Extra的派生属性。因此圣显的派生EM不进入赤沙、西福斯和玛海菈的精通转换，西福斯的派生ER不进入薙草或绝缘转换。绝缘的动态伤害项明确使用 `inputPolicy: "pre-conversion"`。

西福斯与玛海菈在初始化及每600角色帧采样EM，保存所得加成720角色帧；不能用命中时的当前EM假装此前采样结果。`timedSnapshotEm` 因此为显式输入。效果明确无效时不要求快照。这里未建周期调度或卡肉时钟，12秒／10秒只描述对应来源窗口。

圣显每次有效触发使用当时生命上限重新计算“系数×当前总层数”，并非把每层不同历史HP累加。自身层数快照使用 `keySnapshotHp`，团队窗口使用独立的 `keyTeamSnapshotHp`，不自动设为相等。三层时团队增益包含装备者。其他队员共享与多装备者叠加不在本角色配装范围内，保留明确说明。

固定 [敌人伤害结算顺序](https://github.com/genshinsim/gcsim/blob/b4ae769d7c1c1bce68fce5faf0b460c5b5b7f541/pkg/enemy/attack.go) 为先算本次伤害、后发出命中事件。因此赤沙／圣显／和璞鸢等本次才获得的层数不能追溯增益触发该层的那一击。这里输入的是命中前已有层数；没有代替团队模拟器自动生成层数。

固定源码中磐岩结绿与薙草的攻击输出未标记为Extra。本批规则没有后续“攻击再次转换为另一属性”的效果，统一转换前读取不会影响本批数值；后续扩展不能把这条保守执行约定当成所有游戏转换的最终普遍规则。

## 完整条件与剩余阻塞

缺少已支持公式必需的条件、快照或已知来源边界冲突时返回 `missingConditions`，上层必须阻止把缺少这一项的数字显示为完整装备结果。其他尚未支持的护盾吸收、对其他队员的共享等留在 `effectBlockers`；当前明确层数状态本身不要求事件调度已经实现。

护摩恰好50%生命的目录文案为“低于”，[固定参考实现](https://github.com/genshinsim/gcsim/blob/b4ae769d7c1c1bce68fce5faf0b460c5b5b7f541/internal/weapons/spear/homa/homa.go) 使用 `<=0.5`。本模块保留冲突，不擅自选择边界。所有武器条款都执行完整固定文本匹配；活动来源文本变更时拒绝沿用旧映射，要求复核。

目录来源跟随 `equipmentDescriptionSource` 的活动快照，未引用旧的默认历史manifest。14个范围的参考实现固定在 gcsim提交 `b4ae769d7c1c1bce68fce5faf0b460c5b5b7f541`；17份源码的URL和SHA256保存在 `equipmentFormulaSourceEvidence`，包含三把同族武器调用的公共实现与属性／事件顺序证据。原始下载证据保存在本次运行的 `/tmp/gidps-equipment-formula-sources/`。这些证据是可复查的社区实现，不能声称官服独立验证。

## 实测

执行 `npx vitest run packages/game-data/src/equipment-formulas.test.ts`：14项参数化测试通过，耗时857 ms（测试执行6 ms）。每把武器均执行R1–R5文案映射；R1、R5另用手算期望校验。用例还检查ER下限与上限、绝缘爆发限定、条件缺失、两个圣显快照独立、西福斯／玛海菈明确停用、非法层数及护摩50%边界阻塞。核心面板分阶段执行与文档保存由主任务集成测试覆盖。
