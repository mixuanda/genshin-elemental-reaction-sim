## 角色动作来自实际方法

此前来源队伍向每个角色提供相同的十种按钮。现在两套固定源码分别通过 Go 标准库 AST 提取器解析角色类型、跨文件方法、旅行者共享类型、模板继承与纯委托。上游文件先与固定 Git tree 的 blob／大小匹配，再交给本地解析器；不会编译或执行下载的角色代码。模板中直接返回 `not implemented` 的方法标为不支持；有实际实现的方法仍需通过来源运行时的能量、冷却、姿态、体力和前后动作检查。

每个角色包检查九种方法；`wait` 是独立的脚本等待，不计入角色方法数。上表是静态方法入口的计数，包含有条件分支，不是游戏已验证动作数、完整角色数或旧条件技能映射的新增数。生成证据为 [b4 输出](validation/action-capability-inventory-b4-20260928.log)、[a7 输出](validation/action-capability-inventory-a7-20260928.log)及[机器汇总](validation/source-actions-inventory-summary-20260928.json)。

队伍按钮和每行动作下拉按所选角色的方法过滤；换角色后保留原动作供用户修正，生成脚本时明确拒绝该角色没有实现的方法。诺艾尔没有来源瞄准方法，但低／高下落有闲云空中状态条件的实际实现，因此仍可选择下落，由运行时检查条件；安柏有瞄准而没有 `ChargeAttack` 方法。冰旅行者正确解析到 `traveler/common/cryo`，不要求所有方法出现在角色包装文件中。

明确常量的普攻计数器长度用于“连续若干次普攻”按钮。输入接续当前计数器，不强行重置，也不把输入次数当伤害段数。恰斯卡、卡维、玛薇卡、希诺宁在两份来源中的链长有动态或非单一常量赋值，保持未知，只提供单次输入和可编辑重复次数。参数区列出真实方法及明确转发至同接收者 helper 的字面参数键与固定源码链接；不推断默认值、合法范围或一概填 `hold=1`。动态参数、任意帮助函数与具体帧表达式仍需按源码及实际执行解释。

## 讨龙与武器叠层的实际组合

讨龙的真实成功切人回调和现有武器叠层的普通伤害／完整属性读取回调，可在特殊宿主中复用。星导模型的伤害仍经普通事件管线，现有13把武器的普通回调不再因宿主名称被统一拒绝。月绽放等模型中，仅参与普通伤害且不拥有或贡献独立特殊伤害的持有者也可执行该路径。

独立月曜／星扩散伤害尚未提供武器所需的完整 `OnEnemyDamage` 及属性读取回放。若叠层持有者实际成为这类伤害的拥有者或贡献者，完整模拟结果返回前会按真实事件拒绝输出，列出角色与帧；没有伪造对应回调。宗室系列仍要求实际暴击结果。当前本地特殊公式使用 HP 或 EM／暴击，讨龙 ATK 增益不会被错误计入这些特殊伤害。

新增一个聚合核心用例检查：实际讨龙切人、普通命中叠层、星导场景伤害变化，月绽放中普通角色与月曜拥有者分离，以及特殊拥有者阻断。JSON 检查针对 `baseResult` 的普通账本和状态；它不等于完整 `specialDamageEvents` JSON 导入与重算，该完整特殊结果入口仍是未完成项。
