# 确定性动作状态的相位检查点

当前实现支持同一次连续模拟中的延迟扣能、定时召唤、属性转换、显式共享体力、确定性治疗/生命消耗，以及确定性周期实体、显式动作相位和起手条件命中组的完整状态与队列；后续还覆盖下述限定域的普通附着、ICD、直接伤害组、目标时钟关闭时的target-phase-v2、原三把确定性独立武器追击和新增四把状态追击，以及普通宿主的讨龙切人状态。它没有移除状态完整性要求，也没有把普通攻击随机回能改成确定性模型；五把随机追击仍独立阻塞。生产者标识仍为 `nonreactive-phase-state-v2`；结果使用既有 `execution-audit-v1` 的九个状态维度。体力启用时携带版本化子状态；生命动作使用真实主堆和已有 HP 状态，未启用相应能力时保持原状态形状。

## 实际运行数据与归一化

实现位于 `packages/sim-core/src/phase-checkpoint.ts`，由 `simulator.ts` 的 `capturePendingCheckpointsThrough` 在边界帧全部事件执行前调用。`CapturePhaseCheckpointInput` 接收实际 `reservedEnergy`、`activeTimedSummons`、`liveConversions`、`actionLog`，以及相应能力的 `staminaState`、`periodicEntityState`、`actionConditionLog`、`ordinaryAuraState`、`auraObservationState`、`directDamageGroupState`、`weaponProcState` 和 `thrillingTalesState`。具有相关声明的配置必须传入对应实际状态，即使当前为空；只有声明而没有实际状态仍会阻断。

## 边界时序

- 扣能到期帧等于检查点时，尚未执行该帧事件：预留与待扣任务均保留。未声明显式动作相位的旧动作仍先于同帧优先级 2 的扣能执行；`after-frame-tasks-v1` 动作在既有任务之后的优先级8接受，其自产同帧事件按原优先级加10执行。这些顺序来自真实主队列，不是对所有来源队列语义的通用认证。
- 召唤到期帧等于检查点时，实体仍在活动集合；执行到期任务后实体消失，其稍后攻击继续以真实生成快照留在主堆。
- 转换使用严格的 `frame < expiresAtFrame` 条件。转换到期等于检查点时已不影响属性或附魔，旧 Map 中的过期审计记录不作为活动状态。待命中的原始附魔条件保留，仍由实际命中时的转换状态决定。
- `StaminaRuntime.captureBefore(tick)` 先执行严格早于边界的恢复和扣费，再保存独立状态；边界自身的玩家恢复、延迟消费及输入均未发生。相同共享量但恢复冷却或待扣任务不同，仍是不同相位。
- 生命事件在边界帧到期时仍保留于待执行队列；`active` 只保存目标规则，由后续真实事件执行时的站场状态决定。相同 HP 但同帧消费/治疗顺序不同，不能判为同相位。相同事件不去重，纯审计身份的绝对日志下标和事件编号不用于跨周期比较。
- 周期实体的绝对递增代次只作审计身份，导出以同持有者/定义的真实最近代次保存差值及引用关系；被替换的旧tick仍留待取消，已经排出的旧伤害仍带原快照执行。无活实体或在途引用的旧计数只影响未来日志编号，不纳入相等判断。已锁定生命分支也不按边界时的当前HP重算。
- 独立追击的来源冷却在 `expiry === tick` 时仍有效，因此保存剩余0；只有严格过期才规范为就绪。真实队列的触发增益可能在投递边界已过期，但仍属于该追击的历史快照，不按当前buff列表删掉。不同属性快照或目标FIFO不能判为相同周期状态。
- 讨龙属性在到期帧已无数值贡献，但接收者记录仍可能存在并挡住重新领取。只有实际完整Stats执行会清除到期记录；检查点捕获、审计和选择单项属性不引入这次状态变化。相同数字面板而不同接收者存在性，是不同未来状态；持有者通过冷却后先消耗冷却，接收者拒绝不退款。
- `simulateWithStartup` 和检查点共用 `action-pending-horizon.ts` 计算完整尾段。周期实体末tick相对生成帧为 `firstTickDelay + max(0, ceil((duration − firstTickDelay) / interval)) × interval`，再计入生成、伤害延迟及命中产球旅行；同时覆盖所有候选条件命中、延迟扣能、体力、生命变化、定时召唤及其他在途任务。旧式 rotation 和合法时间线两条路径保持一致；尾段只为完整队列和周期输入证明服务，不扩大用户请求的 DPS 观察窗口。

## 原延迟扣能、召唤与转换的聚焦验证

执行一次：

```sh
npx vitest run packages/sim-core/src/__tests__/phase-checkpoint-runtime-state.test.ts
```

首轮 **3/3 通过**，测试耗时 **104 ms**，总耗时 **911 ms**。原始记录：`docs/validation/phase-checkpoint-runtime-state.log`。本轮没有运行构建、旧测试全集、性能或浏览器测试。

1. 实际队列边界：第 59 帧保持能量 60、预留 10；第 60 帧能量 50、预留 0。召唤在 45 帧生成、165 帧到期，165 帧的事件前检查点仍有实体。转换在 165 帧失效，168 帧实际攻击仍使用生成时 `flatAtk=280` 的完整快照；攻击前累计伤害为 0，169 帧检查点包含实际伤害。
2. 合法连续轮转：120 帧周期，延迟扣能 150 帧，召唤生成 130 帧、寿命 270 帧、攻击再延迟 3 帧。预热 9 周期后，用最后 5 个相位状态和周期伤害建立周期 1 稳态；状态包含两个重叠召唤、一个待生成任务、真实预留及转换快照。总模拟尾端为 1483 帧，测量仍仅为 1080 至 1200 帧。没有重置循环状态或补能。相同配置启用随机普攻回能后明确不建立确定性稳态。
3. 缺失状态及队列：声明延迟扣能而未提供真实预留时拒绝；有预留却无待扣任务时拒绝；补齐真实任务后成功；观察尾部不足以容纳声明延迟时继续拒绝。

这些是中性属性的合成执行夹具，用于验证通用状态机制，不是新增角色游戏数据或完整角色来源验收。

## 普通附着首层与真实观察状态

`AuraEngine.captureOrdinaryState()` 直接复制原始元素量、每帧衰减率、来源槽、物化帧和内嵌ICD，不推进时间或采用舍入后的公有快照。自然到期调度还需 `TargetStateTimelineRecorder` 的最新观察帧/Aura状态；只保留 raw gauge 而缺观察状态仍不完整。直接附着与伤害组的窗口在下一次消费 `frame≥resetAtFrame` 时重开，因此已到期窗口可归一移除；不同等号规则的反应拥有状态没有套用该规则。有效窗口的起始group、完整计数、年龄和剩余期限仍保留。

首层可接受域为 `legacy-event-heap-v1` 下的普通持久单元素，或水火/冰火组合，可同时含物理；后续目标阶段v2增量沿用同一元素闭合域。完整未来输入检查编译轮转、未编译的全部能力及条件/周期/召唤命中、默认属性所有者元素、休眠附魔和每目标初始附着；全局元素并集检查会保守拒绝分别作用于不同目标的组合。不能以检查点当前无反应状态，证明未来不会产生未导出机制。

原生 `aura-v7 + legacy-event-heap-v1` 合成连续运行以120帧为周期，8周期预热、2秒观察，实际普通伤害500与逆蒸发750，共1250伤害、625 DPS并建立period1。真实检查点保留残余水元素量、原始衰减率、ICD、伤害组和观察状态；不同衰减率或ICD计数仍为不同状态。完整证据及分次通过记录见 [首层专项](validation/ordinary-aura-phase-checkpoint-core.md)，不把定点复验描述成一次全文件通过。

## 原生 target-phase-v2 的后续支持

`captureTargetPhaseV2State()` 只读捕获真实衰减待执行/已完成去重键、最后处理事件帧、阶段旗标和任务/Reactable.Tick前后快照；`normalizeTargetPhaseV2Checkpoint()` 要求真实 `targetDecay` 队列与去重键逐项双向匹配，保留targetId、相对帧、priority和FIFO。阶段状态写入 `pendingEvents.targetPhase`，Aura捕获还保存实际 `reactableTickModel` 和生命周期缓存。当前帧已有事件、衰减或帧内交付，缺任务、重复键或越过完整尾段时不能标为完整事件前检查点。

只剔除不再改变未来执行的过去阶段、已完成键和审计游标；需要的未来快照/旗标仍保留。正常周期边界的归一结果可以为空，这是读取真实状态后排除已结束历史所得，不能用占位空数组代替捕获。旧legacy检查点不添加该字段。

支持范围为目标时钟关闭的 `target-phase-v2`，普通元素闭合域和随机/反应生命周期限制不变。原生 `aura-v9` 的120帧合成周期在8周期连续预热后，2秒窗口实际伤害1250、DPS625、周期1且检查点完整，配置未降级。v8可走相同支持路径，本次实际连续用例是v9，不宣称另跑v8。真实边界、缺任务/FIFO/截断与其余阻塞证据见 [目标阶段专项](validation/ordinary-aura-target-phase-checkpoint-core.md)。

## 后续独立武器追击检查点证据

钺矛、苍纹角杯、冷寂迸音三把确定性武器的真实运行时冷却与队列上下文已接入；未配置模型时不增加字段，有声明却缺实际捕获仍拒绝。动态action/hit身份按角色/武器规范，命中组保留队列相对关系；精炼、增伤、属性快照、目标顺序与几何不被抹去。普通宿主和周期实体的适用命中只增加真实+1帧投递尾段，钺矛仍要求显式normal，不向生命/粒子任务盲加1，也不人为追加600/900帧冷却等待。

原生 `aura-v9 + target-phase-v2`、无目标时钟的合法三武器合成循环使用960帧周期，8周期连续预热。五个完整检查点相等并建立周期1，16秒测量窗口伤害9800、DPS612.5；边界冷却剩595/897/899帧，待执行冷寂迸音保留两个目标的FIFO，以及触发时 `hpPct=1`、边界已到期的HP增益快照。另有真实周期实体在24帧tick、649帧宿主命中、650帧追击的长尾执行，证明尾段覆盖该在途事件。

三个新增用例均已分别通过：首轮两项通过、一项因夹具失败；仅失败项复验暴露旧合法指令校验漏接，修复后只复验该项及补入实际周期尾段的第三项，先前通过的第二项没有重复执行。逐次结果、日志及支持域见 [专项报告](validation/weapon-proc-phase-checkpoint-core.md)，不能简写为一次全文件首跑通过。普通水火增幅宿主属于既有闭合域；反应伤害回调、其他未导出反应生命周期、随机与目标时钟限制仍各自生效。

后续接入的吃虎鱼刀、试作古华、雪葬的星银、龙脊长枪、忍冬之果有独立随机流及真实延后回调。它们的普通宿主命中只负责排入同帧同相位FIFO任务，成功回调再读取目标附着、取样并投递追击；因此回调前待执行任务和随机流位置都能影响未来伤害，不能仅用已发生的`weaponProcLog`或宿主`auraAfter`代替。当前该私有状态尚未完整导出，配置含新五把便保留完整周期阻塞；霜葬R5仍抽随机数，不作确定性例外。上述旧三把的完整捕获及真实周期证据保持有效，但不扩展为这五把或全部武器已证明稳态。

## 四把状态追击与固定属性增益

笛剑、以理服人、流月针、竭泽的确定性检查点读取真实`lifecycleStates`，不从日志重建另一套状态。效果、命中门槛和激活冷却在到期等号保留剩余0；笛剑效果已失效后，下次合格音符必先清旧层，才将旧音符归一为0；竭泽效果失效后不能再消费且下次成功激活必清次数，才将旧次数归一。该处理不修改原始Status期限、音符或次数账本，仍有效的独立冷却继续保留。

待执行回调保留实际父命中、动作、目标、标签、伤害与同帧FIFO；尚未执行的取样不能由后来的日志倒填。已排追击继续保留实际属性/几何、系数、触发前后完整计数与相对期限，即使数值增益在边界已经到期，也保留触发时的历史快照。尾段只覆盖真实+1帧交付，不额外等待音符窗口或武器冷却。

唯一新增合成用例采用32秒合法闭合输入，实际`aura-v9 + target-phase-v2`、普通水火域、静止目标、无随机暴击及角色卡肉。最终建立周期1、完整覆盖，测量总伤1880、DPS58.75；第1920帧竭泽追击保留历史`flatAtk:200`而造成480伤害，完整sourceResult及capture JSON回放差0。实际一／二音符状态可区分，1831帧到期等号仍保留二音符，1832帧才可与未积累状态等价。详细输入、剩余期限和失败记录见[四状态检查点专项](validation/stateful-weapon-proc-checkpoint.md)。

此用例共四次调用：前两次为夹具枚举和几何声明错误，第三次暴露真实固定属性字段映射错误（实测1800而非1880），修复后仅复验同一用例通过，没有把失败写成首跑成功。当前合法帧新运行以`resolvedRuntimeOptions.flatStatBuffSemantics: "canonical-v1"`记录`atkFlat/hpFlat/defFlat`增益映射到`flatAtk/flatHp/flatDef`。历史当前结果缺标记时保留旧读法，解析不自动补标记；冻结旧schema拒绝新标记，legacy语义不变。该属性取样修复不建立动态最大生命、死亡/复活等生命池机制。

这项证据只扩展上述四把的确定性状态，保留原三把支持；五把随机追击、随机暴击、目标时钟和其余未导出反应域仍分别阻塞，不能推导全部角色或全部武器稳态。

## 后续讨龙切人状态证据

`ThrillingTalesRuntime.captureState()` 提供持有者独立冷却与接收者共享`ttds`记录的真实存在性。`thrillingTalesState`必须与配置持有者一致；无模型不增加字段，缺实际捕获仍拒绝。到期等号保存剩余0，真正已过期且无未来影响的绝对期限才规范掉。属性增益和已保存动作/召唤/在途命中的讨龙快照继续保留来源及相对起止时间，不从输出日志重建另一套状态，也不额外等待1200帧冷却。

三角色40秒合法闭合循环经过8周期同次连续预热，完整检查点建立周期1，测量伤害4080、DPS102；持有者B在边界的冷却剩421帧。另有边界用例真实比较同帧“先切人后完整Stats”与“先live-hit Stats后相位8切人”：前者旧记录阻止领取，后者清除旧记录后可领取R5，下一帧伤害分别600与840。持有者1200帧等号仍阻塞也有本地用例；这些边界不冒充外部样本已实测。

三个新增运行时用例分次通过：首轮一项通过、两项因合法轮转夹具误用`attack`而未进入模拟；只改为已有`normal`后复验两项通过，已过项跳过，未因这些用例修改生产逻辑。专项记录还保留700帧取样、702帧交付的旧增益快照，以及完整JSON恢复，见 [讨龙运行时专项](validation/thrilling-tales-runtime.md)。角色卡肉、特殊宿主和未接入的角色私有Stats读取仍不在此完成范围；其他随机、目标时钟与未导出反应域继续独立阻塞。

## 剩余范围

目标时钟、target-phase-v1/v3、感电、冻结、激化、燃烧、剧变反应、草原核与结晶实体、反应拥有的附着任务、特殊反应注入、插件、概率产球、随机粒子数量、随机暴击、普通攻击随机回能及西风随机流仍独立阻塞。祭礼的独立随机流、持有者触发冷却、实际E串行充能和延迟SetCD任务尚未全部纳入完整周期检查点；显式启用 `sacrificialModel` 时继续拒绝确定性稳态证明，已有运行日志不能替代完整运行态导出。久岐忍固定 E／E/Q 的周期实体、起手生命分支与普通Aura/伤害组不再被一概排除，但其45%产球仍有未导出随机流，不能宣称全状态稳态已建立，见 [E/Q 来源契约](cross-validation/action-library/kuki-burst-source-contract.md)。

生命之契、动态最大生命、死亡/复活、一般治疗/消耗触发回调和其余角色生命参数仍未完成；久岐忍固定条件下的拥有者HP/EM及A1治疗取值不扩大到所有角色，见 [初始生命执行范围](validation/player-health-runtime.md)。全角色已核实体力费用、动态减耗和特殊移动也不在这次共享资源检查点的完成范围。Noelle 来源 Q→N 与 Amber 当前来源 E/Q→N 的普通攻击随机回能仍受原限制；导出确定性的转换、定时实体、共享体力或静态生命队列并不解除其他独立 blocker。有限周期相等只对实际提供、完整导出的边界状态和已验证重复输入成立，不宣称任意未来输入或所有游戏机制已经收敛。
